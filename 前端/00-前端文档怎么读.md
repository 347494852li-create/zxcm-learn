# 前端文档 · 怎么读（先看这一页）

> **你的前端目标**：不是手写前端，是**看得懂调用链** —— 看到一个菜单/按钮，能顺着找到它的 `.vue` 文件和它调的接口。
> （前端是**整包复制**进来的，见 [M0 · T9](../后端/M0-骨架（总览）.md)）
>
> 这一页只干一件事：告诉你**四篇前端文档先读哪篇、什么时候翻哪篇**，让你不再"看花了眼"。

## 0. 关键：它们不是"一本书的四个章节"，是"四把钥匙"

四篇文档**不要当成 1→2→3→4 从头啃到底**。它们各自解决一个不同的问题，
你**带着问题去找**，比从头读快十倍。

| 编号 | 文档 | 它是什么 | 它回答什么问题 |
|---|---|---|---|
| **E1** | [工程结构](E1-zxcm-ui工程结构.md) | 🗺️ **地图** | **文件在哪**？看到菜单/按钮，对应的 `.vue` 和接口是哪个？ |
| **E2** | [代码导读](E2-前端代码导读.md) | 📖 **语法字典** | 屏幕上这行 `v-model` / `el-table` / `:prop` / `scope.row` 是什么意思？ |
| **E3** | [代码走读](E3-前端代码走读.md) | 🚶 **带路** | 从登录到新增，整个前端项目**是怎么跑起来的**？ |
| **E4** | [一次点击的完整旅程](E4-一次点击的完整旅程.md) | 🔍 **放大镜** | 点一个按钮，请求**到底怎么一步步走到后端、又怎么回来**？ |

## 1. 默认顺序（编号就是顺序）：E1 → E2 → E3 → E4

第一次接触前端，就按编号读。但**每篇的读法不一样**，照下面来：

| 步   | 读哪篇              | 怎么读                                                                                | 参考耗时    |
| --- | ---------------- | ---------------------------------------------------------------------------------- | ------- |
| 1   | **E1 工程结构**      | **通读**。先建立"文件都在哪"的地图；**四条关键约定**（菜单→页面 / 页面→接口 / `request.js` / `permission.js`）要记住 | ~30 分钟  |
| 2   | **E2 代码导读**      | **读到 `§5` 之前就够**（§0–§4：`.vue` 骨架、Vue 概念、模板语法、`el-` 组件）。**`§5` 起是逐行拆解，当字典用，别硬背**    | ~1 小时   |
| 3   | **E3 代码走读**      | **跟着代码一条路走完**。开着编辑器，它说打开哪个文件你就打开哪个；**卡住就回 E2 查这一行**                                | ~1.5 小时 |
| 4   | **E4 一次点击的完整旅程** | **选读**。想彻底搞懂"请求怎么走到后端"时读，跟着 11 跳看一遍                                                | ~40 分钟  |

> ⏱ 全程约 **3.5–4 小时**（大致参考，别掐表）。**读完一篇就能停**，下次接着下一篇。

## 4. 先混个眼熟：这 8 个词后面四篇天天出现

不用背。**它们第一次出现时，四篇里都会各自再解释一遍。**

| 名词 | 大白话 |
|---|---|
| **`.vue` 文件** | 一个页面的全部：长什么样（`<template>`）+ 什么逻辑（`<script>`）+ 什么样式（`<style>`） |
| **组件** | 一段能反复用的界面积木（按钮、表格、弹窗）；`el-` 开头的是 Element UI 提供的现成积木 |
| **路由 / `router`** | "哪条网址显示哪个页面"的对照表 |
| **`store`（Vuex）** | 多个页面共用的数据仓库（比如"当前登录用户是谁"） |
| **`api/*.js`** | 一组"只负责发请求"的函数声明 —— 页面要调后端就 `import` 它 |
| **`request.js`** | 所有请求的**唯一出口**（统一加 token、统一处理返回） |
| **`<template>` / `<script>` / `<style>`** | 一个 `.vue` 的三段：界面 / 逻辑 / 样式 |
| **代理转发（`/dev-api`）** | 开发时，前端先把请求发给"自己人"（前端开发服务器），由它转交后端 —— 浏览器全程不知道有这一步 |

> 📌 **讲解原则**：每个词都**先用前端自己的话讲清，再配本项目真实代码**（`zxcm-learn/zxcm-ui` 里能打开的文件）举例。**不拿后端的类去套**。
