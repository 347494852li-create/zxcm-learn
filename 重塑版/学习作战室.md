# 学习作战室 · 从「看得懂」到「讲得清、改得动」

> **这是什么**：重塑版三卷是「按知识组织」的手册，这一页是「按时间组织」的作战计划。
> 它回答三个问题：**先学什么、每天学多少、学到什么程度算过关。**
>
> **怎么用**：先花 5 分钟做 §一 的目标选择，再按 §三 的计划执行；每天结束在 §六 打卡。卡住时回 §二 查「这个知识在哪一章」。

---

## 一、先选目标：你要的是哪一种「会」？

不同目标决定不同的读法，不要一上来就从头读到尾。

| 目标 | 你需要的程度 | 建议周期 | 主路线 |
|---|---|---|---|
| **A. 能跑起来、能演示** | 知道项目怎么启动、每个菜单干什么、能按步骤操作 | 3~5 天 | 基座第 0 章 → 后端第 0 章 → 前端精读 1 + 第 0 章 → 运行手册 |
| **B. 能读懂、能讲清** | 能顺着一条链路讲清前后端和数据库，能回答「为什么这么设计」 | 2~3 周 | 基座第 1~5 章 → 后端第 0~6 章 → 前端第 0~6 章 + 精读 2/3 → 生命周期附录 |
| **C. 能改、能加功能** | 能加字段、加页面、加接口、加审批节点，能自己排查问题 | 4~6 周 | B 的全部 + 后端第 7~10 章 + 基座第 6~15 章 + 改造实验室 |
| **D. 能答辩、能面试** | 10 分钟讲清项目，30 个追问不慌，能主动交代缺口 | 在 B/C 之后 3~5 天 | 答辩作战手册 + 各章答辩卡 + 坦白点清单 |

> **推荐**：大多数人走 **B → D**；如果时间紧，先走 A → D（能演示 + 能讲），再补 C。
> 不要用「读完了」当目标，用 §六 的「能做出来」当目标。

## 五、学习闭环：读 → 抄 → 跑 → 改 → 讲

只看不敲，一周就忘。每个模块至少走一遍这五步：

1. **读**：读本章 §1~§3，知道「做什么、为什么、用什么」。
2. **抄**：照着 §4 的复制清单，把五件套/页面骨架敲一遍（可以先抄答案册，再默写）。
3. **跑**：按 §4/§5 的「动手验证」发一次请求、看一次 SQL、查一次 Redis。
4. **改**：加一个字段/一列/一个按钮，观察前后端各改哪里。
5. **讲**：合上文档，用 3 分钟讲清这个模块的业务、链路、一个设计取舍、一个缺口。

> **判断是否真会**：第 5 步能讲清，才算会；只完成 1~3 步，面试一追问就露馅。

| 先把 Spring/MyBatis 源码学完再来看项目 | 项目里只用得到一小部分，学完就忘 | 按章节用到什么补什么 |
| 只看不敲 | 看得懂 ≠ 写得出，面试一追问就露馅 | 每个模块至少走一遍「读→抄→跑→改→讲」 |
| 从第 0 章一页不落读到第 15 章 | 周期太长，容易中途放弃 | 先走一条主链路（合同审批），再补横切能力 |
| 只看后端不看前端 | 讲不清「一次点击怎么走」，答辩丢分 | 前后端按章节对照读 |
| 只背面试题不看代码 | 追问「在哪一行」就答不上 | 每题都带 `文件:行号` 证据 |
| 假装项目完美 | 面试官一问缺口就慌 | 主动说缺口 + 改进方案（见各卷附录 §五） |
| 追求「学完」 | 永远学不完 | 追求「能做出一个可演示的闭环」 |
