# 附录 · 横切能力索引

> **这是一页速查表，不是新内容。** 第 0~10 章是按「合同生命周期」纵向切的；但有些能力是**横着穿过所有章节**的——鉴权、数据权限、文件存储、缓存、事件……它们在第 1 章第一次出现，之后每一章都在用。
>
> **本附录解决一个问题**：当你想「再看一眼数据权限是怎么做的」或「Redis 到底在哪章讲透的」，不用翻十份文件,查这里。
>
> **使用约定**：所有定位都写成「第 X 章 §Y.Z」或「全路径:行号」，可直接跳转。表名后附建表行号（脚本 `script/sql/zxcm_init.sql`）。

## 七、术语表（全书贯穿的名词，一句话）

| 术语 | 一句话解释 | 详见 |
|---|---|---|
| **草拟 / 台账** | 草拟=合同未定稿阶段，台账=已定稿合同的正式清单（同表不同视图） | 第 9 章 §2.5 |
| **五件套** | 一个功能的 Controller + Service + ServiceImpl + Mapper + 实体 | 第 0 章 §4.1 |
| **BO / VO / Entity** | 入参对象 / 出参对象 / 数据库映射对象 | 第 0 章 §4.2 |
| **文件组 `fileGroupsJson`** | 把「一个合同的多个文件」塞进一个 JSON 字符串字段 | 第 5 章 §1.4 |
| **宽表** | 把所有字段塞进一张大表（vs 垂直拆表） | 第 5 章 §1.3 |
| **六状态字段** | 合同的审批/用印/复核/履行/变更/作废六个正交状态字段 | 第 6 章 §1.2 |
| **发布态三态** | 模板的 未发布/已发布/已停用 三态（vs 布尔 `isPublished`） | 第 7 章 §1.2 |
| **`ONLYOFFICE_KEY`** | OnlyOffice 文档服务器的**缓存键**，内容变了必须换，否则看到旧缓存 | 第 8 章 §1.4 |
| **contentControl** | Word 的"内容控件"，是"要素填充"的载体 | 第 8 章 §2.7 |
| **历史不可变** | 合同盖章/归档后内容冻结，只能作废不能删、只能新增版本不能覆盖 | 第 9 章 §2.4 |
| **双章文件 `FILE_TYPE_SEAL`** | 盖了双方章的最终正本，单独一种文件类型 | 第 9 章 §4.2 |
| **终态 / 回退** | 终态=已完成/已作废（不可再流转）；回退=`backToDraft` 退回草稿 | 第 9 章 §4.7、§5.4 |
| **数据权限 vs 功能权限** | 功能权限=能不能进这个接口（`@SaCheckPermission`）；数据权限=进去后能看哪些数据（`@DataPermission`） | 第 2 章 §2.1 |
| **报表 Mapper** | 理想中应与业务 Mapper 分离、指向只读库的 Mapper（**本项目未做**） | 第 10 章 §2.7 |
