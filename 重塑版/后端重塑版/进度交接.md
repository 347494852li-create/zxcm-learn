## 五、最近核对过的事实（别改回去）

- **逻辑删除**：`@TableLogic` 只对 BaseMapper / Wrapper 自动加 `del_flag='0'`；手写 `@Select` / XML / `runSql` 不会自动加，必须自己写；
- **编号规则**：`validEntityBeforeSave` 是空 TODO；真正的规则校验在 `updateByBo`（文字片段必须有 string、一个规则最多一个流水号）；
- **联系人 JSON**：前端 `contactsArray` → 提交时 `JSON.stringify` 成 `contacts` → 数据库列 `CONTACTS`；读取时 `JSON.parse`；列表接口的 `contacts` 会被当前登录人覆盖；
- **第 2 章拉黑**：`ban` / `unBan` 是 Service 能力，当前没有独立 HTTP 入口；
- **第 1 章 Token**：JWT 风格，`LoginUser` 在 token session（Redis）里，不在 JWT 里；
- **逻辑删除的删除值**：`application.yml:254/256` 配的是 `0/2`（不是 MP 默认的 `0/1`），建表注释也是「0 未删除 2 已删除」；
- **删除事件是「校验」不是「通知」**：`deleteWithValidByIds` 先 `publishEvent(DataDeleteEvent)`，`ContractAuditFormServiceImpl.deleteDataListener`（`@EventListener`，同步）查审批单 `SUBJECTS` 的 JSON，有引用就抛 `ServiceException` 阻止删除；改成 `@Async` 就会失去拦截能力；
- **`${ew.customSqlSegment}`**：MP 3.5.2，`Wrapper#getCustomSqlSegment()` 在条件非空时返回 `" WHERE " + 条件`，只有 order by 时不加 WHERE，全空返回空串；顶层条件外面会被 `NormalSegmentList` 包一层 `( )`；参数名必须靠 `@Param(Constants.WRAPPER)` 叫 `ew`。
