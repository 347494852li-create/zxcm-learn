# 附录 · 答辩作战手册

> **这一篇解决什么问题**：技术你会了，但**讲不出来、被追问就慌、不知道怎么介绍项目**。
> 这里给你：一份 10 分钟讲稿、一张白板图、20 个高频追问、选型口径、坦白点说法、简历 bullet、模拟答辩评分表。
>
> **前提**：这篇不替代各章「本章答辩卡」。先把三卷主线和各章答辩卡过一遍，再用这篇串成一场完整答辩。

---

## 一、答辩到底在考什么

| 维度 | 面试官想确认 | 你要给的东西 |
|---|---|---|
| **真实性** | 你是不是真的做过/读过 | 具体文件、行号、踩过的坑、改过的代码 |
| **系统性** | 你知不知道它在整个系统里的位置 | 一张全景图 + 一条主链路 |
| **深度** | 你是只会用，还是懂原理 | 至少 3 个「为什么这么设计」+ 3 个「怎么改进」 |
| **边界感** | 你会不会把别人的说成自己的 | 主动说明开源/自研边界、项目缺口 |
| **表达** | 能不能让非技术也听懂 | 先业务后技术，先结论后展开 |

> **一句话策略**：**用业务开场，用链路证明，用取舍显深度，用缺口显真实。**

## 二、10 分钟讲稿（按这个顺序，不要从技术栈开始）

### 0:00~1:00 项目一句话 + 业务背景

> 「我讲的是一个**企业合同管理系统**，覆盖合同从起草、审批、用印、履行到归档的全过程。
> 企业需要它，主要解决三件事：**风险控制**（不该签的不签、不该看的不看）、**效率**（模板化、在线编辑、自动编号）、**留痕**（谁改了什么、批了哪一版）。
> 我用的是开源版肇新合同管理系统做学习和二次梳理，重点研究了它的权限、审批流、合同状态和前后端链路。」

**要点**：不要一上来报技术栈；先让面试官知道「这个系统解决什么问题」。

### 1:00~3:00 业务主链（配合白板图）

> 「一条合同的生命周期是：
> **基础数据**（签约主体、合作方、合同类型、编号规则）→ **草拟**（合同主表 + 附件版本）→ **发起审批**（审批单快照 + Activiti 流程实例）→ **审批处理**（同意/驳回/回退/转办/加签）→ **用印**（上传双章合同）→ **履行/变更/续期**→ **作废/关闭**→ **归档**→ **台账/报表**。
> 我重点讲三段：审批、状态、权限。」

**白板画法**（见 §三），边画边说，不要背。

### 3:00~6:00 三个技术亮点

**亮点 1：六个正交状态字段**

> 「合同不是只有一个状态字段，而是六个：总状态、审批、用印、复核、变更、协同。
> 因为状态是正交的：一份合同可以同时『履行中 + 变更中』，一个字段表达不了。
> 前端显示的状态是 `getContractStatusShow` 根据六个字段和时间字段算出来的，不是存出来的。」

**亮点 2：业务表与流程引擎的桥接**

> 「审批用 Activiti 跑，但业务表不直接依赖引擎。`contract_audit_form` 存两个字段：`instance_def_key` 指向流程图，`instance_id` 指向这次流程实例。
> 发起审批时业务侧发 Spring 事件，流程侧监听并启动实例；审批结果再通过事件回写合同状态。两边解耦，换流程不用改业务代码。」

**亮点 3：权限三层**

> 「功能权限用 Sa-Token 的 `@SaCheckPermission`，决定能不能调接口；数据权限用 `@DataPermission` + SpEL，在 MyBatis 拦截器里无痕改写 SQL，决定能看哪些行；再加多租户的 `tenant_id` 隔离。
> 前端 `v-hasPermi` 只是隐藏按钮，不是安全边界。」

### 6:00~8:00 前后端一条链路

> 「以『新增签约主体』为例：页面 `submitForm` 先做表单校验，把两个 JSON 列序列化，调 `api/conf/signingSubject.js` 的 `addSigningSubject`；`request.js` 统一加 `token: Bearer`，请求发到 `/dev-api/...`；开发服务器按 `vue.config.js` 的 proxy 去掉前缀转发到 8080；后端 Controller 接 BO，Service 做业务校验和事务，Mapper 落库；返回 `R`，前端提示成功并刷新列表。」

**要点**：这条链路能讲清，面试官就知道你真的读过前后端。

### 8:00~9:30 缺口与改进（主动说）

> 「这个开源版有几个明确的边界：
> ① 归档/借阅/关闭只有 Service，没有 Controller 和前端，属于商业版裁剪；
> ② 续期后端接口有、前端没接；
> ③ 数据权限的 `elseSql` 兜底实际是死分支，配置缺失时默认放行，安全方向反了；
> ④ 脱敏组件被一行 `return true` 关掉，Spring Cache 配了没用，线程池 `enabled:false` 导致一半参数不生效。
> 如果要改，我会优先补归档写链路、把数据权限默认改成拒绝、再把首页 7 次 COUNT 合成一次 GROUP BY。」

**要点**：主动说缺口是加分项，但每个缺口都要能说出「怎么改」。

### 9:30~10:00 收尾

> 「这个项目让我完整理解了企业后台的权限、流程、状态、版本和前后端协作。我目前能独立加字段、加页面、加接口，也能按链路排查问题；下一步想深入的是流程引擎的边界情况和数据权限的性能。」

## 三、白板图：5 个框 + 4 条线

```
┌──────────────┐      ┌──────────────┐      ┌──────────────┐
│   前端 Vue2   │ ───► │  后端 Spring  │ ───► │ MySQL        │
│ 页面/路由/权限 │      │ Controller   │      │ 业务表/框架表 │
│ axios/代理    │ ◄─── │ Service      │ ◄─── │ Activiti 表  │
└──────────────┘      │ Mapper       │      └──────────────┘
       │              └──────┬───────┘
       │                     │
       ▼                     ▼
┌──────────────┐      ┌──────────────┐
│ Redis        │      │ 文件/OnlyOffice│
│ token/缓存    │      │ 附件/在线编辑  │
└──────────────┘      └──────────────┘
```

**边画边说的四句话**：

1. 前端只请求同源 `/dev-api`，开发服务器代理到 8080。
2. 后端三层：Controller 接参、Service 业务/事务、Mapper SQL。
3. 权限横切：Sa-Token 管接口，数据权限拦截器改 SQL，租户插件加 `tenant_id`。
4. 流程横切：业务表通过 `instance_id` 桥接 Activiti，事件解耦。

## 四、五个模块的「三句话讲法」

> 每个模块准备三句：**解决什么问题 → 关键设计 → 一个缺口/亮点**。面试官挑哪个模块都能接。

### 1. 签约主体 / 合作方

- 解决「我方是谁、对方是谁」的主数据问题。
- 关键设计：JSON 存银行账号/联系人（一起读写、不独立检索）；逻辑删除 + 数据权限。
- 亮点/缺口：合作方「只能改自己的」靠后端数据权限，前端只是提示。

### 2. 合同草拟

- 解决合同第一次进系统：基本信息 + 附件 + 版本。
- 关键设计：`contract_draft` 宽表 + `contract_draft_files` 版本表；文件组 JSON。
- 亮点/缺口：版本表保证法律留痕；文件组 JSON 不适合按文件检索。

### 3. 审批流

- 解决「谁批、批到哪、批完干什么」。
- 关键设计：Activiti 流程 + 审批单快照 + 六个状态字段 + Spring 事件桥接。
- 亮点/缺口：流程可配置；状态约束散落在 if 里，是隐式状态机。

### 4. 用印 / 收尾

- 解决合同签完之后的用印、作废、续期、归档。
- 关键设计：双章文件单独类型；作废是状态不是删除；历史不可变。
- 亮点/缺口：归档/借阅/关闭写链路未接通，续期前端没接。

### 5. 报表 / 台账

- 解决「查得到、导得出、看得懂」。
- 关键设计：台账是多表 JOIN 读视图；报表单独聚合；导出用 EasyPOI。
- 亮点/缺口：首页 7 次 COUNT 可优化；`borrowAuditCount` 写死 0。

## 五、20 个高频追问（10 秒答案 + 证据）

> 更细的题在各章「本章答辩卡」；这里是答辩最常被追的 20 个。

| # | 追问 | 10 秒答案 | 证据 |
|---|---|---|---|
| 1 | 你们的登录流程？ | 验证码 → 查用户 → BCrypt → 组装 `LoginUser` → Sa-Token 生成 token → Redis 会话 → 返回 token | 基座第 2 章 §4；`SysLoginService.java` |
| 2 | token 为什么还要存 Redis？ | 纯 JWT 无法主动失效；存 Redis 才能踢人、强制注销、多端控制 | 基座第 2 章 §4.5 |
| 3 | 认证和鉴权区别？ | 认证=你是谁；鉴权=你能不能调这个接口 | 基座第 1/3 章 |
| 4 | 功能权限和数据权限区别？ | 前者管「能不能进接口」，后者管「进去能看哪些行」 | 基座第 3/4 章 |
| 5 | 数据权限怎么做到不改业务 SQL？ | MyBatis 拦截器 + JSqlParser 解析 SQL，注入 `WHERE` | 基座第 4 章 §4；`PlusDataPermissionHandler` |
| 6 | 前端隐藏按钮就安全了吗？ | 不安全；必须后端 `@SaCheckPermission` | 基座第 3 章；`hasPermi.js` |
| 7 | 为什么用 Sa-Token 不用 Spring Security？ | 后台管理场景要登录+权限+踢人，Sa-Token 代码量最少；Security 适合 OAuth2/网关 | 基座第 2 章 §7 |
| 8 | 合同为什么六个状态字段？ | 状态正交；一个字段表达不了「履行中+变更中」 | 后端第 6 章 §1.2 |
| 9 | 审批流为什么用 Activiti？ | 规则常变，画图改数据即可；引擎提供待办/历史/转办/加签 | 后端第 6 章 §2.1 |
| 10 | 业务表和流程表怎么关联？ | 审批单存 `instance_def_key` + `instance_id` | 后端第 6 章 §1.3 |
| 11 | 审批通过后怎么改合同状态？ | 流程监听器发事件/回写状态；业务与引擎解耦 | 后端第 6 章 §4.3 |
| 12 | 为什么合同要版本表？ | 法律文件必须知道审批/盖章的是哪一版；覆盖会丢历史 | 后端第 5 章 §1.3 |
| 13 | 宽表和拆表怎么选？ | 字段稳定、一起读写 → 宽表；变化频率/访问方式不同 → 拆 | 后端第 5 章 §7 |
| 14 | 文件组为什么用 JSON？ | 总是一起读写、不独立检索；建子表成本大于收益 | 后端第 5 章 §1.4 |
| 15 | 编号为什么不用自增？ | 业务编号带前缀/日期/分类，要预览、补号；规则可配置 | 后端第 3 章 |
| 16 | 续期和续签区别？ | 续期=改结束时间；续签=新合同+关联老合同 | 后端第 9 章 §2.6 |
| 17 | 作废为什么不删除？ | 合同是法律文件，必须留痕；作废只是状态 | 后端第 9 章 §5.2 |
| 18 | 台账和合同表什么关系？ | 台账是多表 JOIN 的读视图，不是独立表 | 后端第 10 章 §2.4 |
| 19 | 前端动态路由怎么来的？ | 登录后 `getRouters` 返回菜单树，`filterAsyncRouter` 转成路由，`addRoutes` | 前端第 2 章；`permission.js` |
| 20 | 一次点击怎么到后端？ | 按钮 → 方法 → api → request 拦截器加 token → `/dev-api` → 代理 → Controller | 前端精读 4；`vue.config.js` |

### 追问的「反杀句」

被追问到不会时，不要硬编，用这三句之一：

- 「这块我只读到/做到 X，还没深入 Y；我的理解是……回去我会从 Z 入手补。」
- 「这个设计在开源版里是 A，但如果规模变大，我会改成 B，因为 C。」
- 「我不能确定线上是不是这样，代码里看到的是 X；如果要确认，我会查 Y。」

> **诚实 + 给出下一步**，比编一个错误答案得分高。

## 六、选型对比口径（被问「为什么不用 X」时）

| 选择 | 本项目 | 替代方案 | 怎么答 |
|---|---|---|---|
| 鉴权 | Sa-Token | Spring Security / Shiro | 后台管理要轻量登录+权限+踢人；Security 适合 OAuth2/网关 |
| 流程 | Activiti 6 | 自写 if-else / Flowable | 规则常变、要待办/历史/流程图；Flowable 是 Activiti 分支，迁移成本高 |
| ORM | MyBatis-Plus | JPA / 纯 MyBatis | 既要 CRUD 效率，又要手写复杂 SQL；JPA 复杂查询不灵活 |
| 缓存 | Redis | 本地 Caffeine | 要集群共享 token/缓存；本地缓存多实例不一致 |
| 会话 | Redis 会话 | 纯 JWT | 要能踢人/强制注销；纯 JWT 签发后不可撤销 |
| 一对多 | JSON 字段 | 子表 | 总是一起读写、不独立检索；子表成本大于收益 |
| 文件存储 | 本地磁盘 + 路径 | OSS/MinIO | 开源版简单；生产应换对象存储，避免单机磁盘和 URL 泄漏 |
| 前端 | Vue2 + Element UI | Vue3 + Element Plus | 项目版本锁定；Vue2 已 EOL，新项目应 Vue3 |

> **答法公式**：**场景 → 约束 → 取舍 → 代价**。不要只说「因为方便」。

## 七、缺口怎么说（主动交代的 5 个）

| 缺口 | 一句话 | 怎么改 |
|---|---|---|
| 归档/借阅/关闭写链路缺失 | 只有 Service，没有 Controller/前端，商业版裁剪 | 补 Controller + 页面 + 权限码；关闭接定时任务 |
| 数据权限默认放行 | 列值为空时 `return ""`，等于看全部；`elseSql` 是死分支 | 默认收敛到 `1=0`；修 `isSuccess` 逻辑 |
| 脱敏被关 | `isSensitive()` 恒 `true`，全项目明文 | 按租户/角色返回真实判断 |
| Spring Cache 配了没用 | `@Cacheable` 全被注释 | 选高频只读接口启用，设 TTL |
| 线程池配置假生效 | `enabled:false`，只有 corePoolSize 生效 | 打开开关，压测后调参 |

> **说法**：「这些不是我不知道，而是我读源码时确认过的边界；如果给我时间，我会按上面的顺序改。」

## 八、简历 bullet（5 条，按 STARR 写）

> 不要写「参与开发」，要写「做了什么 + 用了什么 + 结果/难点」。

1. **合同全生命周期**：梳理并实现/复现合同从草拟、审批、用印、履行到归档的主链路，覆盖 10+ 业务表、6 个正交状态字段。
2. **审批流**：基于 Activiti 6 接入可配置审批流，设计「审批单快照 + `instanceId` 桥接 + Spring 事件回写」方案，实现业务与引擎解耦。
3. **权限体系**：基于 Sa-Token + MyBatis 拦截器实现功能权限、数据权限、多租户隔离三层控制；数据权限通过 SpEL 模板无痕改写 SQL。
4. **前后端链路**：熟悉 Vue2/Element UI/axios/Vuex，能定位「按钮 → api → 拦截器 → 代理 → Controller → Service → Mapper」全链路问题。
5. **性能与稳定性**：识别并优化首页 7 次 COUNT、字典缓存无 TTL、线程池配置假生效等问题，给出可落地的改进方案。

> **注意**：如果项目是学习开源项目，面试时明确说「基于开源版做学习、复现和二次梳理」，不要声称从零原创。

## 九、模拟答辩流程（30 分钟）

| 环节 | 时间 | 要求 | 自评 |
|---|---|---|---|
| 自我介绍 + 项目一句话 | 1 分钟 | 说清业务价值，不报技术栈 | □ |
| 业务主链 + 白板图 | 4 分钟 | 10 个阶段不断线 | □ |
| 三个技术亮点 | 5 分钟 | 每个「是什么 → 为什么 → 代价」 | □ |
| 前后端一条链路 | 3 分钟 | 11 跳说清 | □ |
| 缺口与改进 | 3 分钟 | 3 个缺口 + 3 个改法 | □ |
| 追问 10 个 | 10 分钟 | 每个 10 秒开口 | □ |
| 反问 | 4 分钟 | 问团队/业务/技术演进 | □ |

**打分表（每项 1~5 分）**：

| 项 | 1 分 | 3 分 | 5 分 |
|---|---|---|---|
| 业务表达 | 只会报技术栈 | 能讲主链 | 能让外行听懂 |
| 技术深度 | 只会用 | 能讲设计 | 能讲取舍/代价 |
| 真实性 | 说不出文件 | 能说模块 | 能说文件:行号/坑 |
| 边界感 | 假装完美 | 被问才说缺口 | 主动说缺口+改法 |
| 应变 | 卡住沉默 | 能绕回 | 诚实+给下一步 |

> 目标：**每项 ≥3 分，真实性/边界感 ≥4 分**。

## 十一、最后三句话

1. **不要背稿，背结构**：业务 → 主链 → 亮点 → 链路 → 缺口。
2. **每个结论都带证据**：文件、行号、表、接口、日志。
3. **不会就说不会，但要给下一步**：诚实比完美更像真的。

> 你准备到什么程度算够？**合上所有文档，能对着一张白纸讲 10 分钟，并被追问 10 个问题不慌**——就够了。
