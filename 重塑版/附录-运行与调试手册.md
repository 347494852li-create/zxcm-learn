## 三、调试工具箱：5 个最常用的动作

### 3.1 浏览器 Network：先判断「前端发没发对」

1. F12 → Network；
2. 勾选 **Fetch/XHR**；
3. 操作页面（点查询/新增）；
4. 看目标请求：
   - **Request URL**：是不是 `/dev-api/...`？路径对不对？
   - **Request Headers**：有没有 `token: Bearer ...`？
   - **Payload / Query String**：参数名和值对不对？
   - **Response**：`code` 是 200 还是 401/500？`msg` 是什么？
5. 如果请求根本没出现 → 前端方法没触发/被校验拦住，去 Console 看报错；
6. 如果请求出现了但 URL 不对 → 查 `api/*.js` 的 `url` 和 `request.js` 的 `baseURL`；
7. 如果请求转了但 404/500 → 转后端排查（§3.2）。

### 3.2 后端 SQL 日志：看框架到底发了什么 SQL

本项目已开启 MyBatis 标准输出（`ruoyi-admin/src/main/resources/application.yml:241`）：

```yaml
logImpl: org.apache.ibatis.logging.stdout.StdOutImpl
```

启动后，IDEA 控制台会打印：

```
==>  Preparing: SELECT ... FROM contract_draft WHERE ...
==> Parameters: ...
<==      Total: 10
```

**用法**：
- 数据没查到 → 把 SQL 复制到 MySQL 客户端执行，看是不是条件/数据权限的问题；
- 数据权限没生效 → 看 SQL 里有没有多出 `AND (...)` 条件；
- 更新/删除影响 0 行 → 看 `WHERE` 条件是不是被逻辑删除/租户条件过滤掉了。

### 3.3 Redis：看 token、缓存、错误次数

```bash
redis-cli -h 192.168.56.10 -a root -n 5

# 看所有 key（生产环境别用 keys *，本地可以）
keys *

# 看登录会话
get satoken:login:token:<token>

# 看某个业务缓存（前缀见基座第 12 章）
get sys_dict:...
```

常见 key：
- `satoken:login:token:*`：token 会话；
- `captcha_codes:*`：验证码（校验后立即删）；
- 登录错误次数 key（`Constants.LOGIN_ERROR + tenantId + ":" + username`）；
- 字典/参数缓存。

### 3.4 MySQL：确认数据到底进没进库

```bash
mysql --no-defaults --ssl-mode=DISABLED -h192.168.56.10 -uroot -proot zxcm
```

常用查询：

```sql
-- 合同主表最近 5 条
SELECT id, contract_name, contract_status, contract_approve_status, del_flag, create_time
FROM contract_draft ORDER BY create_time DESC LIMIT 5;

-- 某合同的文件版本
SELECT id, contract_id, file_type, version, del_flag
FROM contract_draft_files WHERE contract_id = 'xxx' ORDER BY create_time;

-- 审批单
SELECT id, contract_id, instance_id, instance_def_key, audit_status
FROM contract_audit_form WHERE contract_id = 'xxx';

-- 菜单是否存在
SELECT menu_id, menu_name, path, component, perms FROM sys_menu WHERE menu_name LIKE '%合同%';
```

> 老客户端连 MySQL 8 必须加 `--no-defaults --ssl-mode=DISABLED`，否则可能报 SSL/认证错误。

### 3.5 断点：按「一层一入口」下

| 想确认 | 断点位置 |
|---|---|
| 请求有没有进后端 | Controller 方法第一行（如 `TSigningSubjectController.list`） |
| 参数有没有绑上 | Controller 方法参数 / BO 的 getter |
| 业务规则走没走 | ServiceImpl 的关键 `if` / `validEntityBeforeSave` |
| SQL 条件对不对 | Mapper 方法 / `buildQueryWrapper` |
| 数据权限改了什么 | `PlusDataPermissionHandler` 的 `buildDataFilter` |
| 登录态有没有 | `LoginHelper.getLoginUser()` |
| 前端请求怎么发的 | `zxcm-ui/src/utils/request.js` 请求拦截器 |

> 断点调试比加 `System.out` 快，也不会忘删。

## 四、故障树：按现象查

### 4.1 启动类

| 现象 | 大概率原因 | 处理 |
|---|---|---|
| `Port 8080 was already in use` | 端口被占 | `netstat -ano \| findstr :8080`，kill 或改 `server.port` |
| `Communications link failure` | MySQL 没起/地址错 | 先跑 §一 的 MySQL 连通命令 |
| `Unable to connect to Redis` | Redis 没起/密码错 | 先跑 `redis-cli ping`；核对 `application-dev.yml` 的 host/password/db |
| `Unknown database 'zxcm'` | 库没建/库名不对 | `show databases;`；建库或改 JDBC URL |
| `Table 'zxcm.xxx' doesn't exist` | 建表脚本没跑全 | 按后端第 1 章的 4 个脚本顺序补跑 |
| `Access denied for user` | 账号密码/权限不对 | 核对 `application-dev.yml` |
| `ERR_OSSL_EVP_UNSUPPORTED` | Node 新版本 + webpack 4 | 确认 `npm run dev` 带 `--openssl-legacy-provider` |
| `node: command not found` | PATH 没前置 | `export PATH="/e/nvm/v24.9.0:$PATH"` |

### 4.2 登录 / 权限

| 现象 | 大概率原因 | 处理 |
|---|---|---|
| 登录页验证码不显示 | 后端没起/验证码接口 500 | Network 看 `captchaImage`；看后端日志 |
| 登录提示「用户不存在/密码错误」 | 账号错/租户选错 | 确认租户；查 `sys_user` |
| 登录成功但页面空白 | 前端路由/JS 报错 | Console 看第一个红色错误 |
| 登录后菜单为空 | `getRouters` 没返回/角色没授权 | 查 `sys_menu` + `sys_role_menu`；看接口 Response |
| 刷新后 404 | history 模式 + 服务器没配 fallback | 开发环境确认 devServer；生产配 Nginx `try_files` |
| 接口 401 | token 没带/过期/被顶下线 | Network 看请求头；重新登录；查 Redis 会话 |
| 接口 403 | 没权限码 | 查 `sys_menu.perms` 和角色授权；后端看 `@SaCheckPermission` |
| 按钮看不到 | `v-hasPermi` 没权限 | 查当前用户 `permissions` 是否包含该权限码 |
| `NavigationDuplicated` | 重复 push 同一路由 | 项目已用 `.catch(() => {})`；新代码也要处理 |

### 4.3 请求 / 代理 / 数据

| 现象 | 大概率原因 | 处理 |
|---|---|---|
| 请求 URL 是 `http://localhost/dev-api/...` 且 404 | 代理没配/后端没起 | 看 `vue.config.js` proxy；`curl localhost:8080` |
| 请求直接打 8080 被 CORS 拦 | 没走 `/dev-api` | 检查 `request.js` 的 `baseURL` 和 api 的 `url` |
| 请求转圈后 `ECONNREFUSED` | 后端没起/端口错 | 起后端；核对 target |
| 请求 200 但页面没数据 | 返回结构不是 `{rows,total}` / 字段名不对 | Network 看 Response；对照 `TableDataInfo` |
| 新增成功但列表没有 | 查询条件/数据权限/分页 | 查 SQL 日志和 `del_flag` |
| 参数全是 null | JSON 字段名和 BO 对不上 | 对比 api 的键和 BO 字段 |
| 后端报「xxx不能为空」 | 分组校验 | 看 `@Validated(AddGroup/EditGroup)` 和 BO 注解 |
| 上传失败 | 文件大小/类型/目录权限 | 看 `application.yml` 的 multipart 限制；看 `ruoyi.profile` 目录 |
| 上传成功但下载 404 | 文件路径/相对路径问题 | 查 `conf_file` 的路径和磁盘文件 |
| Excel 导出乱码/打不开 | 响应头/文件名编码 | 看 `download` 方法和浏览器 Network |

### 4.4 工作流 / 文档 / 其他

| 现象 | 大概率原因 | 处理 |
|---|---|---|
| 发起审批报「流程定义不存在」 | 流程图没部署/`instanceDefKey` 错 | 查 `act_re_procdef`；看设计器是否发布 |
| 待办为空 | 任务没派到当前人/流程没启动 | 查 `act_ru_task` 的 `ASSIGNEE_` |
| 审批后状态没变 | 监听器没触发/事件没发 | 看后端日志和 `contract_audit_form` |
| OnlyOffice 打不开 | 文档服务器没起/地址不可达 | `curl` OnlyOffice 地址；看 `application-dev.yml` 的 domain/port/callbackUrl |
| OnlyOffice 回调不保存 | 回调地址容器访问不到 | 用 `host.docker.internal` 或宿主机 IP |
| 归档按钮找不到 | 开源版只读 | 这是预期缺口（后端第 9 章） |
| 续期按钮找不到 | 前端没接 | 这是预期缺口（后端第 9 章） |
| 报表数字不对 | 统计口径/时间字段 | 对照 `DashboardController` 的 SQL |
| 定时任务不跑 | `xxl.job.enabled: false` | 本地默认关闭，属预期 |

## 五、每次改代码后的回归清单

> 改完一个功能，至少跑这 6 条，别只看「页面没报错」。

- [ ] **接口**：Network 里目标请求 200，Response 的 `code=200`
- [ ] **数据库**：目标表数据真的变了（`SELECT` 确认）
- [ ] **权限**：换一个没权限的账号，按钮/接口被拦
- [ ] **边界**：空值、超长、重复提交、非法状态各试一次
- [ ] **前端**：刷新页面后数据还在（不是只存在内存）
- [ ] **日志**：后端没有新的 ERROR/异常堆栈

## 七、一页排查口诀

```
先看三层：Network 看请求 → 后端日志看异常 → 数据库看数据
登录问题：先看 401/token/Cookie，再看 Redis 会话
菜单问题：先看 getRouters 返回，再看 sys_menu/sys_role_menu
数据问题：先看 SQL 日志，再看数据权限/租户/逻辑删除
前端问题：先看 Console 第一个红错，再看 Network 第一个失败请求
```

> 记住：**不要一上来就改代码**。先用上面的顺序定位「是哪一层的问题」，再动手。
