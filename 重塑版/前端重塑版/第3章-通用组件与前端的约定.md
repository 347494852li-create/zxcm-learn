# 第 3 章 · 通用组件与前端的「约定」

> 前面两章讲了「请求」和「权限」两条线。这一章讲第三条线：**「约定」**。打开任何一个业务页面，你会看到一堆没 import 就直接用的东西——`<JTable>`、`v-hasPermi`、`this.$modal`、`dict.type.xxx`。它们从哪来、怎么用、为什么这么设计，这一章一次讲清。**读完这章，后面对任何页面都能「无障碍阅读」，不会再被陌生的名字绊住。**

> **零基础先补概念（第一次看「约定」，先读这 4 条）**
>
> 1. **全局组件**：用 `Vue.component('名字', 组件)` 注册一次，所有页面都能直接写 `<名字 />`，不用 import。本项目 `JTable`、`Pagination` 都在 `zxcm-ui/src/main.js:93-106` 注册。见《Vue2 从 0 到精通》第 4 章 §3.2。
> 2. **mixin（混入）**：把一段组件选项（`data`、`created` 等）「合并」进使用它的组件。本项目用全局 mixin 给声明了 `dicts` 的页面自动注入字典（`zxcm-ui/src/utils/dict/index.js:6-32`）。见《Vue2 从 0 到精通》第 10 章 §六。
> 3. **字典**：后端维护的「编码 → 中文」映射表。页面只声明字典类型（如 `BUSINESS_STATUS`），显示时用 `<DictTag>` 查表；具体有哪些编码、翻成什么，都以「字典管理」里的配置为准。
> 4. **插槽（slot）**：父组件写在子组件标签内部的内容，会塞进子组件模板的 `<slot />` 位置。`JTable` 就是靠 `<slot />`（`zxcm-ui/src/components/JTable/index.vue:22`）把页面里写的 `<el-table-column>` 收进来的。见《Vue2 从 0 到精通》第 4 章 §8.1。

## 一、这部分是做什么的

一个后台系统有上百个页面，其中 90% 长得**几乎一样**：

- 上面一排搜索条件
- 中间一排操作按钮 + 一个表格
- 下面一个分页条
- 点新增/编辑弹一个表单弹窗
- 列表里的「状态」列要显示成「草稿/审批中/已完成」而不是 `0/1/3`

如果每个页面都从头写一遍这些，会有**巨量重复代码**。本项目的解法是**把「重复」抽象成「约定」**：

| 重复的东西 | 抽象成 | 用法 |
|---|---|---|
| 表格 + 序号列 + 分页 | `<JTable>` + `<Pagination>` | 传 `data` 就行 |
| 状态码 ↔ 中文标签 | **字典机制**（`dicts` + `<DictTag>`） | `dicts: ['BUSINESS_STATUS']` 一行 |
| 成功/错误提示、确认框 | `this.$modal.msgSuccess(...)` | 一行 |
| 弹窗 | `el-dialog` 是 Element 自带 | 直接写 |
| 文件上传 | `<FileUpload>` / `<FileUploadContract>` | 传地址 |

**一句话定位**：本章是「前端的公共零件库说明书」。后面第 4~10 章每读一个页面，你都会看到这些零件被反复使用——**这一章没读透，后面会一直卡**。

## 二、站在架构师角度，为什么这么设计

### 2.1 为什么是「全局注册」而不是「每个页面 import」

本项目的组件分两层：

- **Element-UI 原生组件**（`el-table`、`el-dialog`、`el-button`…）：靠 `Vue.use(Element)` 全局注册（`main.js:128`），任何页面直接用。
- **本项目自研/封装的组件**（`JTable`、`Pagination`、`DictTag`、`FileUpload…`）：靠 `Vue.component('名字', 组件)` 全局注册（`main.js:93-106`）。

**为什么不每个页面 import**：一个组件被 100 个页面用，import 就是 100 行重复。全局注册后，**你只要知道「有哪些全局组件」，读任何页面都不用找 import**。这是「约定优于配置」。

**代价（也是答辩点）**：全局注册的组件**没有 IDE 的自动补全和跳转**（因为编译器不知道标签从哪来），排查时要回头看 `zxcm-ui/src/main.js:93-106`。所以本项目只把「高频、通用」的组件全局注册，低频的（如某个页面的子组件）还是页面内自己 import。

### 2.2 为什么要有「字典」这套机制

后台系统里，数据库存的往往是**编码**而不是中文：

- 合同状态存 `'0'`（拟定中）、`'3'`（审批中）、`'6'`（履行中）（后端枚举见 `zxcm-contract/src/main/java/com/ruoyi/contract/enums/ContractEnums.java:19-21`；界面文案以字典配置为准）
- 是否删除存 `'0'/'1'`
- 合同类型存某个 ID

**界面必须显示中文**。如果每个页面自己写「把 `'0'` 翻译成『草稿』」的映射，会有两个问题：
1. **重复**：几十个页面都要翻译同样的状态码。
2. **不可维护**：公司改个措辞（「草稿」→「拟稿」），要改几十处。

**本项目的解法：字典（Dict）机制**——把「编码↔中文」的映射**存到后端数据库**，前端启动页面时一次性拉下来，之后用 `dict.type.字典类型名` 就能拿到整张映射表（如 `dict.type.BUSINESS_STATUS`）。

**为什么放后端**：字典是「业务配置」，不是「前端代码」。运维在后台改一个字典项，页面刷新/重新进入后生效，**不用改前端、不用发版**。这和第 2 章「菜单由后端下发」是同一个思路：**能让运营改的，就别写死在代码里。**

### 2.3 为什么字典要用 `mixin`（全局混入）

字典的实现（`zxcm-ui/src/utils/dict/index.js:6-32`）用了 Vue 的 **mixin**：给**每个组件**都混入一个 `data().dict` 和一个 `created()` 钩子。

```js
// utils/dict/index.js:6-32（简化）
Vue.mixin({
  data() {
    if (this.$options.dicts === undefined) return {}      // 没声明 dicts 的组件，啥也不做
    const dict = new Dict()
    return { dict }
  },
  created() {
    if (!(this.dict instanceof Dict)) return              // 同上，跳过
    this.dict.init(this.$options.dicts).then(() => { ... }) // 按需加载字典
  }
})
```

**怎么用**：在页面里写一行

```js
export default {
  dicts: ['BUSINESS_STATUS'],    // 声明我要用哪些字典（真实例见签约主体页）
  ...
}
```

**关键设计（很重要）**：mixin 里先判断 `this.$options.dicts`——**没声明 `dicts` 的组件直接 `return {}`，完全不初始化字典**。这样就不会「所有组件都去请求字典」，只有真正声明的页面才拉。**这是「按需加载」的优雅实现**，也是答辩的加分点。

### 2.4 `JTable` 为什么值得自己封装

Element 的 `<el-table>` 已经很好用了，为什么还要封 `JTable`？

看 `zxcm-ui/src/components/JTable/index.vue:1-91` 全文（91 行），`JTable` 做了这些事：
- 包一层 `<el-table>`（`:2`），**`v-bind="$attrs"` + `v-on="$listeners"`**（`:8,12`）——把外面传的所有属性和事件**透传**给内部 `el-table`，所以 `JTable` 用法和 `el-table` 几乎一样。
- **自动加「序号列」**（`:15-21`，`hasNO` 默认 `true`）。
- **可选加「多选列」**（`:14`，`hasC` 默认 `false`）。
- **`<slot />` 透传列定义**（`:22`）——你在 `<JTable>` 里写的 `<el-table-column>` 会塞进 slot。
- **`doLayout()`**（`:82-88`）：`data` 或 `columnData` 变化时，`setTimeout 100ms + nextTick` 后重算表格布局。**这是为了修 Element 表格「列宽不刷新」的经典 bug**——数据变了但表格布局不重绘，会出现列宽错乱。

**为什么值得封**：本项目 **90% 的列表页**都长一样（序号 + 部分多选 + 一堆列 + 透传分页）。封成 `JTable` 后，页面代码写 `<JTable :data="list">...</JTable>` 就完事。**这是「本项目前端最大的自研亮点」**，答辩时讲清楚 `$attrs`/`$listeners` 透传 + `doLayout` 解决列宽 bug，层次就上去了。

### 2.5 `plugins/` 里的 `$modal`、`$auth` 等是什么

`main.js:110` 的 `Vue.use(plugins)` 把一批工具挂到 `Vue.prototype` 上（`plugins/index.js:8-19`）：

| 挂载 | 文件 | 干啥 |
|---|---|---|
| `this.$modal` | `plugins/modal.js` | 消息/确认框（`msgSuccess`/`confirm`/`alert`…） |
| `this.$auth` | `plugins/auth.js` | 权限判断方法（`hasPermi`/`hasRole`，第 2 章讲过） |
| `this.$tab` | `plugins/tab.js` | 标签页操作（打开/关闭页签） |
| `this.$cache` | `plugins/cache.js` | 本地缓存读写（local/session） |
| `this.$download` | `plugins/download.js` | 下载相关 |

**为什么单独搞个 `plugins`**：这些是「工具方法」不是「组件」，挂在 `Vue.prototype` 上后，任何组件 `this.$modal.xxx()` 就能用，不用 import。

> **读代码的口诀**：看到 `this.$xxx` → 去 `plugins/` 找；看到 `<XxxYyy>` 未 import → 去 `main.js:93-106` 找；看到 `dict.type.xxx` → 这是字典机制（本章 §2.2）。

### 4.2 字典机制：三步用法

**第一步**：页面声明要用哪些字典（`dicts` 数组，值是**字典类型名**）：

```js
export default {
  dicts: ['BUSINESS_STATUS'],   // 真实例：签约主体页用到的字典类型
  ...
}
```

**第二步**：等字典就绪。有两种方式：
- **模板里直接用**：`dict.type.BUSINESS_STATUS` 就是数组（`[{ label:'...', value:'...' }, ...]`，label 具体文案以后端字典为准），配合 `<DictTag :options="dict.type.BUSINESS_STATUS" :value="row.businessStatus" />` 显示。
- **`onDictReady` 回调**：字典加载完会触发，需要「拿到字典后做点别的」时用（`utils/dict/index.js:26`）。

**第三步**：显示。`<DictTag>`（`components/DictTag/index.vue`）接收 `options`（字典数组）和 `value`（当前编码），在数组里找到匹配项，**根据字典项的 `listClass` 决定显示成普通文字还是彩色 `el-tag`**（`:6-23`）。

**一个真实例子**（签约主体页，`zxcm-ui/src/views/conf/signingSubject/index.vue`）：
```js
// zxcm-ui/src/views/conf/signingSubject/index.vue:607
dicts: ['BUSINESS_STATUS'],
```
模板里（`zxcm-ui/src/views/conf/signingSubject/index.vue:155-160`）：
```vue
<template slot-scope="scope">
  <dict-tag
    :options="dict.type.BUSINESS_STATUS"
    :value="scope.row.businessStatus"
  />
</template>
```

> ⚠️ **注意 `dict.type.xxx` 和 `dict.label.xxx` 的区别**：`dict.type` 是**数组**（给 `<DictTag>` 用），`dict.label` 是**对象**（如 `{ '0':'拟定中', '3':'审批中' }`，具体文案以后端字典为准，给「直接取中文」用）。定义在 `utils/dict/Dict.js:19-20,35-36`。

### 4.3 标准 CRUD 页面的「骨架」（后面几章反复用）

90% 的业务页面都是这个骨架，认熟了看新页面就快了：

```vue
<template>
  <div class="app-container">
    <!-- ① 搜索区 -->
    <el-form ref="queryForm" :model="queryParams" :inline="true">
      <el-form-item label="名称"><el-input v-model="queryParams.name" /></el-form-item>
      <el-form-item>
        <el-button type="primary" @click="handleQuery">搜索</el-button>
        <el-button @click="resetQuery">重置</el-button>
      </el-form-item>
    </el-form>

    <!-- ② 工具条 -->
    <el-row>
      <el-button v-hasPermi="['xxx:add']" @click="handleAdd">新增</el-button>
      <right-toolbar @queryTable="getList" />
    </el-row>

    <!-- ③ 表格 -->
    <JTable :data="tableData">
      <el-table-column label="名称" prop="name" />
      <el-table-column label="状态">
        <template slot-scope="scope">
          <dict-tag :options="dict.type.xxx" :value="scope.row.status" />
        </template>
      </el-table-column>
      <el-table-column label="操作">
        <template slot-scope="scope">
          <el-button v-hasPermi="['xxx:edit']" @click="handleUpdate(scope.row)">修改</el-button>
          <el-button v-hasPermi="['xxx:remove']" @click="handleDelete(scope.row)">删除</el-button>
        </template>
      </el-table-column>
    </JTable>

    <!-- ④ 分页 -->
    <pagination :total="total" :page.sync="queryParams.pageNum" :limit.sync="queryParams.pageSize"
                @pagination="getList" />

    <!-- ⑤ 新增/编辑弹窗 -->
    <el-dialog :visible.sync="open" title="...">
      <el-form ref="form" :model="form" :rules="rules">...</el-form>
    </el-dialog>
  </div>
</template>

<script>
export default {
  dicts: ['xxx'],
  data() {
    return {
      tableData: [], total: 0, open: false,
      queryParams: { pageNum: 1, pageSize: 10, name: '' },  // 查询条件
      form: {},                                             // 弹窗表单
      rules: {}                                             // 校验规则
    }
  },
  created() { this.getList() },                             // 进页面就拉列表
  methods: {
    getList()       { listXxx(this.queryParams).then(res => { this.tableData = res.rows; this.total = res.total }) },
    handleQuery()   { this.queryParams.pageNum = 1; this.getList() },
    resetQuery()    { this.resetForm('queryForm'); this.getList() },
    handleAdd()     { this.reset(); this.open = true },
    handleUpdate(r) { this.form = {...r}; this.open = true },
    submitForm()    { /* add/update 二选一 */ },
    handleDelete(r) { this.$modal.confirm('确认删除？').then(() => delXxx(r.id)).then(() => this.getList()) },
  }
}
</script>
```

**记住这个骨架**，第 4 章（基础数据页）几乎就是它的展开；第 5~10 章是它的各种变体。

### 4.4 我想改「状态列显示的中文」怎么办

**不要改前端代码**。去后端「字典管理」里改字典项——这就是 §2.2 说的「字典存后端」的意义。前端只负责按 `value` 查 `label`。

### 4.5 我想改「分页每页显示多少条」

`<Pagination>` 的 `pageSizes` prop 默认 `[10,20,30,50]`（`zxcm-ui/src/components/Pagination/index.vue:39`），`limit` 默认 20（`:32-34`，默认值在 `:34`）。页面里一般用 `queryParams.pageSize = 10` 覆盖。

### 4.6 逐行读：`JTable` 是怎么「包一层」的（`zxcm-ui/src/components/JTable/index.vue:1-24`）

```vue
<template>
  <el-table
    ref="JTable"
    :data="data"
    class="Jcommon-table"
    :height="height"
    :element-loading-text="'加载中'"
    v-bind="$attrs"
    :border="border"
    :tree-props="treeProps"
    :row-key="rowKey"
    v-on="$listeners"
  >
    <el-table-column v-if="hasC" type="selection" width="50" align="center" />
    <el-table-column
      v-if="hasNO"
      type="index"
      width="50"
      label="序号"
      align="center"
    />
    <slot />
  </el-table>
</template>
```

| 行号 | 这一行在干什么 | 为什么这么写 |
|---|---|---|
| `:2` | 用 `<el-table>` 当根元素 | JTable 不重写表格，只在 Element 表格外面加能力 |
| `:3` | `ref="JTable"` | 让 `doLayout()` 能拿到内部表格实例（`:85`） |
| `:4` | `:data="data"` | 表格数据由页面通过 prop 传进来 |
| `:5` | `class="Jcommon-table"` | 统一本项目表格的样式 |
| `:6` | `:height="height"` | 高度默认 `100%`（prop 在 `:52-54`），页面可覆盖 |
| `:8` | `v-bind="$attrs"` | 父组件写在 `<JTable>` 上、但没被 props 声明的属性，原样传给内层 `el-table`（如 `v-loading`） |
| `:12` | `v-on="$listeners"` | 父组件监听的事件原样传给内层（如 `selection-change`） |
| `:14` | `hasC` 为 true 时加多选列 | 默认 `false`（`:44-47`），需要批量操作时才开 |
| `:15-21` | `hasNO` 为 true 时加「序号」列 | 默认 `true`（`:39-42`），省掉每个列表页手写序号列 |
| `:22` | `<slot />` | 页面写在 `<JTable>...</JTable>` 里的 `<el-table-column>` 会落到这个位置 |

> 透传的本质：页面写 `<JTable :data="list" @selection-change="xxx">`，`data` 走 props，`selection-change` 走 `$listeners`，其余属性走 `$attrs`，所以用起来几乎和原生 `<el-table>` 一样。

### 4.7 动手验证：看字典请求、看 JTable 渲染

### 5.1 【字典从声明到显示】

### 5.3 【跨组件通信】`$EventBus` 用在什么时候

`main.js:85` 挂了 `this.$EventBus = new Vue()`。当**两个没有父子关系的组件**要通信时用它，比如「某个子页操作完，通知另一个子页刷新」。用法：

```js
// 发送方
this.$EventBus.$emit('refreshList')
// 接收方
mounted() { this.$EventBus.$on('refreshList', this.getList) }
```

本项目的在线文档编辑页（第 8 章）用它较多。

## 六、面试高频问题

**Q1：你们前端为什么有很多组件不用 import 就能用？**
A：在 `main.js:93-106` 用 `Vue.component()` 全局注册了（JTable、Pagination、DictTag、FileUpload…），全局组件在任何页面直接用标签名。工具方法（`$modal`/`$auth`/`$cache`）是用 `Vue.prototype` 挂的（`plugins/index.js`）。好处是页面代码干净，代价是 IDE 不提示、排查要回 main.js。

**Q2：什么是字典？为什么要用字典？**
A：字典是「编码↔中文」的映射表，存在后端数据库。比如合同状态 `0/3/6` 对应「拟定中/审批中/履行中」（界面文案以字典配置为准）。用它有两个好处：① 前端不用在每个页面重复写映射；② 措辞要改时改后台数据即可，不改代码、不发版。这是「能让运营配的别写死」。

**Q3：字典是怎么按需加载的？**
A：`zxcm-ui/src/utils/dict/index.js:6-32` 用 Vue **mixin** 给每个组件混入逻辑，但**先判断组件有没有声明 `dicts`**（`:8-10`）——没声明的直接 `return {}`，不初始化、不请求。只有 `dicts: [...]` 声明了的页面才去 `GET /system/dict/data/type/{type}` 拉字典。这就是按需加载。

**Q4：`dict.type` 和 `dict.label` 有什么区别？**
A：`dict.type.类型名` 是**数组**（`[{label,value,...}]`），配 `<DictTag>` 用；`dict.label.类型名` 是**对象**（`{'0':'草稿'}`），需要直接取中文时用（`utils/dict/Dict.js:19-20`）。

**Q5：`<JTable>` 和 Element 的 `<el-table>` 什么关系？为什么要封装？**
A：`JTable` 内部包了 `el-table`（`components/JTable/index.vue:2`），用 `v-bind="$attrs"` `v-on="$listeners"` 把属性和事件透传给内部，所以用法和 `el-table` 一样。它额外做了：默认加序号列、可选多选列、以及 `doLayout()`（`:82-88`）用 `setTimeout+nextTick` 重算窗口尺寸来修 Element 表格列宽不刷新的 bug。封装它是因为本项目 90% 列表页结构相同，避免重复。

**Q6：`$attrs` 和 `$listeners` 是干啥的？**
A：Vue 2 里，父组件传给子组件的**非 props 属性**会在 `$attrs`，**事件监听**会在 `$listeners`。封装组件时用 `v-bind="$attrs"` + `v-on="$listeners"` 就能「透传」——子组件不用声明父组件可能传的每一个属性和事件，做到「和原生组件用法兼容」。这是高阶封装的必备技巧。

**追问：那 `v-bind="$attrs"` 和一个个写 `:prop` 有什么区别？**
A：props 是子组件**声明过、要自己处理**的属性；`$attrs` 是父组件传了但子组件**没声明**的那部分。前者同名属性不会再进 `$attrs`，后者可以一次性透传给内层组件。

**Q7：`this.$modal` 和 `this.$message`（Element）有什么区别？**
A：`this.$modal` 是本项目对 Element 的 `Message`/`MessageBox`/`Notification` 的**二次封装**（`zxcm-ui/src/plugins/modal.js:6-84`）。好处是：统一了文案格式、统一了错误信息的清洗（`normalizeUserMessage`，防止把后端堆栈暴露给用户）、把「提示」和「确认框」收在一处。直接用 Element 的 `this.$message` 也能用，但不统一。

**Q8：`$EventBus` 是干啥的，什么时候用？**
A：`new Vue()` 当事件总线（`main.js:85`），用于**非父子组件通信**。`A.$EventBus.$emit('事件名', 数据)`，`B.$EventBus.$on('事件名', 回调)`。本项目在在线编辑等场景用。但现在更推荐用 Vuex 管状态，EventBus 适合「一次性通知」。

**Q9：一个标准列表页有哪些部分？**
A：五块——① 搜索区（el-form inline）② 工具条（新增/导出按钮 + RightToolbar）③ 表格（JTable + 列定义）④ 分页（Pagination）⑤ 新增/编辑弹窗（el-dialog）。数据流：`created → getList → 赋值 tableData/total`；动作：`handleAdd/Update/Delete → api → $modal 提示 → getList 刷新`。

**Q10：`this.resetForm` 是什么？**
A：`utils/ruoyi.js` 里的工具函数，配合 `main.js:77` 挂到原型上。实现就是 `this.$refs[refName].resetFields()`（`zxcm-ui/src/utils/ruoyi.js:53-57`）：把 `el-form` 里带 `prop` 的字段重置到初始值、清掉校验状态；表单外的数据它不管。页面里 `resetQuery` 常调它。

### 6.1 本章答辩卡（3 组追问级问答）

**追问 1：字典是异步加载的，页面 `created` 里能直接用 `dict.type.xxx` 吗？**
10 秒答案：不能保证。mixin 的 `created` 只是把请求发出去，响应回来前 `dict.type.xxx` 还是空数组。需要「字典到了再做」的逻辑要放在 `onDictReady` 回调或监听 `dictReady` 事件里。
证据：`zxcm-ui/src/utils/dict/index.js:17-31`、`zxcm-ui/src/utils/dict/Dict.js:76-79`。

**追问 2：`JTable` 对 `data` 做了深度监听，会不会有性能问题？**
10 秒答案：会有代价。列表数据一变就触发 `doLayout()`，而它是 `setTimeout 100ms + nextTick` 后重算表格布局；数据量特别大时这是额外开销。本项目页面列表一般分页，所以可接受。
证据：`zxcm-ui/src/components/JTable/index.vue:65-88`（`deep: true` 与 `doLayout` 实现）。

**追问 3：`DictTag` 的 `value` 为什么允许传数组？**
10 秒答案：`values` 计算属性会把单值统一转成数组，再判断「字典项的值是否在数组里」。所以传数组时就可能同时渲染多个标签，适合「多个状态/类型并存」的列。
证据：`zxcm-ui/src/components/DictTag/index.vue:3-4`（`v-for` + `values.includes`）、`:37-46`（`value` 的 prop 类型和 `values` 计算属性）。

## 七、选型对比

### 7.1 全局注册组件 vs 局部注册

| | 全局注册（本项目自研组件） | 局部 import |
|---|---|---|
| 页面代码 | 干净，标签直接用 | 每个页面一堆 import |
| Tree-shaking | ❌ 无法按需删除 | ✅ 没用到的会被打包剔除 |
| IDE 提示 | ❌ 无跳转 | ✅ 有 |
| 适用 | 高频通用组件 | 低频、页面专用 |

**结论**：高频组件全局注册省事，低频的别全局注册（否则打包体积白增、且无法 tree-shaking）。本项目就是这么权衡的。

### 7.2 字典（后端配置）vs 前端写死映射

| | 字典机制（本项目） | 前端硬编码 `{'0':'草稿'}` |
|---|---|---|
| 改措辞 | 后台改，即时生效 | 改代码 + 重新发版 |
| 复用 | 全站共用一份 | 每页各写一份 |
| 复杂度 | 要拉接口、要 mixin | 简单 |
| 适用 | 状态、类型等**业务配置** | 极少变的**技术常量** |

**结论**：业务语义的「状态/类型」用字典（会变、要复用）；纯技术的常量（如 HTTP 方法名）硬编码即可。**判断标准：这个值会不会被运营改？会 → 字典。**

### 7.3 `JTable` 封装 vs 用 Element 原生

| | `<JTable>`（本项目） | 原生 `<el-table>` |
|---|---|---|
| 序号列 | 自带 | 每次手动写 `<el-table-column type="index">` |
| 列宽 bug | 内置 `doLayout` 修复 | 要自己处理 |
| 透传能力 | `$attrs/$listeners` 全透传 | — |
| 适用 | 业务列表页 | 弹窗小表、树表、特殊表格 |

**结论**：常规业务列表用 `JTable`，**特殊表格（如合同类型的树表）直接用 `el-table`**——本项目就是这么混用的（见第 4 章合同类型页）。

## 本章小结

- 前端有大量「约定」：全局组件、全局方法、字典机制。读代码卡住先回头看 `main.js` + `plugins/`。
- **字典机制**：`dicts:['类型名']` 声明 → mixin 按需 `GET /system/dict/data/type/{type}` → `dict.type.xxx`（数组）配 `<DictTag>`，`dict.label.xxx`（对象）取中文。改措辞改后端。
- **`JTable`**：包 `el-table` + 序号列 + `$attrs/$listeners` 透传 + `doLayout` 修列宽。本项目自研亮点。
- **标准 CRUD 骨架**：搜索 + 工具条 + 表格 + 分页 + 弹窗；`created→getList`，`handleXxx→api→$modal→getList`。后面每章都是它的变体。
- `plugins/` 提供 `$modal`（提示/确认）、`$auth`（权限）、`$cache`（缓存）、`$EventBus`（跨组件通信）。
