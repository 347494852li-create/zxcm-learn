# 前端精读五篇 · 怎么用（先看这一页）

> **你的前端目标**：不是手写前端，是**看得懂调用链**——看到一个菜单/按钮，能顺着找到它的 `.vue` 文件和它调的接口，能说清一次点击怎么走到后端。
>
> **这一页的定位**：它是《前端重塑版》的**精读层导航**。主线第 0~10 章按「机制 + 页面族」讲；这里的五篇按「地图 → 语法 → 带路 → 放大镜」陪你读真实代码。两边配合使用，不重复替代。

## 1. 默认顺序：精读 1 → 精读 2 → 精读 3 → 精读 4

第一次接触前端，就按编号读。但每篇的读法不一样：

| 步 | 读哪篇 | 怎么读 | 参考耗时 |
|---|---|---|---|
| 1 | **精读 1 工程结构** | **通读**。先建立「文件都在哪」的地图；四条关键约定（菜单→页面 / 页面→接口 / `request.js` / `permission.js`）要记住 | ~30 分钟 |
| 2 | **精读 2 代码导读** | **读到 §5 之前就够**（§0–§4：`.vue` 骨架、Vue 概念、模板语法、`el-` 组件）。**§5 起是逐行拆解，当字典用，别硬背** | ~1 小时 |
| 3 | **精读 3 代码走读** | **跟着代码一条路走完**。开着编辑器，它说打开哪个文件你就打开哪个；卡住就回精读 2 查这一行 | ~1.5 小时 |
| 4 | **精读 4 一次点击** | **选读**。想彻底搞懂「请求怎么走到后端」时读，跟着 11 跳看一遍 | ~40 分钟 |

> ⏱ 全程约 **3.5–4 小时**（大致参考，别掐表）。**读完一篇就能停**，下次接着下一篇。

## 4. 先混个眼熟：这 8 个词五篇里天天出现

不用背。它们第一次出现时，各篇都会再解释一遍。

| 名词 | 大白话 |
|---|---|
| **`.vue` 文件** | 一个页面的全部：长什么样（`<template>`）+ 什么逻辑（`<script>`）+ 什么样式（`<style>`） |
| **组件** | 一段能反复用的界面积木（按钮、表格、弹窗）；`el-` 开头的是 Element UI 提供的现成积木 |
| **路由 / `router`** | 「哪条网址显示哪个页面」的对照表 |
| **`store`（Vuex）** | 多个页面共用的数据仓库（比如「当前登录用户是谁」） |
| **`api/*.js`** | 一组「只负责发请求」的函数声明——页面要调后端就 `import` 它 |
| **`request.js`** | 所有请求的**唯一出口**（统一加 token、统一处理返回） |
| **`<template>` / `<script>` / `<style>`** | 一个 `.vue` 的三段：界面 / 逻辑 / 样式 |
| **代理转发（`/dev-api`）** | 开发时，前端先把请求发给「自己人」（前端开发服务器），由它转交后端——浏览器全程不知道有这一步 |

> 📌 **讲解原则**：每个词都**先用前端自己的话讲清，再配本项目真实代码**举例。**不拿后端的类去套**。

## 5. 读完怎么自测（不看书，能不能做到）

1. 随便指一个左侧菜单，你能在 30 秒内说出：它的页面文件在哪、它调的接口函数在哪、后端 Controller 大概在哪个模块。
2. 随便打开一个 `.vue`，你能分清哪些是 `data`、哪些是 `methods`、哪些是全局注册的组件/方法。
3. 你能从「点新增 → 填表 → 确定」讲清：参数怎么收集、怎么校验、怎么发请求、代理怎么改写、后端怎么接。

三条都能做到，说明精读篇已经「读进手里」了；做不到就回到对应那一篇，不用从头再来。
