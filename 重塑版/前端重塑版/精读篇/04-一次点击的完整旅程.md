## 0. 全景：这一趟一共 11 跳

```
【浏览器里】用户在弹窗点「确 定」
      │  ①  @click="submitForm"                      ← 模板
      ▼
【.vue 页面】submitForm()                             ← 页面脚本
      │  ②  this.$refs['form'].validate(...)         前端校验，不过就停
      │  ③  this.form.contacts = JSON.stringify(...) 两个 JSON 列先序列化
      │  ④  addSigningSubject(this.form)             调 api 函数
      ▼
【api/conf/signingSubject.js】addSigningSubject()
      │  ⑤  return request({ url:'/conf/signingSubject', method:'post', data })
      │       —— 注意：这里**只是"声明要发什么请求"**，一个字节都没发出去
      ▼
【utils/request.js】axios 实例（所有请求的唯一出口）
      │  ⑥  请求拦截器：config.headers['token'] = 'Bearer ...'
      │  ⑦  baseURL = '/dev-api'  →  真正要请求的地址 = /dev-api/conf/signingSubject
      ▼
【浏览器】把相对地址补全成完整 URL 发出去
      │  ⑧  POST http://localhost/dev-api/conf/signingSubject      ← ★ Network 里看到的就是这个
      ▼
【webpack-dev-server】代理（跑在你机器上的一个 Node 进程）
      │  ⑨  匹配到 '/dev-api' → target 改成 http://localhost:8080
      │  ⑩  pathRewrite 把 '/dev-api' 删掉
      ▼
【后端 Tomcat :8080】收到 POST /conf/signingSubject
      │  ⑪  Filter 链 → DispatcherServlet → 拦截器链（Sa-Token 登录 & 权限）→ Controller
      ▼  Controller → Service → Mapper → 【MySQL】
      ▲  返回 { code:200, msg:"操作成功" }
      ▼
【utils/request.js】响应拦截器：code===200 → 原样返回
      ▼
【.vue 页面】.then(...)：弹「新增成功」→ 关弹窗 → getList() 重拉列表 → 表格自动刷新
```

**先记住两个"分水岭"**：

1. **⑤ 之前，一个字节都没发出去**。`api/*.js` 只是"描述这次要发什么请求"的**声明**，真正发请求的是 `request.js` 里的 axios。
2. **⑧ 和 ⑪ 是两台不同的机器（进程）**。⑧ 的 host 是**前端开发服务器**（`localhost:80`），⑪ 才是后端（`localhost:8080`）。中间那一步（⑨⑩）就是**代理转发**——浏览器完全不知道有这一步。

```js
service.interceptors.request.use(config => {
  const isToken = (config.headers || {}).isToken === false
  if (getToken() && !isToken) {
    config.headers['token'] = 'Bearer ' + getToken()   // ★ 自动带上 token，页面里从不用手写
  }
  // get请求把 params 拼到 URL 后面（本项目 POST 用不到这段）
  if (config.method === 'get' && config.params) {
    let url = config.url + '?' + tansParams(config.params);
    url = url.slice(0, -1);
    config.params = {};
    config.url = url;
  }
  return config
}, error => { return Promise.reject(error) })
```

# 中篇 · 代理转发（⑨⑩）—— 你最想看的一段

## 为什么要多这一层？

前端页面由 `http://localhost`（**80**）提供，后端在 `http://localhost:8080`。站在浏览器角度，**端口不同 = 不同源**，JS 直接请求 8080 会被**同源策略**拦下（除非后端专门配 CORS 头）。

所以前端**只请求自己这个源**，用一个特殊前缀 `/dev-api` 打标记，剩下的交给**开发服务器（一个 Node 进程）在服务端替它转**。

## 转发规则的定义

**文件**：`zxcm-ui/vue.config.js:31-46`

```js
devServer: {
  host: '0.0.0.0',
  port: port,                      // 12 行：process.env.port || ... || 80
  open: true,
  proxy: {
    [process.env.VUE_APP_BASE_API]: {          // ← 键 = '/dev-api'
      target: `http://localhost:8080`,         // ← 转到哪
      changeOrigin: true,                      // ← 转发时把 Host 头改成 target 的
      pathRewrite: {
        ['^' + process.env.VUE_APP_BASE_API]: ''   // ← 把开头的 /dev-api 换成空串 = 删掉
      }
    }
  },
  disableHostCheck: true
},
```

## 一次改写，对照着看

| | 值 |
|---|---|
| 浏览器发出的 | `POST http://localhost` **`/dev-api`** `/conf/signingSubject` |
| 匹配代理键 `'/dev-api'` | ✅ 命中（路径以它开头） |
| 换 `target` | host 换成 `http://localhost:8080` |
| `pathRewrite` 删前缀 | `/dev-api/conf/signingSubject` → `/conf/signingSubject` |
| **后端最终收到** | `POST http://localhost:8080/conf/signingSubject` |

> 🧠 **为什么非要把 `/dev-api` 删掉**：后端根本没有 `/dev-api` 这个路径。
> 它纯粹是前端打的"标记"——**凡是以它开头的请求，就是"这条要麻烦开发服务器替我转出去"**。
> 删掉之后，剩下的 `/conf/signingSubject` 正好对上后端 Controller 的 `@RequestMapping("/conf/signingSubject")`。

## 出问题时，怎么一眼分清是谁的锅

| 你看到的 | 是谁的问题 |
|---|---|
| Request URL 是 `localhost/dev-api/...` | **正常**，这就是转发入口 |
| 请求**一直转圈 / `net::ERR_EMPTY_RESPONSE`**，`npm run dev` 终端刷 `[HPM] ... (ECONNREFUSED)` | **后端没起**（代理转不过去）。⚠️ **这不是 404** |
| 返回 **404** | 后端起了，但**没这个接口**（Controller 没拷 / url 拼错） |

> 技术细节：本项目的代理是 `http-proxy-middleware 0.19.1`（`@vue/cli-service 4.4.6` 带的），它的默认错误处理**只打日志、不回响应**（源码 `node_modules/http-proxy-middleware/lib/index.js:35` `proxy.on('error', logError)`），所以后端没起时请求是"挂住"，不会给你一个干净的 404。

# 下篇 · 后端这半程（⑪ 往后）

## ⑪-1 请求进了哪：Tomcat → Filter → DispatcherServlet → 拦截器

后端是内嵌 Tomcat，监听 **8080**（`ruoyi-admin/src/main/resources/application.yml:30`）。一个请求进来，大致穿过这几道关：

| 关卡 | 谁 | 干什么 | 在哪配 |
|---|---|---|---|
| Filter 1 | `XssFilter` | 防 XSS | `FilterConfig.java:44-50`（最高优先级）|
| Filter 2 | `RepeatableFilter` | 让 body 能被重复读（`@RequestBody` + 日志都要读）| `FilterConfig.java:59-64` |
| DispatcherServlet | Spring MVC | 按 url 找到该由哪个 Controller 处理 | 自动 |
| 拦截器 1 | `PlusWebInvokeTimeInterceptor` | 记请求耗时 | `ResourcesConfig.java:40` |
| 拦截器 2 | `SaRouteInterceptor` | **登录校验**：不在白名单的路径，必须有有效 token | `SaTokenConfig.java:55-78` |
| 拦截器 3 | `SaAnnotationInterceptor` | **处理 `@SaCheckPermission` 注解**：查权限码 | `SaTokenConfig.java:79` |

> 🧠 注意 `SaTokenConfig.java:61` 那句 `.notMatch(securityProperties.getExcludes())`：
> **白名单里的路径（登录、验证码、注册）不校验登录**，其余全要。所以「哪些接口不用登录」是**配置**说了算，不是代码里到处写 `if`。

## ⑪-2 Controller：参数怎么"装"进来

**文件**：`zxcm-contract/.../conf/controller/TSigningSubjectController.java:72-77, 143-150`

```java
@Validated                                    // ← 让类里的校验注解生效
@Api(value = "签约主体控制器", tags = {"签约主体管理"})
@RequiredArgsConstructor
@RestController
@RequestMapping("/conf/signingSubject")       // ★ 和前端 url 对上（注意大小写！）
public class TSigningSubjectController extends BaseController {

    private final ITSigningSubjectService iTSigningSubjectService;

    @ApiOperation("新增签约主体")
    @SaCheckPermission("conf:signingSubject:add")     // ← 权限码，由上面那个注解拦截器查
    @Log(title = "签约主体", businessType = BusinessType.INSERT)   // ← 写 sys_oper_log
    @RepeatSubmit()                                    // ← 防重复提交（Redis 里记一次）
    @PostMapping()                                     // ← 对应前端的 method:'post'
    public R<Void> add(@Validated(AddGroup.class) @RequestBody TSigningSubjectBo bo) {
        return toAjax(iTSigningSubjectService.insertByBo(bo) ? 1 : 0);
    }
}
```

**三件事在这里同时发生**：

1. **`@RequestBody` 把 JSON body 反序列化成 `TSigningSubjectBo`**（Jackson 按字段名匹配）。
   前端 body 里的 `signingSubjectName` / `uscc` / `contacts`…… 会被塞进 Bo 的**同名字段**。
   ⚠️ **前端字段名必须和 Bo 字段名一致**，否则那个字段就是 `null`（这是本项目最常见的"参数丢了"原因）。

2. **`@Validated(AddGroup.class)` 按分组校验**。
   同一个 Bo，新增和修改用两套规则（**文件**：`TSigningSubjectBo.java`）：

   ```java
   public class TSigningSubjectBo extends BaseEntity {
       @NotBlank(message = "主键不能为空", groups = {EditGroup.class})        // 只有"改"才要求 id
       private String id;

       @NotBlank(message = "签约主体名称不能为空", groups = {AddGroup.class, EditGroup.class})
       private String signingSubjectName;

       @NotBlank(message = "统一社会信用代码不能为空", groups = {AddGroup.class, EditGroup.class})
       private String uscc;
   }
   ```

   > 这就是「同一个 Bo、两套规则」的做法：Controller 上 `add` 传 `AddGroup`、`edit` 传 `EditGroup`。
   > **校验不过 → Spring 抛异常 → 全局异常处理器返回 `{code:500, msg:"签约主体名称不能为空"}`**。
   >
   > ⚠️ **顺手读出一个真坑**：`signingSubjectCode`（主体编号）的 `@NotBlank` 是**被注释掉的**（`TSigningSubjectBo.java:52-55`）——
   > 也就是**前端 `rules` 里必填、后端根本不校验**。用 `curl` / `doc.html` 绕过前端就能建一条没有编号的数据。
   > 「**前端校验只是体验，后端校验才是真约束**」这句话，这里就是个活例子。

3. **权限、日志、防重 都是注解，不是手写代码**。`@SaCheckPermission` 没权限会直接抛 `NotPermissionException`。

## ⑪-3 Service：真正的业务逻辑

**文件**：`TSigningSubjectServiceImpl.java:132-145`

```java
@Override
public Boolean insertByBo(TSigningSubjectBo bo) {
    TSigningSubject add = BeanUtil.toBean(bo, TSigningSubject.class);  // Bo → Entity
    if (add.getForever() == 1) {
        add.setBusinessEndDate(null);          // 长期有效 → 清掉结束日期
    }
    validEntityBeforeSave(add);                // 入库前的业务校验
    add.setCreateBy("admin");                  // ⚠️ 硬编码"admin"（答案册的技术债）
    add.setUpdateBy("admin");
    boolean flag = baseMapper.insert(add) > 0;  // ★ 真正写库
    if (flag) {
        bo.setId(add.getId());                  // 把自增/雪花 id 回填给 Bo
    }
    return flag;
}
```

> 🧠 两个"读到就该记住"的点：
> - `BeanUtil.toBean`：**Bo（面向接口的入参）→ Entity（面向数据库的表对象）**。两套类分开，是为了"接口字段"和"表字段"能各改各的。
> - `setCreateBy("admin")` 是硬编码 —— 正确写法应该是 `LoginHelper.getUsername()`。**回答面试时可以主动说这是技术债**，比被问倒好。

## ⑪-4 Mapper → MySQL：SQL 在哪

**Entity**：`conf/domain/TSigningSubject.java:36` → `@TableName("conf_signing_subject")`
**Mapper**：`conf/mapper/TSigningSubjectMapper.java` 继承 `BaseMapperPlus`，**没有 XML**。

`baseMapper.insert(add)` 由 MyBatis-Plus **生成** INSERT，形状大致是：

```sql
INSERT INTO conf_signing_subject
  (signing_subject_name, uscc, business_status, contacts, bank_json,
   create_by, update_by, del_flag, tenant_id, ...)
VALUES
  ('测试主体', '91110...', '1', '[{"...":"..."}]', '[]',
   'admin', 'admin', '0', '00000000', ...)
```

> 🧠 **为什么没有 XML**：MyBatis-Plus 的 `BaseMapper` 自带 `insert/updateById/selectById` 等，条件是**用 Java 代码拼**（`LambdaQueryWrapper`，见 `buildQueryWrapper`）。
> 只有少数复杂 SQL（比如报表）才写 XML 或 `@Select`。**代价**：MP 全靠"字段名对得上"——Entity 字段名 ↔ 表列名映射错了，SQL 就错。

## 返回：一个 `R` 对象怎么变成页面上的"新增成功"

Controller 里 `toAjax(...)` 把 boolean 包成统一响应体：

```
HTTP 200
{ "code": 200, "msg": "操作成功", "data": null }
```

**回到前端**：`utils/request.js:71-111`（响应拦截器）

```js
service.interceptors.response.use(res => {
    const code = res.data.code || 200;
    ...
    if (code === 401) { ...弹"重新登录"... }
    else if (code === 500) { Message({ message: msg, type: 'error' }); return Promise.reject(...) }
    else if (code !== 200) { Notification.error({ title: msg }); return Promise.reject('error') }
    else {
      return res.data          // ★ code===200：把 {code,msg,data} 整个交给页面
    }
  },
  error => { ...Network Error / timeout / 4xx 5xx 统一弹错... }
)
```

> 🧠 **`code !== 200` 不用每个页面自己判** —— 拦截器全包了。页面里只写"成功之后干什么"。

最后回到 `index.vue:821-826` 的 `.then`：

```
弹「新增成功」→ this.open = false（关弹窗）→ this.getList()（重拉列表）→ 表格自动重画
```

> **前端不会"自动同步数据库最新数据"**，这就是为什么每个 `submitForm` 末尾都要手动 `this.getList()`。

## 本章答辩卡（追问级）

**卡 1：开发环境为什么要多一层 `/dev-api` 代理？**

**10 秒答案**：因为前端 80、后端 8080，端口不同就是跨源，浏览器会按同源策略拦截。让前端只请求同源的 `/dev-api`，再由 webpack-dev-server 在服务端把前缀去掉、转发到 8080，浏览器就看不到跨源这一步；生产环境则由 Nginx 做同样的转发。

**证据**：`zxcm-ui/vue.config.js:31-46`、`zxcm-ui/src/utils/request.js:19-24`。

**卡 2：`changeOrigin: true` 到底改了什么？**

**10 秒答案**：它改的是转发请求的 `Host` 请求头，让后端以为是直接访问自己的域名/端口。很多后端/虚拟主机按 `Host` 做路由或校验，不开它容易出现 404 或重定向异常；它不改路径，路径由 `pathRewrite` 负责。

**证据**：`zxcm-ui/vue.config.js:37-43`。

**卡 3：为什么提交前要把 `contacts` / `bankInfos` 先 `JSON.stringify`？**

**10 秒答案**：后端 BO 里这两个字段是字符串/JSON 列，不是数组对象。前端表单里是数组，直接发过去类型对不上，后端反序列化会失败；先序列化成字符串，后端再按 JSON 存进表里的 `json` 列。

**证据**：`zxcm-ui/src/views/conf/signingSubject/index.vue` 的 `submitForm`（`JSON.stringify` 两处）、后端 `TSigningSubjectBo.java` 对应字段。
