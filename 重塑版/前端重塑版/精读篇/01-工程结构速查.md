## 0. 前端工程由哪几样东西组成

看目录之前，先把「一个前端工程到底由什么构成」说清楚。整个 `zxcm-ui` 主要就是
**页面 + 接口声明 + 一堆胶水**，后面所有目录都能对到下面这张表：

| # | 东西 | 它实际是什么（用前端自己的话说） | 本项目里的真实例子 |
|---|---|---|---|
| 1 | **页面 · `.vue` 文件** | 一个 `.vue` 文件 = 一个页面的**全部**：结构（长什么样，`<template>`）+ 逻辑（点按钮干什么，`<script>`）+ 样式（`<style>`）。浏览器打开某个菜单，加载的就是这一个文件 | `views/system/user/index.vue` 就是「用户管理」页 |
| 2 | **接口声明 · `api/*.js`** | 一个 js 文件里写一组函数，每个函数**只干一件事**：把请求发到某个 URL，然后把响应交回来。页面要调后端，就 `import` 这些函数来调 | `api/system/user.js` 里的 `listUser()` 发 `GET /system/user/list` |
| 3 | **`@` 路径别名** | 写 `import` 时的简写：`@` 就代表 `src/`。作用是让路径短一点、不受当前文件层级影响 | `import request from '@/utils/request'` 就是 `src/utils/request.js` |

这三样之外剩下的都是**胶水**：`main.js`（启动）、`router/`（哪条地址显示哪个 `.vue`）、
`store/`（多页面共用的数据）、`utils/`（公共工具）。它们在第 2 节起的目录说明里逐个讲。

整个前端的分工就一句话：

```
后端给「数据 + 菜单」 → 前端把菜单变成「左侧导航」，把数据填进「表格」
```

前端**不决定你有什么权限**。`getRouters` 返回什么菜单、`getInfo` 返回什么权限码，

| `package-lock.json` | 锁定每个依赖的确切版本 | **别手改** |

## 3. ⭐ 四条关键约定（看懂这个，前端就不再是黑盒）

### 约定 1：菜单 → 页面，靠一个字符串

后端 `sys_menu` 表里有一列 `COMPONENT`，它的值**就是 `views/` 下的文件路径**。

实测（数据库查出来的真实数据）：

| 菜单名（`MENU_NAME`）| 路由（`PATH`）| **前端文件（`COMPONENT`）** |
|---|---|---|
| 用户管理 | `user` | `system/user/index` |
| 角色管理 | `role` | `system/role/index` |
| 菜单管理 | `menu` | `system/menu/index` |
| 部门管理 | `dept` | `system/dept/index` |
| 字典管理 | `dict` | `system/dict/index` |
| 参数设置 | `config` | `system/config/index` |
| 在线用户 | `online` | `monitor/online/index` |
| 操作日志 | `operlog` | `monitor/operlog/index` |
| 代码生成 | `gen` | `tool/gen/index` |
| 表单构建 | `build` | `tool/build/index` |

→ `system/user/index` 实际对应的文件是：

```
src/views/system/user/index.vue
        └──────┬──────┘
   就是 sys_menu.COMPONENT 的值
```

**转换发生在哪**？`src/store/modules/permission.js:124-131`：

```js
export const loadView = (view) => {
  if (process.env.NODE_ENV === 'development') {
    return (resolve) => require([`@/views/${view}`], resolve)   // ← 字符串拼成真实路径
  } else {
    return () => import(`@/views/${view}`)
  }
}
```

`@/` 就是 `src/`，所以 `@/views/system/user/index` → `src/views/system/user/index.vue`。

> **所以「新增一个页面」在后端要做的就是**：在 `sys_menu` 插一条记录，
> `COMPONENT` 填 `views/` 下的相对路径（不含 `.vue`），前端**一行代码都不用改**。

`COMPONENT` 有三个**保留字**（不是文件路径，是特殊组件），见 `permission.js:61-72`：

| 值 | 含义 |
|---|---|
| `Layout` | 带侧边栏 + 顶栏的整体框架（一级目录用）|
| `ParentView` | 只是分组容器，本身没有页面（二级目录用）|
| `InnerLink` | 内嵌一个外部网页（iframe）|


### 约定 2：页面 → 接口，是 `import` 一份 api 清单

一个典型页面（以 `views/system/user/index.vue` 为例）的结构：

```
<template>   ← HTML 结构（表格、按钮、弹窗）
<script>     ← JS 逻辑：import 接口 → data 里存数据 → 方法里调接口
<style>      ← 样式
```

`<script>` 顶部会有：

```js
import { listUser, getUser, addUser, updateUser, delUser } from "@/api/system/user"
```

而 `src/api/system/user.js` 里就是**纯接口声明**，长这样：

```js
import request from '@/utils/request'

export function listUser(query) {
  return request({ url: '/system/user/list', method: 'get', params: query })
}
```

> **一句话**：`api/*.js` 是「请求声明」的集中地——页面自己**不拼 URL**，而是从这儿 import 函数来调。
> 本项目约定**一个后端模块对应一个 `api/*.js`**：后端有几个接口，这儿就写几个函数，
> `url` 和请求方法照抄 Controller。注意这是**项目约定**（为了两边好对照），不是语法强制。

`api/` 目录**按后端模块划分**，和后端模块同名：

| `src/api/` 下的目录 | 对应后端 |
|---|---|
| `system/` | `ruoyi-base` 的系统管理 |
| `conf/` | `zxcm-contract` 的合同基础配置（签约主体、编号规则、合同类型、合作方）|
| `contract/` | `zxcm-contract` 的合同（草拟、审签、文件）|
| `template/` | 模板管理 |
| `activiti/` | Activiti 工作流 |
| `monitor/` | 系统监控 |
| `tool/` | 代码生成、表单构建 |
| `notify/` / `qywx/` / `syncData/` | 通知、企业微信、数据同步 |

> ➡️ **这条约定的落点在后端 Controller**：`api/` 里的每个函数，后端都有一个 `@RequestMapping` 方法接它。
> 哪个前端页面 → 对应哪个后端模块 → 该读后端卷哪一章，**本文第 8 节有一张完整映射表**；一条完整的「页面 → 接口 → Service → 数据库」链路，[前端代码走读 · 走读 ③](03-四条链路走读.md) 逐行走过一遍。

### 约定 3：`utils/request.js` 是所有请求的必经之路

`src/utils/request.js` 用 axios 建了一个**统一的请求实例**，页面里所有接口都走它。它做了 4 件大事：

| 位置 | 干了什么 | 你要知道的 |
|---|---|---|
| `:21` | `baseURL = process.env.VUE_APP_BASE_API` | 所以请求实际发往 `/dev-api/xxx`，被 `vue.config.js` 的代理转发到 `localhost:8080/xxx` |
| `:80-97` | **响应拦截器**：`code === 401` → 弹「登录状态已过期」→ 登出 | 会话过期时的那个弹窗在这 |
| `:98-111` | `code === 500` 弹红条错误；`code !== 200` 弹通知 | 统一错误处理，页面里不用每处都写 try/catch |

还有两个小机制：

- `:29` / `:42-64`：**防重复提交**。1 秒内相同 URL + 相同参数视为重复，直接 reject（`headers.repeatSubmit === false` 可关掉）
- `:36-41`：GET 请求的参数会被拼成 query string

> **调试技巧**：页面上某个请求没带 token 或报 401，先看这个文件，不用去翻具体页面。

Token 存在哪？`src/utils/auth.js`：

```js
const TokenKey = 'Admin-Token'
export function getToken() { return Cookies.get(TokenKey) }     // token 存在 Cookie
```

这就是项目搭起来后第一次登录验收要看的「Application → Cookies 里有 `Admin-Token`」。

### 约定 4：`permission.js` 决定「能不能进这个页面」

`src/permission.js` 是一个**全局前置守卫**（`router.beforeEach`），每次切路由都会跑一遍。逻辑：

```
访问任意页面
   │
   ├─ 有 token？
   │    ├─ 是 → 拉过用户信息了吗？（store.getters.roles 是否为空）
   │    │        ├─ 没拉 → GetInfo（拉用户+权限）→ GenerateRoutes（拉菜单变路由）→ 放行
   │    │        └─ 拉过 → 直接放行
   │    └─ 否 → 在免登录白名单里吗？
   │             ├─ 是（/login /register …）→ 放行
   │             └─ 否 → 踢回 /login
```


| | 前端 `permission.js` | 后端 Sa-Token 拦截器 |
|---|---|---|
| 拦什么 | 页面级的**跳转**（不让没权限的人进页面）| 接口级的**调用**（不让没权限的人调 API）|
| 防谁 | 防误操作、防手敲 URL | **真正的安全边界** |
| 能绕过吗 | **能**（改前端代码、直接 curl 接口）| 不能 |

> ⚠️ **面试常考**：前端路由守卫**不是安全措施**，只是体验优化。
> 真正的权限在后端。前端把某个菜单藏起来，不代表接口就安全了——
> 所以后端第 1 章起，每个 Controller 方法都要有 `@SaCheckPermission`。

同步地看一眼（`:12`）——白名单里是 `/login`、`/register`、`/auth-redirect`、`/bind`、`/wxLogin`、`/wxCallback`，
和后端 `security.excludes` 是**两套独立的名单**，改一个不影响另一个。

## 4. `layout/`：页面外壳，菜单在这渲染

`src/layout/` 只有一个 `index.vue` 和一组 `components/`：

```
layout/
├── index.vue                 ← 整体布局：左菜单 + 上顶栏 + 内容区
└── components/
    ├── Sidebar/              ← ★ 左侧菜单栏（把 getRouters 的数据渲染成导航）
    ├── Navbar.vue            ← 顶栏（面包屑、全屏、头像下拉）
    ├── TagsView/             ← 页签栏（打开过的页面，像浏览器标签）
    ├── AppMain.vue           ← 内容区（<router-view> 就在这，页面真正显示的地方）
    ├── Settings/             ← 右侧主题设置抽屉
    └── InnerLink/            ← iframe 内嵌页
```

**左侧菜单为什么能显示出来**？
`store/modules/permission.js` 的 `GenerateRoutes` 把 `getRouters` 的结果处理后，
分别存进 `sidebarRouters`（给侧边栏）、`routes`（给路由表），
`Sidebar/` 组件读 `sidebarRouters` 渲染成菜单 DOM。

这就是项目搭起来后要验的第 4 条：「`getRouters` 返回的菜单树**被渲染成了左侧菜单**」——
接口返回 JSON 只证明后端通了，**渲不渲染得出来要靠 Vue**。

> **排错口诀**：接口有菜单数据但左侧空白 → 看 `Sidebar/` 和 `permission_routes`；
> 左侧有菜单但点进去 404 → 看 `sys_menu.COMPONENT` 填的值对不对、对应 `.vue` 文件存不存在。

## 5. `store/`：Vuex 全局状态（6 个模块）

前端没有 session，登录用户、权限、菜单都缓在内存里，这就是 Vuex。

| 模块 | 存什么 | 关键点 |
|---|---|---|
| `user.js` | token、用户信息、**roles**、**permissions** | `GetInfo` 把后端 `getInfo` 的返回存进来 |
| `permission.js` | **菜单路由**（`sidebarRouters` 等） | `GenerateRoutes` 生成 |
| `app.js` | 侧边栏折叠状态、设备类型、尺寸 | 界面状态 |
| `tagsView.js` | 打开过的页签、缓存过的页面 | 界面状态 |
| `settings.js` | 标题、主题色、公司配置 | 界面状态 |
| `notify.js` | 未读消息数 | 界面状态 |

`store/getters.js` 是**快捷访问层**，页面里用 `this.$store.getters.roles` 就能拿到。
注意里面这几个和后端一一对应：

| getter | 来自后端哪个接口 |
|---|---|
| `roles` / `permissions` | `getInfo` |
| `permission_routes` / `sidebarRouters` | `getRouters` |

> **面试点（《基座重塑版》第 2/3 章也讲过，这里能看到前端侧的证据）**：
> `roles` 和 `permissions` **只在登录后拉一次**（`permission.js:43` 判断 `roles.length === 0`）。
> 后端改了权限，前端不会自动知道——这就是「改权限要重新登录」在前端侧的原因。

## 6. `directive/`：`v-hasPermi` 是怎么把按钮藏起来的

`src/directive/permission/` 下三个文件：

| 文件 | 指令 | 行为 |
|---|---|---|
| `hasPermi.js` | `v-hasPermi="['system:user:add']"` | 有权限 → 显示；无权限 → **把这个元素从 DOM 移除** |
| `notHasPermi.js` | `v-not-hasPermi="[...]"` | 反过来 |
| `hasRole.js` | `v-hasRole="['admin']"` | 按角色判定 |

用法在页面里：

```html
<el-button v-hasPermi="['system:user:add']" @click="handleAdd">新增</el-button>
```

判定依据是 `store.getters.permissions`（来自后端 `getInfo` 的 `permissions` 数组）。
`plugins/auth.js` 提供 `hasPermi()` 判定函数。

> 这是项目搭起来后要验的第 4 件事之一：「`v-hasPermi` 指令**隐藏按钮**」——
> 需要浏览器真的执行指令钩子（DOM 操作），接口层验不了。

## 9. 操作指南：四个最常用的查法

### 查法 1：看到一个菜单，找它的前端文件

```sql
SELECT MENU_NAME, PATH, COMPONENT FROM sys_menu WHERE MENU_NAME = '用户管理';
-- COMPONENT = system/user/index
```
→ 打开 `src/views/system/user/index.vue`

### 查法 2：看到一个页面，找它调了哪些接口

打开 `views/xxx/index.vue`，看 `<script>` 顶部的 `import { ... } from "@/api/..."`，
再去 `src/api/...` 找对应的 `request({url, method})`。

或用一句话的办法：**直接在 `src/api/` 里全局搜 URL 片段**。

### 查法 3：看到一个按钮，找它的接口

页面里找 `@click="handleXxx"` → 跳到 `methods` 里的 `handleXxx()` → 看它调了哪个 api 函数。

### 查法 4：接口 404 / 401 了，去哪排查

| 现象 | 先看哪 |
|---|---|
| 请求 URL 不对（少了/多了前缀）| `vue.config.js` 的 proxy + `.env.development` 的 `VUE_APP_BASE_API` |
| 请求**转圈不返回** / `ERR_EMPTY_RESPONSE`，npm 终端刷 `ECONNREFUSED` | **后端没起**（代理转不过去）。**这不是 404**，详见 §12 第 4 条 |
| 没带 token | `utils/request.js:32-34` |
| 401 弹重登 | 正常行为，token 过期了 → 重新登录 |
| 404 | 后端 Controller 没有这个路径（**业务模块还没接入时，接口 404 属预期**）|

### 启动与打包

```bash
# 前提：PATH 前置（本机 node 装在 E:\nvm\v24.9.0）
$env:PATH = "E:\nvm\v24.9.0;$env:PATH"

cd E:/Develop/project/zxcm-learn/zxcm-ui
npm run dev          # 开发：起在 80 端口 → http://localhost
npm run build:prod   # 生产打包 → 产物在 dist/
```

## 11. 开发环境下，一个请求是怎么从前端走到后端的（速查）

> 完整机制 —— 7 步拆解 + 代理规则逐行 + 「一次改写」对照表 —— 在 **[精读 4 · 中篇「代理转发」](04-一次点击的完整旅程.md)**。
> 本文是「地图」，这里只留最该记住的结论，**不重复展开**。

浏览器里那条 `http://localhost/dev-api/xxx` —— **host 是前端自己（80），不是后端**。

| 关键点 | 值 / 位置 |
|---|---|
| 请求其实发给了谁 | **前端开发服务器**（一个跑在你机器上的 Node 进程），不是后端 |
| 为什么要绕这一层 | 页面在 `:80`、后端在 `:8080`，**端口不同 = 不同源**，JS 直连会被同源策略拦下 |
| `/dev-api` 前缀从哪来 | `utils/request.js:21` 里 `baseURL = process.env.VUE_APP_BASE_API`，值在 `.env.development` |
| 谁来转 | `vue.config.js:31-46` 的 `devServer.proxy`：命中 `/dev-api` → `target` 换成 `localhost:8080` |
| 为什么要删前缀 | `pathRewrite` 把 `/dev-api` 删掉 —— **后端根本没有这个路径**，它只是前端打的「转发标记」 |
| 后端最终收到 | `http://localhost:8080/xxx`，命中对应 Controller 的 `@RequestMapping` |

> 💡 点开 Network 里那条请求，**Request URL 是 `http://localhost/dev-api/login`**：host 是前端、path 里带 `/dev-api`。**后端 8080 从头到尾没在浏览器里出现过。**
>
> 出问题（转圈 / 404 / 401）怎么分清是谁的锅 → 直接看下一节 [§12 踩坑速查](#12-踩坑速查前端) 第 4 条。

## 12. 踩坑速查（前端）

把前端跑起来这一步的坑，几乎全在**环境**和**代理配置**上，跟 Vue 代码本身无关。按现象查表：

| # | 现象 | 真因 | 怎么办 |
|---|---|---|---|
| 2 | `npm run dev` 报 `listen EADDRINUSE :80` | 端口**写死 80**（`vue.config.js:12`），被 IIS / 其他 Web 服务占了 | 关掉占 80 的服务；或临时换端口：`port=8081 npm run dev` |
| 3 | 浏览器 `http://localhost` 打不开 | 80 是默认端口，URL **不用写端口** | 直接开 `http://localhost` |
| 4 | 页面能开，但**接口全卡住不返回**（转圈 / `net::ERR_EMPTY_RESPONSE`），npm 终端刷 `[HPM] Error occurred while trying to proxy ... (ECONNREFUSED)` | **后端没起**，代理转不过去（`vue.config.js:35-42`）| 先起后端：`curl localhost:8080/captchaImage` 应返回 200。（**注意不是 404** —— 404 是「后端起了但没这个接口」）|
| 5 | 登录成功，但**首页白屏 / 左侧菜单是空的** | `getRouters` 返回的菜单里 `component` 值和 `src/views/` 下真实路径对不上，`loadView()` 找不到文件 → 路由注不进去 | 对照 `sys_menu.COMPONENT` ↔ `src/views/` 目录名（**大小写敏感**）|
| 7 | 菜单里点「合同管理」之类进去 404 | **正常**：菜单是数据库里的数据，对应的 `.vue` / Controller 还没做 | 做完对应模块就好；**别当 bug 修** |
| 8 | 改了 `sys_menu`（加页面 / 换权限），前端**不生效** | 菜单和权限是**登录时查一次、之后一直用缓存** | **退出重新登录** |
| 9 | 想写 Vue 3 的语法（`<script setup>`、`ref()`）怎么都不对 | 本工程是 **Vue 2.6.12**，不是 Vue 3 | 用 Vue 2 的选项式写法（`data()` / `methods`）|
| 10 | `import x from '@/xxx'` 里的 `@` 是什么 | `@` = `src/` 的别名（vue-cli 默认配的）| 看到 `@/api/contract` 就是 `src/api/contract.js` |

**定位前端问题的三件套**：

1. **F12 → Network**：接口到底发出去没有、URL 对不对、响应什么。
2. **F12 → Console**：`Cannot read property 'xxx' of undefined` 这类报错直接指向哪个页面哪个变量。
3. **F12 → Application → Local Storage / Cookies**：`Admin-Token` 在不在（不在就是没登录成功）。

## 13. 🎤 怎么对面试官讲（被问到前端时）

Java 后端岗一般**不深挖前端**，但会问「前后端怎么协作」「这个页面你怎么查问题」。用下面这段收口：

> 「前端这块我主要是**读懂 + 定位**，不负责开发。我把它拆成一条链：**浏览器上的一个元素 → 哪个 `.vue` 文件 → 它 import 的哪个 `api/*.js` → 那个 url 对应后端哪个 Controller**。
> 机制上是：后端 `sys_menu` 表存着菜单和 `component` 字段，前端登录后用 `getRouters` 拉到菜单树，`permission.js` 把每个 `component` 字符串拼成 `require('@/views/' + 路径)` **动态注册成路由**——所以**加一个新页面根本不用改前端代码，在数据库插一条菜单就行**。
> 所有请求都过 `utils/request.js` 这一个出口：统一给请求头塞 `token: Bearer xxx`、统一处理 401 过期跳登录、统一弹错误提示。
> 我排前端问题按三层走：**Network 看请求发没发对、Console 看 JS 报错、数据库看菜单和数据**。」

**如果被追问「那你怎么把前后端串起来的？」，换这一版 —— 按四条真实链路答**：

> 「我按四条链路把前后端打通了 ——
> **登录链**：`login.vue` 提交 → `api/login.js` 打 `POST /login` → 后端校验验证码、查库、`StpUtil.login()` 发 token；前端用 `js-cookie` 把 token 存进 Cookie `Admin-Token`，之后每次请求在 `request.js` 里**自动**塞进请求头。
> **菜单链**：登录后带 token 调 `getRouters`，后端从 `sys_menu` 返回菜单树，前端 `permission.js` 把每个 `component` 字符串**动态 require 成路由** —— 所以**加页面不用动前端，数据库插一条菜单就行**。
> **列表链**：页面 `created` 调 `api/xxx/list`，后端 Controller → Service → Mapper，返回 `{rows, total}` 渲染到表格。
> **新增链**：弹窗表单 `form` → `api/xxx` 打 `POST` → 后端接 Bo 校验入库。
> 排查问题我就顺着链路反着找：**Network 看请求、Console 看报错、数据库看菜单和数据**。」

（四条链的**逐行走读**见 [精读 3 · 前端代码走读](03-四条链路走读.md)；把其中一条**每跳贴代码**的完整版见 [精读 4 · 一次点击的完整旅程](04-一次点击的完整旅程.md)。）

## 本章答辩卡（追问级）

**卡 1：新增一个菜单页面，为什么前端一行代码都不用改？**

**10 秒答案**：菜单不是写死在前端路由里的。登录后 `permission.js` 调 `GetInfo` / `GenerateRoutes`，后端 `getRouters` 从 `sys_menu` 返回菜单树；前端 `filterAsyncRouter` 把每个 `component` 字符串交给 `loadView` 动态 `import` 成路由，再 `addRoutes`。所以只要数据库插一条菜单、给角色授权，页面就能出现。

**证据**：`zxcm-ui/src/permission.js:43-52`、`zxcm-ui/src/store/modules/permission.js`（`filterAsyncRouter` / `loadView`）、`zxcm-ui/src/router/index.js:32-132`。

**卡 2：前端用 `v-hasPermi` 把按钮藏了，后端还需要校验吗？**

**10 秒答案**：必须要。`v-hasPermi` 只是把按钮从 DOM 里删掉，是体验优化，不是安全边界；用户完全可以绕过页面直接调接口。每个写接口仍然必须有 `@SaCheckPermission`。

**证据**：`zxcm-ui/src/directive/permission/hasPermi.js:8-28`、后端 `@SaCheckPermission` 遍布 Controller（如 `TSigningSubjectController.java`）。

**卡 3：浏览器为什么不会直接请求 8080？**

**10 秒答案**：开发时前端在 80、后端在 8080，端口不同就是不同源，浏览器会按同源策略拦。前端只请求自己的 `/dev-api`，由 webpack-dev-server 按 `vue.config.js` 的 proxy 规则去掉前缀再转发到 8080，所以浏览器全程以为在访问同一个源。

**证据**：`zxcm-ui/vue.config.js:31-46`、`zxcm-ui/src/utils/request.js:19-24`。
