# 第 5 章 · 合同草拟与文件页面

> 前四章都是「配置数据」。从这一章开始进入**合同主线**——用户真正干活的页面。合同草拟目录 `src/views/contract/contractDraft/` 是全站**文件最多、表单最长**的地方，光一个「发起审批」表单（`apply.vue`）就有 **1309 行**。这一章教你「面对一个巨型页面，怎么读、怎么定位」。

---

## 一、这部分是做什么的

「合同草拟」是**一条合同从无到有的前半段**：

```
创建合同（填基本信息，生成合同）  →  上传/编写合同文本（文件）  →  发起审批
   createContract.vue                    info / 文件组件              apply.vue
```

对应的页面族（`src/views/contract/contractDraft/`）：

| 文件 | 行数 | 干什么 |
|---|---|---|
| `index.vue` | 464 | **合同列表**（草稿态的合同）+ 「更多」下拉（新版本/文件/下载/删除） |
| `createContract.vue` | 611 | **创建合同**（新建 / 续签 / 变更三种入口共用） |
| `apply.vue` | **1309** | **发起审批**（填完整申请表单，最长） |
| `edit.vue` | 1169 | **编辑 + 流程审批**（审批中修改后重新提交） |
| `newVersion.vue` | 186 | **创建新版本** |
| `info/index.vue` | 105 | 合同详情（含模板合并） |
| `info/editInfo.vue` | 78 | 合同详情编辑 |
| `merchant.vue` / `flowShow.vue` | 79 / 36 | 小弹窗（选商户 / 显示流程） |
| `contractDraftFiles/index.vue` | 353 | **合同文件管理**（独立页，见 §4.6） |

> **零基础先补概念（前端视角）**
>
> - **文件上传组件**：浏览器原生 `<input type="file">` 只能选文件，不会自动上传；Element 的 `el-upload` 把「选文件 → 发请求 → 拿回服务器返回」串起来。本项目的 `FileUploadContract` 是 `el-upload` 的二次封装：文件先传到文件服务，组件把服务器返回的 `uid/name/url` 交给页面，页面再把它们拼进表单一起提交（`zxcm-ui/src/views/contract/contractDraft/apply.vue:96-101`、`createContract.vue:102-111`）。上传组件的 props 用法见《Vue2 从 0 到精通》第 4 章 §4。
> - **`$router.resolve` + `window.open`**：`$router.resolve({...})` 只负责把「路由 + 参数」算成一个完整 URL，不跳转；`window.open` 才真的打开新标签页。本项目用它打开全屏的在线编辑页（`zxcm-ui/src/views/contract/contractDraft/index.vue:335-338`）。路由基础见《Vue2 从 0 到精通》第 5 章 §4.2、§5.1。
> - **父组件用 `ref` 调子组件方法**：合同列表页并没有把「创建合同」表单写在列表页里，而是把子组件挂成 `<createContract ref="createContract" ... />`（`index.vue:212`），点按钮时执行 `this.$refs.createContract.add()`（`:385-387`）。原理见《Vue2 从 0 到精通》第 4 章 §9.1。
> - **提交前把数组变成 JSON 字符串**：表单里「合同文件」「签约主体」这些字段在界面上一行行增删，代码里是数组；后端接口期望字符串，所以提交前统一 `JSON.stringify`（`createContract.vue:523,527,533`；`apply.vue:1171-1174`）。这不是 Vue 语法，而是前后端的数据结构约定。

> 后端对应：[后端重塑版 第 5 章「合同草拟」](../后端重塑版/第5章-合同草拟.md)。

## 二、站在架构师角度，为什么这么设计

### 2.1 为什么「创建合同」和「发起审批」是两个页面

看代码分工：
- `createContract.vue` → 调 `addContractDraft`（`POST /contract/contractDraft`）——**只创建合同的基本记录**（编号、类型、名称、我方/对方主体）。
- `apply.vue` → 调 `addContractAudit`（`POST /contract/contractAudit`）——**提交完整审批申请**。

**为什么分开**：
- **合同记录先落库、后走审批**。用户可能先建个合同、过两天再补充内容提交——分两步更符合真实业务节奏。
- 两步对应**两个不同的后端实体/表**（`contract_draft` 草稿 vs 审批申请），职责不同。
- 「发起审批」还有「保存草稿」的能力，同一份表单既能存也能提。

**答辩点**：**「合同生命周期是分阶段落库的，不是一步到位」**——创建（草稿）→ 发起审批（审批态）→ 用印 → …… 每一步写不同的表、改不同的状态。这条主线就是整个[后端重塑版](../后端重塑版/README.md)的骨架。

### 2.2 为什么 `createContract.vue` 一个文件要干「新建 / 续签 / 变更」三件事

看 `createContract.vue:325,332,349`：

```js
add()          { /* 新建合同 */ }
renew(row)     { /* 续签：基于旧合同生成新合同 */ }
updateContract(row) { /* 变更 */ }
```

**为什么在同一个文件**：这三种操作**表单高度重合**（都是填合同基本信息），区别只是「从空白开始」还是「从旧合同复制」。如果各写一个文件，会有三份几乎一样的 611 行表单。**复用同一套模板，用不同入参区分**，是务实的选择。

**答辩点**：**「续签/变更在数据上都是『复制旧合同 + 标记关系』」**——`renew` 会把旧合同的信息带过来，`submitForm` 时通过 `addContractDraft` 或 `updateContractDraft` 分别落库（`createContract.vue:537,547`）。

### 2.3 为什么 `apply.vue` 这么长（1309 行），不拆吗

`apply.vue` 是最长的页面。**没拆的原因**：它是一个**「一次性提交的大表单」**——所有字段最终打包成一个 `form` 提交给 `addContractAudit`（`:1177`）。拆成子组件后，反而要「把几十个字段来回 props / emit」，比不拆更麻烦。

**读这种巨型页面的方法**（这一节很重要）：
1. **别看 `<template>` 全文**（几百行），直接找 `<script>`。
2. 看 `data()` 里的 `form` 对象——**`form` 的字段就是「这个表单填什么」**。
3. 看 `submitForm()`（`apply.vue:1148`）——**这是整页的「出口」**，它告诉你提交什么、打哪个接口。
4. 再回头看 template 里**你不认识的那几块**（如文件上传 `:96`）。

**答辩点**：**「看长表单先看 form 和 submitForm，不要从 HTML 从头读」**——这是读陌生大页面的通用技巧。

### 2.4 为什么「编辑文本」是**新开一个浏览器路由**，不是弹窗

看 `index.vue:335`：

```js
editDoc(row) {
  const pathInfo = this.$router.resolve({ path: '/contractFileEdit', query: { id: row.id }})
  // 然后 window.open(pathInfo.href) 打开新窗口
}
```

**为什么**：合同**在线编辑文档**（第 8 章）是一个**独立的、全屏的、带 OnlyOffice/WPS 的页面**，塞进弹窗会又挤又慢。所以用 `$router.resolve` 生成 URL 再 `window.open` **开一个新标签页**。

`/contractFileEdit` 这个路由就是在**静态路由**里注册的（`router/index.js:75-79`，第 2 章讲过）——正因为它要被独立打开、不属于菜单树。

### 2.5 为什么合同要「创建新版本」

合同审批中/盖章后**不能直接改**（这是[后端重塑版 第 9 章](../后端重塑版/第9章-用印·作废·续签·归档.md)讲的「历史不可变」原则）。要改，就**新建一个版本**——`newVersion.vue` 调 `addNewVersion`（`POST /contract/contractDraft/newVersion`），保留旧版本、生成新版本。

**答辩点**：**「历史不可变」在前端的体现就是「多一个『创建新版本』按钮，而不是『编辑原合同』」**。前端和后端在同一条原则上是一致的。

### 2.6 「合同文件」为什么是独立页面

`contractDraftFiles/index.vue` 是一个**独立的 CRUD 页面**（和基础数据页一样，有表格/分页/权限），管理合同的**附件文件**。它虽然也在合同目录下，但形态上是「标准 CRUD」，所以放在 `contract/contractDraftFiles/` 单独一个文件夹。

### 4.2 `createContract.vue` —— 创建合同（611 行）

| 行号 | 内容 |
|---|---|
| `:214` | 确定按钮 → `submitForm` |
| `:325` | `add()` 新建 |
| `:332` | `renew(row)` 续签 |
| `:349` | `updateContract(row)` 变更 |
| `:433` | `listContractTemplate({contractType})` 按类型拉可用模板 |
| `:521` | `submitForm()` |
| `:537` | `updateContractDraft(this.form)`（变更） |
| `:547` | `addContractDraft(this.form)`（新建/续签落库） |

**读法**：这页的 `form` 里有几个**隐藏的入口标记**（区分新建/续签/变更），`submitForm` 里根据标记决定调哪个接口。**这是「一个页面扮三种角色」的实现手法**。

**逐行读 `submitForm()`（`zxcm-ui/src/views/contract/contractDraft/createContract.vue:521-559`）**：

```js
submitForm() {
  let that = this;
  this.form.fileGroup = JSON.stringify(this.selectedFiles)
  this.$refs['form'].validate((valid) => {
    if (valid) {
      this.buttonLoading = true
      this.form.contractType = JSON.stringify(this.form.contractTypeArray)
      if (this.selectedTemplate != undefined) {
        this.form.contractTemplateId = this.selectedTemplate.id
        this.form.fileGroup = JSON.stringify([])
      } else {
        this.form.contractTemplateId = undefined
        this.form.fileGroup = JSON.stringify(this.selectedFiles)
      }

      if (this.form.id != null) {
        updateContractDraft(this.form)
          .then((response) => {
            this.$modal.msgSuccess('修改成功')
            this.open = false
            this.$emit('reload')
          })
          .finally(() => {
            this.buttonLoading = false
          })
      } else {
        addContractDraft(this.form)
          .then((response) => {
            let contractInfo = response.data;
            this.$modal.msgSuccess('新增成功')
            this.open = false

            this.$emit("applyAudit", contractInfo);
            //this.$emit('reload')
          })
          .finally(() => {
            this.buttonLoading = false
          })
      }
    }
  })
}
```

1. `submitForm()`：弹窗「确定」按钮的入口（`:214`）。
2. `let that = this;`：先把 `this` 存起来。下面的 `.then` 回调是普通函数，里面直接写 `this` 会丢指向；这里其实后续都用了箭头函数，所以 `that` 没被用到，是**遗留写法**（可在答辩时主动说明）。
3. `JSON.stringify(this.selectedFiles)`：把界面上选中的文件数组转成字符串，先塞进 `fileGroup`。
4. `this.$refs['form'].validate(...)`：调用 Element 表单的校验；校验通过才执行 `if (valid)` 里面的提交逻辑（表单/校验见《Vue2 从 0 到精通》第 8 章 §5.6）。
5. `this.buttonLoading = true`：按钮转圈，防止用户连点造成重复提交。
6. `this.form.contractType = JSON.stringify(this.form.contractTypeArray)`：合同类型在界面上是级联选择器给出的数组（如 `[父类型id, 子类型id]`），后端要字符串，所以转成 JSON。
7. `if (this.selectedTemplate != undefined)`：判断用户有没有选模板。
8. `this.form.contractTemplateId = this.selectedTemplate.id`：选了模板就只传模板 id。
9. `this.form.fileGroup = JSON.stringify([])`：选了模板时**清空手工上传的文件数组**——正文由模板生成，不再用上传件。
10. `else { this.form.contractTemplateId = undefined; this.form.fileGroup = JSON.stringify(this.selectedFiles) }`：没选模板就反过来，传模板 id 为空，传手工上传的文件。
11. `if (this.form.id != null)`：`id` 有值代表这是「变更」而不是「新建」。
12. `updateContractDraft(this.form)`：变更走 `PUT /contract/contractDraft`（`:537`）。
13. `this.$emit('reload')`：子组件通知父组件；父组件在 `<createContract ... />` 上没有监听 `reload`（`index.vue:212` 只监听 `applyAudit`），所以**这个事件目前没有接收方**，是一个小缺口。
14. `else { addContractDraft(this.form) }`：新建/续签走 `POST /contract/contractDraft`（`:547`）。
15. `response.data`：后端返回新合同记录，`:553` 通过 `$emit('applyAudit', contractInfo)` 交给父组件；父组件 `applyAudit`（`index.vue:309-312`）刷新列表并立刻打开审批表单。
16. `.finally(...)`：无论成功失败都把按钮 loading 关掉——成功和失败都能再次点击。

> ⚠️ **坦白点**：第 13 条说的 `$emit('reload')` 目前**没有父组件监听**——`index.vue:212` 的 `<createContract>` 只写了 `@applyAudit="applyAudit"`。也就是说「变更合同」保存成功后，列表不会自动刷新（新增/续签会走 `applyAudit` 刷新）。答辩被问到「你的页面有没有已知缺口」时，这是一个可以主动讲的真实例子。

### 4.7 我要「改一个合同表单字段」怎么办

1. 判断字段属于哪个阶段：创建（`createContract.vue`）/ 发起审批（`apply.vue`）/ 编辑（`edit.vue`）。

3. 后端字段是否支持，看[后端重塑版 第 5 章](../后端重塑版/第5章-合同草拟.md)。

### 4.8 动手验证（在浏览器里确认上面的结论）

1. **创建合同**：进入「合同管理 → 合同草拟」，按 `F12` 打开 DevTools → **Network**，点「创建合同」，填合同名称、选合同类型，点确定。找到 `contractDraft` 的 **POST** 请求，查看 **Payload**：`contractType` 是字符串（形如 `"[1,5]"`），`fileGroup` 也是字符串（`createContract.vue:523,527`）。
2. **看自动打开审批**：创建成功后，页面应立刻弹出「发起合同审批」表单。这是 `$emit('applyAudit', contractInfo)` → 父组件 `applyAudit`（`zxcm-ui/src/views/contract/contractDraft/index.vue:309-312`）→ `showApply(row)`（`:302-307`）连续动作的结果，不是重新点了一次按钮。
3. **看编辑文本的新窗口**：在列表里点「编辑文本」，浏览器会**新开一个标签页**，地址形如 `/contractFileEdit?id=...`。回到 DevTools 的 **Network**，新标签页会加载在线编辑相关资源——这说明走的是独立路由，不是弹窗（`index.vue:335-338`；路由注册在第 2 章讲过的静态路由）。
4. **看审批表单的提交**：在审批表单里点「保存/下一步」，Network 里会出现 `POST /contract/contractAudit`，Payload 里 `subjects`、`partners`、`stampType`、`uploadFile` 都是字符串（`apply.vue:1171-1174`）。
5. **看版本弹窗**：点「更多 → 创建新版本」，弹窗标题是「上传新版本」，里面先显示旧版本号和旧文件，再让填新版本号；确定后请求 `POST /contract/contractDraft/newVersion`（`newVersion.vue:116-142`）。

**预期**：每次提交都能在 Network 看到对应请求和 `code:200` 响应；选中模板时 `fileGroup` 是 `"[]"`，不选模板时 `fileGroup` 里是已上传文件的 JSON 字符串。若请求报 401，先检查登录 token（第 1 章）。

## 六、面试高频问题

**Q1：合同草拟这条线有哪些页面？**
A：合同列表（`contractDraft/index.vue`）、创建合同（`createContract.vue`）、发起审批（`apply.vue`）、编辑+审批（`edit.vue`）、创建新版本（`newVersion.vue`）、合同详情（`info/`）、合同文件（`contractDraftFiles/index.vue`）。

**Q2：为什么「创建合同」和「发起审批」分开？**
A：因为生命周期分阶段落库——先 `POST /contract/contractDraft` 建草稿记录，内容齐了再 `POST /contract/contractAudit` 提交审批。对应两张不同的表/两个状态。也符合真实业务（先建后补）。

**Q3：一个 1309 行的表单页你怎么读/维护？**
A：不从头读 HTML。**先看 `data()` 里的 `form`**（知道填什么），**再看 `submitForm()`**（知道提交到哪，`apply.vue:1148→1177`），最后才回看 template 里不认识的块。维护时也是改这三处：form、submitForm、对应表单项。

**Q4：一个页面怎么同时支持「新建/续签/变更」？**
A：用入口标记区分。`createContract.vue` 里 `add/renew/updateContract` 三个方法（`:325/332/349`）准备不同的 `form`，`submitForm`（`:521`）根据标记决定调 `addContractDraft`（`:547`）还是 `updateContractDraft`（`:537`）。三种操作共用同一套表单模板。

**Q5：「编辑文本」为什么要新开窗口？**
A：合同在线编辑是一个独立的、全屏的、带 OnlyOffice/WPS 的页面（第 8 章）。用 `$router.resolve('/contractFileEdit', {query:{id}})` 生成 URL 再 `window.open` 开新标签页（`zxcm-ui/src/views/contract/contractDraft/index.vue:335-338`）。`/contractFileEdit` 在静态路由里注册（`zxcm-ui/src/router/index.js:75-79`），就是因为它要独立打开、不走菜单。
**追问：`resolve` 和 `push` 有什么区别？** 答：`push` 会立刻在当前窗口跳转；`resolve` 只把路由解析成 `{ href, route, location }`，不跳转，所以能拿 `href` 交给 `window.open` 开新标签页（见《Vue2 从 0 到精通》第 5 章 §4.2）。

**Q6：为什么合同要「创建新版本」而不是直接改？**
A：合同审批中/盖章后**历史不可变**——不能覆盖原内容。改的话就 `POST /contract/contractDraft/newVersion` 生成新版本，保留旧的。前端用「创建新版本」按钮体现这个原则（`newVersion.vue:136`）。

**Q7：合同文件管理页和前面的基础数据页有什么不同？**
A：**没有不同**——它就是一个标准 CRUD 页（`JTable` + 分页 + 权限 `contract:contractDraftFiles:*`）。这正好说明业务页和管理页在代码结构上是同构的。

**Q8：合同列表的「更多」下拉怎么实现的？**
A：用 Element 的 `<el-dropdown>`（`contractDraft/index.vue:162-190`），每个 `el-dropdown-item` 带 `command`，下拉触发 `handleCommand`（`:322-330`）里 `switch(command)` 分发到 `handleUpdateFile`/`handleDelete`/`handleUpdate` 等方法。**「命令模式」在前端的应用**。

**Q9：列表里的状态怎么显示成中文？**
A：字典机制。`dicts: ['CONTRACT_REVIEW_STATUS']`（`index.vue:228`）声明字典，模板里用 `<dict-tag>` 显示。改措辞改后端字典（第 3 章）。

**Q10：创建合同时，合同编号哪来的？**
A：走编号规则接口 `GET /conf/billRule/getBillNumber/{code}`（`zxcm-ui/src/api/conf/billRule.js:4` 的 `getBillCode`）。后端按「编号规则」生成（[后端重塑版 第 3 章](../后端重塑版/第3章-编号规则.md)）。前端在创建表单里拿到编号展示/写入。

### 本章答辩卡（追问级）

**卡 1：点「创建合同」并提交后，为什么审批表单会自动弹出来？**
10 秒答案：创建合同是一个子组件，提交成功后它 `$emit('applyAudit', 新合同)`；父组件监听这个事件，刷新列表并调用 `showApply`，用 `$nextTick` 等 DOM 就绪后调审批表单的 `init(id)`。不需要用户再点一次「发起审批」。
证据：`zxcm-ui/src/views/contract/contractDraft/createContract.vue:553`、`index.vue:212`、`index.vue:309-312`、`index.vue:302-307`。

**卡 2：`apply.vue` 1309 行，如果面试官让你拆，你按什么边界拆？**
10 秒答案：按「是否独立提交」拆。`apply.vue` 的所有字段最终打包进一个 `form` 走 `addContractAudit`，拆开反而要几十个 props/emit，所以不拆；但文件上传、合作方选择、合同信息预览这类有独立状态和独立接口的块可以拆成子组件（项目里 `merchant.vue`、`info/index.vue`、`flowShow.vue` 已经是这么做的）。
证据：`zxcm-ui/src/views/contract/contractDraft/apply.vue:1148-1177`（统一出口）、`:604-628`（引入子组件）、`:624`（`merchant`）、`:625`（`info`）。

**卡 3：「创建新版本」提交后，父页面怎么知道要刷新？旧版本数据会丢吗？**
10 秒答案：子组件成功后 `$emit('reload')`，父组件在 `<new-version ... @reload="getList()" />` 上监听并重新拉列表。旧版本由后端保留，新版本通过 `POST /contract/contractDraft/newVersion` 生成；前端只负责传新版本号和文件。
证据：`zxcm-ui/src/views/contract/contractDraft/newVersion.vue:133-142`（尤其 `:139`）、`index.vue:211`。

## 七、选型对比

### 7.1 分阶段落库 vs 一步落库

| | 分阶段（本项目） | 一步到位 |
|---|---|---|
| 业务贴合 | ✅ 符合「先建后补」 | ❌ 强制一次填完 |
| 数据一致性 | 要处理「草稿态」中间状态 | 简单 |
| 灵活性 | 高 | 低 |

**结论**：合同这种「信息多、周期长」的业务，分阶段落库更贴合实际。代价是要维护「草稿」这个中间状态。

### 7.2 巨型表单：单文件 vs 拆分

| | 单文件（本项目 apply.vue） | 拆子组件 |
|---|---|---|
| 字段传递 | 直接用一个 `form` | 几十个 props/emit，繁琐 |
| 可读性 | 单文件长，但集中 | 分散 |
| 适用 | **一次性提交的大表单** | 有独立逻辑的块 |

**结论**：`apply.vue` 是「一次性提交」，所有字段最终打包成一个 `form`，**拆反而麻烦**，所以不拆。但如果是「多个独立子表单、各自提交」，就该拆（如合作方的 `edit.vue`，第 4 章）。

### 7.3 在线编辑：弹窗 vs 新窗口

| | 新窗口（本项目） | 弹窗 |
|---|---|---|
| 空间 | 全屏，够用 | 挤 |
| 性能 | 独立页面加载快 | 弹窗内嵌编辑器重 |
| 路由 | 走静态路由 | 无需路由 |

**结论**：文档编辑器是大而重的独立应用，新窗口更合适。`window.open` + 静态路由是标准做法。
