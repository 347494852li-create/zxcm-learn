# 第 2 章 · 路由·菜单·按钮权限

> 这一章回答三个问题：**① URL 怎么对应到页面**（路由）、**② 左边那排菜单是怎么长出来的**（动态菜单）、**③ 为什么有些按钮你看不到**（按钮权限）。这三个问题背后是同一套机制——**「前端不写死权限，一切权限从后端来」**。

> **零基础先补概念（第一次看路由，先读这 4 条）**
>
> 1. **前端路由**：把「浏览器地址里的一个路径」映射到「显示哪个组件」。点菜单不会请求新的 HTML，只是让 Vue Router 换掉 `<router-view>` 里的组件。本项目路由表在 `zxcm-ui/src/router/index.js:32`。见《Vue2 从 0 到精通》第 5 章 §一、§三。
> 2. **路由守卫**：路由切换前/后自动执行的钩子。`beforeEach` 在每次跳转前跑，用来判断「有没有登录、能不能进」，本项目在 `zxcm-ui/src/permission.js:14`。见《Vue2 从 0 到精通》第 5 章 §九。
> 3. **动态路由**：路由不是全写在代码里，而是启动时从后端拿菜单，再用 `router.addRoutes()` 在运行时加进路由器。本项目在 `zxcm-ui/src/store/modules/permission.js:33-51`。见《Vue2 从 0 到精通》第 5 章 §十。
> 4. **自定义指令（directive）**：给标签加一个自定义属性（如 `v-hasPermi`），Vue 在元素插入页面时执行你写的函数。本项目用它按权限删按钮（`zxcm-ui/src/directive/permission/hasPermi.js:9`）。见《Vue2 从 0 到精通》第 2 章 §9.2。

## 一、这部分是做什么的

前端有三层「门」：

| 层 | 管什么 | 举例 | 靠什么实现 |
|---|---|---|---|
| **路由层** | URL 该显示哪个页面 | 点 `/contract/contractDraft` 显示合同草拟页 | Vue Router |
| **菜单层** | 左侧菜单显示哪些项 | 用户没配「模板管理」角色，左侧就没这项 | 后端 `/getRouters` + `router.addRoutes` |
| **按钮层** | 页面上哪些按钮可见 | 没有「删除」权限，删除按钮**直接消失** | `v-hasPermi` 指令 |

**关键认知**：这三层**不是前端自己判断的**。前端的「我有什么权限」是登录后从后端 `GET /getInfo` 拿到的 `permissions` 列表（形如 `['contract:contractDraft:add', ...]`），前端的活儿只是**拿这个列表去过滤**。

> 后端权限码怎么定义、怎么配到角色的，见[后端重塑版 附录 §二 注解速查表](../后端重塑版/附录-横切能力索引.md)。

## 二、站在架构师角度，为什么这么设计

### 2.1 为什么路由要分「静态」和「动态」

打开 `src/router/index.js`，路由分成两组：

**`constantRoutes`（静态路由，`:32-132`）**——所有人都有的：
- `/login` 登录、`/register` 注册、`/404` `/401` 错误页
- `/index` 首页
- `/user/profile` 个人中心
- **`/contractFileEdit`、`/contractFileView`、`/contractFileRevise`、`/fileView`**——这几个是**在线文档编辑页**（第 8 章讲），它们被放在静态路由是因为要从**独立窗口**打开，不方便走菜单。

**`dynamicRoutes`（动态路由，`:135-207`）**——**要权限才加载**的：
- `/system/user-auth`（分配角色，要 `system:user:edit`）
- `/system/role-auth`（分配用户，要 `system:role:edit`）
- `/system/oss-config`、`/system/dict-data`、`/tool/gen-edit`

**为什么分开**：`constantRoutes` 是「地基」，登录页、首页、404 必须随时能进；`dynamicRoutes` 是「带权限的详情页」，没权限的人根本不该知道它存在。**分开之后，登录页在没登录时也能正常渲染**（否则会死锁：要进登录页但登录页也要权限）。

### 2.2 为什么「菜单不用前端写死」，而是后端下发

这是本项目权限设计的**核心**。前端**没有**一份「菜单列表写在代码里」，而是启动时调 `GET /getRouters`，后端根据**当前用户的角色**查出他能看的菜单，返回一个**树形结构**，前端再把它「翻译」成 Vue Router 的路由。

**为什么这么设计**：
- **加一个菜单不用改前端、不用重新发版**——运维在后台配一个菜单 + 配给角色，前端刷新就多出来了。
- **权限的「真相」只有一份**（在后端数据库），前端不会和后端「对不上」。
- 这也是 RuoYi 框架的招牌设计，**答辩时说的就是「菜单级别的前端路由」**。

**代价**：前端启动时多两次请求（`/getInfo` + `/getRouters`）。但这个代价换来「权限动态可控」，非常值。

### 2.3 为什么后端返回的 `component` 是**字符串**

后端返回的菜单里，每个节点有个 `component` 字段，值长这样：`"contract/contractDraft/index"`——**是个字符串，不是组件**。因为后端（Java）不可能返回一个 Vue 组件对象，它只能是「路径字符串」。

前端拿到字符串后，用 `loadView` 把它**翻译成真实组件**（`store/modules/permission.js:124-131`）：

```js
export const loadView = (view) => {
  if (process.env.NODE_ENV === 'development') {
    return (resolve) => require([`@/views/${view}`], resolve)
  } else {
    return () => import(`@/views/${view}`)   // 生产环境懒加载
  }
}
```

**这就是「约定」的威力**：后端只要在数据库菜单表里填 `contract/contractDraft/index`，前端 `@/views/contract/contractDraft/index.vue` 这个文件就会被加载。**字段值和文件路径必须严格对应**，这是前后端的一个隐式契约。

还有一个特殊约定：后端可能返回 `"Layout"`、`"ParentView"`、`"InnerLink"` 三个**关键字**，它们不对应 `views/` 下的文件，而是对应**框架壳组件**（`store/modules/permission.js:63-68`）：
- `Layout` → 后台整体框架（侧边栏 + 顶部栏）
- `ParentView` → 只有 `<router-view>` 的「占位父节点」（用于三级菜单）
- `InnerLink` → 内嵌 iframe 的外链页

### 2.4 为什么按钮权限用「指令」而不是「v-if」

给一个按钮加权限，你可能会想在 `<el-button>` 上写 `v-if="hasPermi('xxx')"`。但本项目写的是：

```vue
<el-button v-hasPermi="['contract:contractDraft:add']">创建合同</el-button>
```

`v-hasPermi` 是**自定义指令**（`zxcm-ui/src/directive/permission/hasPermi.js:8-28`）。它和 `v-if` 的区别：

| | `v-if="hasPermi('x')"` | `v-hasPermi="['x']"`（本项目） |
|---|---|---|
| 写法 | 还要写 `hasPermi` 方法、要 import | 一个属性搞定，值就是权限码数组 |
| 时机 | 渲染时判断 | `inserted` 钩子，DOM 插入后判断 |
| 逻辑 | 自己写 | 指令内部统一（支持 `*:*:*` 超管通配） |

**指令的实现超简单**（`directive/permission/hasPermi.js:9-27`）：当按钮的 DOM 被插入页面时，指令读用户权限列表——**如果没有匹配的权限，就把这个 `el` 从父节点上删掉**（`el.parentNode.removeChild(el)`，`:22`）。

> ⚠️ **重要认知（答辩加分项）**：`v-hasPermi` 是**「隐藏」不是「防护」**。它只是把按钮从 DOM 里删了，用户如果懂技术，仍能直接构造请求绕过。**真正的安全必须在后端**——后端每个接口上都有 `@SaCheckPermission("contract:contractDraft:add")`（[后端重塑版 附录 §二](../后端重塑版/附录-横切能力索引.md)）。前端指令只是**体验优化**：让没权限的人看不到点不了的按钮，而不是「防黑客」。

### 2.5 `*:*:*` 超管通配

指令里有个细节（`hasPermi.js:11,18`）：如果用户的权限列表里有 `*:*:*`，那么**任何**权限校验都通过。这是**超级管理员**的通行证——不用给他配每一条权限，只配 `*:*:*` 就行。角色校验同理，有个 `admin` 通配（`plugins/auth.js:16`）。

### 4.2 路由节点上的关键字段（`router/index.js:9-29` 有官方注释）

| 字段 | 含义 |
|---|---|
| `path` | URL 路径 |
| `component` | 组件（或字符串，动态路由由后端给） |
| `hidden: true` | 不在侧边栏显示（如 404、编辑详情页） |
| `redirect` | 进入此路由时重定向到哪 |
| `alwaysShow: true` | 有多个子路由时也显示父节点（不自动折叠） |
| `permissions: [...]` | 进这个路由需要的权限码（动态路由用） |
| `meta.title` | 菜单/面包屑显示的名字 |
| `meta.icon` | 图标（`src/assets/icons/svg` 下的 svg 名） |
| `meta.activeMenu` | 高亮哪个侧边栏项（详情页常用） |

### 4.3 我想改「换一个页面的 URL」怎么办

- **页面属于静态路由**：直接改 `router/index.js` 里 `path`。
- **页面属于动态路由（菜单下发的）**：**前端改没用**，得去后端数据库的菜单表改。这就是 §2.2 说的「菜单真相在后端」。

### 4.4 我想「加一个新按钮 + 权限控制」怎么办

1. 先在后端把权限码（如 `contract:contractDraft:export`）配到菜单/角色上（[后端重塑版 第 2 章](../后端重塑版/第2章-合作方管理.md) 数据权限相关）。
2. 前端页面里给按钮加指令：

```vue
<el-button v-hasPermi="['contract:contractDraft:export']" @click="handleExport">导出</el-button>
```

3. 后端接口上加 `@SaCheckPermission("contract:contractDraft:export")` 兜底。

### 4.5 全站有多少权限指令可用

| 指令 | 文件 | 语义 |
|---|---|---|
| `v-hasPermi="['a:b:c']"` | `directive/permission/hasPermi.js` | 有该权限才显示 |
| `v-hasRole="['admin']"` | `directive/permission/hasRole.js` | 有该角色才显示 |
| `v-notHasPermi="['a:b:c']"` | `directive/permission/notHasPermi.js` | **没有**该权限才显示（本项目只在合作方页用过，见第 4 章） |

### 4.6 逐行读：按钮权限指令（`zxcm-ui/src/directive/permission/hasPermi.js:8-28`）

```js
export default {
  inserted(el, binding, vnode) {
    const { value } = binding
    const all_permission = "*:*:*";
    const permissions = store.getters && store.getters.permissions

    if (value && value instanceof Array && value.length > 0) {
      const permissionFlag = value

      const hasPermissions = permissions.some(permission => {
        return all_permission === permission || permissionFlag.includes(permission)
      })

      if (!hasPermissions) {
        el.parentNode && el.parentNode.removeChild(el)
      }
    } else {
      throw new Error(`请设置操作权限标签值`)
    }
  }
}
```

| 行号 | 这一行在干什么 | 为什么这么写 |
|---|---|---|
| `:8` | 导出一个指令对象 | 在 `zxcm-ui/src/directive/index.js:11` 用 `Vue.directive('hasPermi', ...)` 注册 |
| `:9` | 用 `inserted` 钩子：元素已经插入页面后执行 | 只有插入后才拿得到 `parentNode`，才能把元素从 DOM 删除；`bind` 阶段还没进 DOM，删不了 |
| `:10` | 从 `binding` 里取出指令值 | 模板里写 `v-hasPermi="['a:b:c']"`，这里拿到的就是数组 |
| `:11` | 定义超管通配符 `*:*:*` | 超级管理员只配这一条就能通过所有校验 |
| `:12` | 从 Vuex getter 读当前用户权限列表 | `permissions` 来自登录后 `GET /getInfo`，存在 `store/modules/user.js:33-35`，getter 在 `zxcm-ui/src/store/getters.js:15` |
| `:14` | 校验指令值必须是非空数组 | 防止有人写成 `v-hasPermi="xxx"` 或空数组，导致「永久隐藏」还查不出原因 |
| `:15` | 把指令值存成 `permissionFlag` | 后面用 `includes` 判断 |
| `:17-19` | 遍历用户权限：有 `*:*:*`，或用户权限出现在要求的数组里，就算通过 | `.some()` 的语义是「有一个满足即可」；注意方向是「用户权限 ∈ 要求的权限数组」 |
| `:21-22` | 没有匹配权限 → 从父节点删除这个元素 | 是 `removeChild`，不是 `display:none`，所以 DOM 里根本不存在 |
| `:24-25` | 指令值不合法 → 直接抛错 | 属于开发者写错，让问题在开发阶段暴露 |

> 这套「按权限删 DOM」的写法只是体验优化，不是安全边界，见 §2.4 的「重要认知」。

### 4.7 动手验证：把菜单和按钮权限「抓现行」

前提：前端 `http://localhost/`，用有权限的账号登录，DevTools 打开。

1. **看后端下发的菜单树**：Network 过滤 `getRouters`，点 Response/Preview。预期：返回树形 JSON，节点的 `component` 是**字符串**（如 `contract/contractDraft/index`），不是组件代码（`zxcm-ui/src/api/menu.js:4-9`）。
2. **菜单跟着角色变**：对照后端返回的 `meta.title` 与左侧菜单，应一一对应；换一个角色不同的账号登录，菜单项会变，但前端代码没改一行。
3. **按钮是真删不是隐藏**：管理员账号打开「合同草拟」页，Elements 里搜「创建合同」能找到按钮；换一个没有 `contract:contractDraft:add` 权限的账号，再搜同一文字——**DOM 里找不到**，因为它被 `el.parentNode.removeChild(el)` 删掉了（`zxcm-ui/src/directive/permission/hasPermi.js:21-22`）。
4. **未登录直达被拦**：退出登录后，地址栏直接访问 `http://localhost/contract/contractDraft`。预期：跳到 `http://localhost/login?redirect=%2Fcontract%2FcontractDraft`（`zxcm-ui/src/permission.js:85-92`）。
5. **刷新后动态路由重建**：在任意业务页按 F5。Network 里会重新出现 `getInfo`、`getRouters`，最终仍停留在当前路由，不会掉回首页（`zxcm-ui/src/permission.js:43-51`）。

## 五、一个操作的完整生命流程

### 5.1 【登录后，菜单怎么长出来】

```
前置：第 1 章讲完，此时 token 已在 Cookie，但 roles 为空

① 路由守卫 permission.js:43 发现 store.getters.roles.length === 0
   └─ 调 store.dispatch('GenerateRoutes')                     (permission.js:48)

② GenerateRoutes action 执行                                  (store/modules/permission.js:33)
   └─ 调 getRouters() → GET /getRouters                       (api/menu.js:4)

③ 后端返回树形菜单（示例）
   [
     { path:'/contract', component:'Layout', meta:{title:'合同管理'},
       children:[
         { path:'contractDraft', component:'contract/contractDraft/index',
           meta:{title:'合同草拟'} }, ...
       ] }
   ]
   · 注意 component 是字符串，还可能有 'Layout'/'ParentView' 关键字

④ 前端 filterAsyncRouter 遍历，把每个 component 翻译成真组件   (store/modules/permission.js:56-81)
   ├─ 'Layout'      → import Layout 组件      (:63-64)
   ├─ 'ParentView'  → import ParentView       (:65-66)
   └─ 'contract/contractDraft/index' → loadView(...) → () => import('@/views/contract/contractDraft/index')  (:70→:124-131)

⑤ 同时 filterDynamicRoutes(dynamicRoutes) 按权限过滤那 5 个静态动态路由 (store/modules/permission.js:41)
   └─ 例如有 system:user:edit 才 push /system/user-auth

⑥ 给表尾补一条「兜底 404」：{ path:'*', redirect:'/404' }       (:42)

⑦ router.addRoutes(asyncRoutes)  —— 真正把路由注册进 Vue Router   (:43)
   commit('SET_ROUTES', rewriteRoutes) → 存 Vuex                  (:44)

⑧ 左侧菜单组件读 Vuex 的 sidebarRouters，渲染出菜单树（Layout 里）
   —— 用户看到菜单「长出来」了

⑨ next({ ...to, replace:true }) 进入目标页                      (permission.js:51)
```

**答辩点**：**「菜单不是前端写的，是后端按角色查出来、前端翻译成路由的」**。`component` 字符串 ↔ `views/` 文件路径的对应关系是**前后端隐式契约**。

### 5.2 【按钮权限怎么生效】

以合同列表页的「创建合同」按钮为例（`zxcm-ui/src/views/contract/contractDraft/index.vue:76-83`，`v-hasPermi` 在 `:77`）：

```
① 页面渲染，遇到 <el-button v-hasPermi="['contract:contractDraft:add']">创建合同</el-button>

② Vue 把这个按钮 DOM 插入页面 → 触发指令的 inserted 钩子           (hasPermi.js:9)

③ 指令读 value = ['contract:contractDraft:add']
   └─ 读当前用户权限 permissions = store.getters.permissions      (hasPermi.js:12)
      （就是第 1 章 GetInfo 时存进 Vuex 的那个列表）

④ 判断：permissions 里有没有 'contract:contractDraft:add'
   ├─ 有（或权限里有超管通配 '*:*:*'）→ 什么都不做，按钮留着
   └─ 没有 → el.parentNode.removeChild(el) —— 按钮从 DOM 消失     (hasPermi.js:22)

⑤ 结果：没权限的用户，这个按钮根本不存在（不是灰掉，是没渲染出来）
```

### 5.3 【点菜单跳页面】

```
① 用户点左侧菜单「合同草拟」
   └─ 菜单项是 router-link，触发路由跳转

② 路由守卫 beforeEach 触发                                      (permission.js:14)
   ├─ NProgress.start() 顶部进度条起
   ├─ 有 token 且 roles 已加载 → 走 else 分支 next() 直接放行     (permission.js:81-83)
   └─ 加载目标页组件（懒加载：首次才下载这个页面 JS）

③ 路由 afterEach → NProgress.done()                             (permission.js:97-98)

④ 目标页渲染，created/mounted 里发自己的数据请求（如 getList）
   —— 后面几章每章都讲这个「页面自己的请求」
```

## 六、面试高频问题

**Q1：你们前端路由是怎么做的？**
A：分静态和动态两组。静态的 `constantRoutes`（登录、首页、404、在线编辑页）所有人都有；动态的由后端 `GET /getRouters` 按当前用户角色返回菜单树，前端用 `filterAsyncRouter` 把后端给的 `component` 字符串翻译成真实组件，再 `router.addRoutes` 动态注册。菜单级权限就是这么来的。

**Q2：为什么路由要用 history 模式？**
A：`router/index.js:210` 是 `mode:'history'`，URL 里没有 `#`，更美观、更像传统网站。代价是**后端必须配置**：任何前端路由的 404 都要重定向回 `index.html`，否则刷新页面会真 404。生产环境通常靠 Nginx 的 `try_files` 兜底。**坦白点**：仓库里没有附带 Nginx 配置文件，这一条属于部署侧配置；答辩时要说「部署时配置」而不是「代码里写了」。

**Q3：后端返回的 component 是字符串，前端怎么变成组件的？**
A：`loadView` 函数把字符串拼成路径动态 import：开发环境用 `require([\`@/views/${view}\`])`，生产环境用 `() => import(\`@/views/${view}\`)`（`store/modules/permission.js:124-131`）。所以后端菜单表里的 `component` 值必须和前端 `views/` 下的文件路径严格对应。另外 `Layout`/`ParentView`/`InnerLink` 是三个关键字，映射到框架壳组件。

**Q4：按钮权限怎么控制的？`v-if` 还是别的？**
A：自定义指令 `v-hasPermi`（`zxcm-ui/src/directive/permission/hasPermi.js:8-28`）。在按钮上写 `v-hasPermi="['权限码']"`，指令在 `inserted` 钩子里读 Vuex 里的用户权限，没有就把按钮 DOM 删掉。支持 `*:*:*` 超管通配。

**Q5：那用户把按钮 DOM 改出来，或者直接调接口怎么办？**
A：**前端指令只是隐藏，不防绕过**——这是体验优化，不是安全措施。真正的安全在后端，每个接口都有 `@SaCheckPermission` 注解，后端会再校验一次。这是「前端校验不可信」原则的体现。

**追问：如果后端 `@SaCheckPermission` 拒绝了请求，前端看到什么？**
A：后端返回非 200 的业务码，响应拦截器走 `Notification.error` 弹错并 reject（`zxcm-ui/src/utils/request.js:104-108`），页面不会进入 `.then` 的成功回调。

**Q6：路由守卫里为什么要 `next({ ...to, replace: true })`？**
A：因为 `router.addRoutes` 是**异步添加**路由的，添加完必须**重新导航一次**才能命中新加的路由。`{ ...to, replace:true }` 就是「重新去同一个目的地，但用 replace 不产生历史记录」，避免用户点浏览器后退卡死。源码注释里也写了这是「hack 方法」（`permission.js:51`）。

**Q7：没登录访问一个需要登录的页面会怎样？**
A：路由守卫发现没 token → 如果目标页在白名单（`/login`/`/register`/`/wxLogin` 等，`permission.js:12`）就放行，否则 `next('/login?redirect=' + to.fullPath)` 跳登录页并记住原地址，登录成功后跳回来。

**Q8：三级菜单怎么处理？**
A：`filterChildren`（`store/modules/permission.js:83-105`）专门处理三层及以上的嵌套，把父节点的 path 拼到子节点 path 前，生成完整的路由路径。对应后端返回菜单时用 `ParentView` 做中间层。

**Q9：`constantRoutes` 里为什么把 `/contractFileEdit` 这些放在静态路由？**
A：因为这些**在线文档编辑页**（第 8 章）通常从**独立浏览器窗口**打开（点「编辑文本」按钮用 `window.open` 或 `router.resolve` 开新页），走菜单不方便；而且它们不属于某个菜单树节点。放在静态路由里任何人登录后都能按需打开。

**Q10：`meta.activeMenu` 是干啥的？**
A：详情页（如 `/system/user-auth` 分配角色）不是菜单项，但它属于「用户管理」这个大菜单。`meta.activeMenu: '/system/user'` 让进入详情页时，左侧「用户管理」菜单保持**高亮**，用户不会迷失。本项目很多合同详情页都用它高亮对应的列表菜单。

### 6.1 本章答辩卡（3 组追问级问答）

**追问 1：刷新页面后动态路由会不会丢？为什么用户感觉不到？**
10 秒答案：会丢——Vuex 在内存里，刷新就清空。但守卫发现 `roles` 为空，会重新 `GetInfo`、重新 `GenerateRoutes` 并 `addRoutes`，所以用户只是多等两次请求。
证据：`zxcm-ui/src/permission.js:36-51`、`zxcm-ui/src/store/modules/permission.js:33-51`。

**追问 2：后端 `/getRouters` 已经按角色过滤过菜单了，为什么前端还要 `filterDynamicRoutes`？**
10 秒答案：因为它们过滤的不是同一批路由。后端给的是「菜单树」；`dynamicRoutes` 是前端写死的「详情页/配置页」路由（如分配角色、字典数据），不在菜单里，所以前端要再按 `permissions` 过滤一遍。
证据：`zxcm-ui/src/store/modules/permission.js:41`、`:108-122`；`zxcm-ui/src/router/index.js:135-207`。

**追问 3：按钮放在 `el-table` 的插槽里，`v-hasPermi` 为什么还能生效？**
10 秒答案：自定义指令跟元素在不在插槽里无关。表格渲染出这一行的按钮时，按钮元素照样会插入 DOM，`inserted` 钩子照样执行，没权限就删除该按钮节点。
证据：`zxcm-ui/src/directive/permission/hasPermi.js:9`、`:21-22`；按钮在表格插槽中：`zxcm-ui/src/views/contract/contractDraft/index.vue:146-153`。

## 七、选型对比

### 7.1 前端路由权限 vs 后端路由权限

| | 后端下发菜单（本项目） | 前端写死所有路由 |
|---|---|---|
| 加菜单 | 后台配，前端不用改、不用发版 | 要改前端代码重新部署 |
| 权限真相 | 唯一一份（后端库） | 前后端各写一份，易对不上 |
| 启动开销 | 多一次 `/getRouters` 请求 | 无 |
| 灵活性 | 高（可分角色动态） | 低 |

**结论**：后台管理系统选「后端下发」是行业主流（RuoYi/Vue-Admin 都是这套）。代价是启动多一次请求，收益是权限完全动态可控。

### 7.2 按钮权限：自定义指令 vs `v-if` vs 权限组件

| | `v-hasPermi` 指令（本项目） | `v-if="hasPermi('x')"` | `<Permission>` 组件 |
|---|---|---|---|
| 代码量 | 最少（一个属性） | 中（要 import 方法） | 多（要包一层标签） |
| 可读性 | 高（一看就知道是权限） | 一般 | 高 |
| 统一逻辑 | ✅（指令内部统一、带超管通配） | ❌ 每个页面自己判断 | ✅ |

**结论**：指令写法最省事、语义最清晰，还统一了「超管通配」这种边界逻辑。`v-if` 写法每个页面都要自己写判断方法，容易漏。

### 7.3 history vs hash 模式

| | history（本项目） | hash |
|---|---|---|
| URL | `example.com/contract/list` 干净 | `example.com/#/contract/list` 带 `#` |
| 后端要求 | **要配 Nginx 兜底**（`try_files ... /index.html`） | 无要求 |
| SEO | 略好 | 一般 |

**结论**：history 好看、更专业，代价是后端必须兜底。本项目是后台系统，生产部署时需要 Nginx `try_files` 之类的前端路由兜底（仓库未附 Nginx 配置，属部署侧工作）。

## 本章小结

- 路由分两组：`constantRoutes`（静态，登录/首页/404/在线编辑页）、`dynamicRoutes`（动态，要权限）。
- 菜单**不在前端写死**，由后端 `GET /getRouters` 按角色下发，前端 `loadView` 把字符串翻译成组件，`addRoutes` 动态注册。
- `component` 字符串 ↔ `views/` 文件路径是**前后端隐式契约**；`Layout`/`ParentView`/`InnerLink` 是框架壳关键字。
- 按钮权限用 `v-hasPermi` 指令：无权限就把 DOM 删掉；支持 `*:*:*` 超管通配。
- **前端权限是「隐藏」不是「防护」**，真正的安全在后端 `@SaCheckPermission`。
- 路由守卫 `next({...to, replace:true})` 是为了让 `addRoutes` 后重新导航命中新路由（框架 hack）。
