# 第 7 章 · 模板体系页面

> 模板是「合同的胚子」——一套预先做好的合同文档样式，起草合同时套用。模板体系前端有**三种状态**：**草稿 → 发布 → 停用**，对应三个文件夹。这一章讲清这三个状态下的页面，以及为什么模板目录里塞了这么多弹窗组件。

---

## 一、这部分是做什么的

合同模板有生命周期：

```
草稿(templateDrafts)  →  发布(templatePublish)  →  停用(templateStop)
  编辑/上传模板文件         对外可被合同引用          下架，不再可选
  可发布                   可创建新版本/切换版本       可重新发布
```

对应目录 `src/views/template/`：

| 页面 | 文件 | 行数 | 干什么 |
|---|---|---|---|
| **模板草稿** | `templateDrafts/index.vue` | 522 | 模板列表 + 上传模板文件 + 发布 |
| 草稿-新增/编辑弹窗 | `templateDrafts/TemplateDraftsEditDialog.vue` | 493 | 模板编辑表单 |
| 草稿-查看弹窗 | `templateDrafts/TemplateDraftsViewDialog.vue` | 283 | 只读查看 |
| 草稿-主文件上传 | `templateDrafts/fileUploadMain.vue` | 143 | 上传模板主体文件 |
| 草稿-附件上传 | `templateDrafts/fileUploadAttachment.vue` | 270 | 原设计的附件上传；**当前未被任何文件引用**（实际用 `FileUploadContract`） |
| 草稿-关联模板 | `templateDrafts/linkTemplate.vue` | 330 | 原设计的关联模板；**组件存在，但表单入口被注释** |
| **模板发布** | `templatePublish/index.vue` | 442 | 已发布模板列表 + 停用/新版本 |
| 发布-版本列表 | `templatePublish/versionList.vue` | 104 | 查看/切换版本 |
| 发布-新版本 | `templatePublish/newVersion.vue` | 76 | 创建新版本 |
| **模板停用** | `templateStop/index.vue` | 432 | 已停用模板列表 + 重新发布 |

> **零基础先补概念（前端视角）**
>
> - **弹窗组件 + `ref` 调 `show()`**：一个 `.vue` 文件可以只做成「弹窗」——模板根节点是 `<el-dialog>`，父页面把它挂在模板末尾并写 `ref="xxx"`，点按钮时执行 `this.$refs.xxx.show(row)`。模板草稿的新增/编辑弹窗就是这么用的（`zxcm-ui/src/views/template/templateDrafts/index.vue:295`、`:481-488`，弹窗方法在 `TemplateDraftsEditDialog.vue:236-245`）。原理见《Vue2 从 0 到精通》第 4 章 §9.1。
> - **版本化（前端怎么理解）**：同一个模板保留多份「快照」，每份有版本号和状态；页面不覆盖旧快照，而是新增一份。这样已经引用旧版本的合同不会悄悄变化。前端的体现是「创建新版本」弹窗只让填新版本号（`templatePublish/newVersion.vue:48-69`），「版本管理」弹窗列出所有版本并允许切换「发布中」的那一份（`templatePublish/versionList.vue:83-100`）。
> - **文件上传组件的返回值**：`fileUploadMain` 内部是 `el-upload`，上传成功后把服务器返回的对象通过 `v-model` 交回父表单；父表单提交时只取 `url/name/fileId` 三个字段（`TemplateDraftsEditDialog.vue:57-59`、`:299-301`）。上传组件本身不负责业务字段。
> - **三个页面 = 同一套列表骨架 + 不同操作**：草稿页、发布页、停用页都有搜索区 + `JTable` + 分页，差别只在操作列按钮。前端没有「发布状态」这种魔法，就是后端返回不同列表、页面显示不同按钮（`templatePublish/index.vue:200-248`、`templateStop/index.vue:206-237`）。

> 后端对应：[后端重塑版 第 7 章「模板体系」](../后端重塑版/第7章-模板体系.md)。

## 二、站在架构师角度，为什么这么设计

### 2.1 为什么模板要分「草稿 / 发布 / 停用」三个文件夹

**核心是「发布态」这个设计**：模板做好了不能马上给别人用，得先**发布**——发布后才是「正式可用」的模板。

**为什么**：
- **草稿是「正在编辑」**：随时能改，别人看不到。
- **发布是「正式可用」**：合同起草时能选到的，就是已发布的模板。发布后**不能随便改**（要改就发新版本）。
- **停用是「下架」**：不再可选，但历史引用还在。

**答辩点**：**「模板的『发布态』隔离了『编辑中』和『已上线』」**——这和代码发布的分支（develop/main）是一个思路，也和[后端重塑版 第 7 章](../后端重塑版/第7章-模板体系.md)的模板版本化设计对应。

**三个文件夹而不是一个文件夹加状态字段**，是因为**每个状态的可用操作完全不同**——草稿能「编辑/删除/发布」，发布能「停用/新版本」，停用能「重新发布」。**操作不同 → 页面不同 → 分文件夹**。这跟第 6 章「按钮状态机」是一个思路，只是模板的操作差异大到「值得分成独立页面」。

### 2.2 为什么模板草稿目录里有那么多弹窗文件

`zxcm-ui/src/views/template/templateDrafts/` 下有 **6 个 `.vue` 文件**：`index.vue` + `TemplateDraftsEditDialog` + `TemplateDraftsViewDialog` + `fileUploadMain` + `fileUploadAttachment` + `linkTemplate`。

**设计意图**：模板编辑是个**复杂操作**，本来打算按下面几块拆：
- 基本表单（名称、类型、部门使用范围）→ `TemplateDraftsEditDialog`
- **上传模板主文件**（Word/PDF）→ `fileUploadMain`
- **上传附件**→ 设计上有 `fileUploadAttachment`
- **关联其它模板**（如「主合同」关联「保密协议」）→ `linkTemplate`
- 查看 → `TemplateDraftsViewDialog`

**为什么拆成多个文件**：这是第 4 章「表单长了就拆」的**大规模应用**——文件上传有独立逻辑、独立状态，拆开比一个 1500 行的 `index.vue` 好维护。

> ⚠️ **坦白点（以源码为准）**：目前实际被挂到界面上的只有 `TemplateDraftsEditDialog`、`TemplateDraftsViewDialog` 和 `fileUploadMain`（`index.vue:295-296`；`TemplateDraftsEditDialog.vue:57-59`）。**附件上传用的是全局组件 `FileUploadContract`**（`TemplateDraftsEditDialog.vue:68-78`），`fileUploadAttachment.vue` 在全仓**没有被任何文件引用**；`linkTemplate.vue` 虽然被 import（`TemplateDraftsEditDialog.vue:140`），但它在表单里的那段模板（`:109-116`）是**注释掉的**，所以当前界面上没有「关联模板」入口。答辩时请说「设计上拆成四块，当前版本只启用主文件上传，附件改用通用上传组件，关联模板入口被注释」——不要说「关联模板功能已在线」。

**答辩点**：**「模板编辑按『表单 + 主文件 + 附件 + 关联』拆组件，但当前只启用了表单 + 主文件，另外两个是预留/遗留」**。这既体现组件化，也体现你能如实说出代码现状。

### 2.3 为什么「发布后要改」是「创建新版本」而不是「编辑」

看 `zxcm-ui/src/views/template/templatePublish/index.vue:222-246` 的「更多」下拉——里面有两项：「创建新版本」调 `addNewVersion(row)`（`:386-388`，打开 `newVersion.vue` 弹窗）和「版本管理」调 `manageVersion(row)`（`:389-391`，打开 `versionList.vue` 弹窗），**没有「编辑」**。

**为什么**：模板一旦发布，可能已经被很多合同引用了。如果直接改，那些已引用它的合同会「悄无声息地变了」。所以发布后的模板**不可直接编辑**，要改就**发新版本**——旧版本还在，新版本是新的。

**创建新版本和版本管理是两个不同弹窗**：`newVersion.vue`（76 行）只让填「新版本号」并提交 `POST /template/templatePublish/newVersion`；`versionList.vue`（104 行）列出该模板的所有版本，并把某个旧版本重新「发布」成当前版本（`changeVersion`）。创建和切换分开，是刻意的小而专。

**答辩点**：**「已发布模板不可变，改就发新版本」**——和第 5 章「合同历史不可变」、[后端重塑版 第 9 章](../后端重塑版/第9章-用印·作废·续签·归档.md)是同一条原则在不同对象上的体现。**整个系统的核心设计哲学就是「历史不可变」**。

### 2.4 为什么模板要「关联其它模板」（`linkTemplate.vue`）

一份完整的合同可能需要多个文档：「合同正文 + 保密协议 + 附件清单」。所以一个模板可以**关联其它模板**，起草时把关联的模板**一起合并**成一份文档。

**为什么**：避免重复维护——「保密协议」单独做成一个模板，被多个合同类型关联，改一处全生效。

**答辩点**：**「模板关联 = 文档组装」**——一份合同由多个模板片段拼成。这块和文档合并（第 8 章）连上了。

> ⚠️ 注意：`linkTemplate.vue` 组件存在，但当前 `TemplateDraftsEditDialog.vue:109-116` 的入口是注释状态；面试时可以说「设计支持，当前版本未启用」，不要说「线上可点」。

### 2.5 为什么有 `templatePublish/versionList.vue` 这么小的文件（104 行）

看它只有 104 行——因为它只干一件事：**显示版本列表 + 切换当前版本**。新版本（`newVersion.vue`，76 行）也只干一件事：**创建新版本**。

**为什么拆这么细**：「查看/切换版本」和「创建版本」是两个独立的小功能，各自成组件，比塞进 `index.vue` 的下拉菜单里写 200 行更清晰。**这是刻意的小而专**。

**读法**：这些是 `index.vue` 或 `TemplateDraftsEditDialog.vue` 通过 import + `ref`/`v-model` 使用的子组件。**读一个模板操作（如「上传主文件」）时，先从父组件找它怎么被调起，再进子组件看逻辑**。

**逐行读「创建新版本 / 版本管理」的分发（`templatePublish/index.vue:386-391`）**：

```js
addNewVersion(row) {
  this.$refs.newVersion.showDialog(row)
},
manageVersion(row) {
  this.$refs.versionList.show(row)
},
```

1. `addNewVersion(row)`：方法名和后端 API `addNewVersion` 同名，但这里**不是直接发请求**，只是打开弹窗。
2. `this.$refs.newVersion`：对应模板里的 `<newVersion ref="newVersion" ... />`（`index.vue:263`），也就是 `newVersion.vue` 组件实例。
3. `.showDialog(row)`：调用子组件的方法（`newVersion.vue:48-55`），把当前模板行传进去，子组件用它预填「当前版本号」。
4. `manageVersion(row)`：另一个入口，打开的是「版本管理」。
5. `this.$refs.versionList`：对应 `<versionList ref="versionList" @change="getList" />`（`index.vue:264`）。
6. `.show(row)`：子组件拉版本列表并显示弹窗（`versionList.vue:76-79`）。
7. 两个方法都**只负责打开弹窗**；真正的 POST/GET 在子组件里（`newVersion.vue:59-62`、`versionList.vue:83-88,93-97`）。这就是「父组件管入口，子组件管自己的逻辑」。

### 4.6 动手验证（在浏览器里确认模板三态和版本）

1. **看草稿列表**：进入「模板管理 → 模板草稿」，`F12` → **Network**，刷新后找到 `templateDrafts/list` 请求，Response 的 `rows` 里应有 `draftStatus`（草稿状态）和 `version`（版本号）。
2. **看新增/修改共用一个弹窗**：点「新增」和点某一行的「编辑模板」，弹窗标题分别变成「新增模板 / 修改模板」，但 DOM 里是同一个 `el-dialog`（`TemplateDraftsEditDialog.vue:236-245`）。Network 里「编辑」会先发 `GET /template/templateDrafts/{id}`。
3. **看发布接口的方法**：在草稿行点「发布模板」，Network 里该请求的 **Method 是 GET**，URL 是 `/template/templateDrafts/publish/{id}`（`zxcm-ui/src/api/template/templateDrafts.js:45-49`），不是 PUT。
4. **看两个下拉项打开不同弹窗**：进入「模板发布」页，点「更多 → 创建新版本」，出现标题「创建新版本」的窄弹窗（400px，只有版本号输入框）；点「更多 → 版本管理」，出现标题「版本管理」的宽弹窗（900px，带版本表格和「发布」按钮）。两者分别由 `newVersion.vue` 和 `versionList.vue` 渲染（`templatePublish/index.vue:263-264,386-391`）。
5. **看版本切换请求**：在版本管理弹窗里对一个非「发布中」的版本点「发布」，确认后 Network 出现 `GET /template/templatePublish/changeVersion?templateId=...`（`versionList.vue:93-97`），列表随之刷新。
6. **验证附件组件**：在「新增模板」弹窗里，「模板正文」用 `fileUploadMain`（一个输入框 + 上传按钮），「模板附件」用 `FileUploadContract`（disabled 状态）；页面上找不到 `fileUploadAttachment.vue` 的痕迹，也找不到「关联模板」表单项——这和 §2.2 的坦白点一致。

**预期**：发布/停用/切换版本三个操作在 Network 里都是 **GET**；创建新版本是 **POST**；创建和版本管理是两个不同弹窗。若菜单里看不到「模板停用」，检查当前账号的菜单权限（第 2 章）。

## 五、一个操作的完整生命流程

> 本节流程里的 `index.vue` 默认指 `zxcm-ui/src/views/template/templateDrafts/index.vue`；`templatePublish/index.vue` 指 `zxcm-ui/src/views/template/templatePublish/index.vue`；`templateStop/index.vue` 指 `zxcm-ui/src/views/template/templateStop/index.vue`。

### 5.1 【模板从草稿到发布】

```
① 进入「模板草稿」页 → getList() → GET /template/templateDrafts/list  (index.vue:379)

② 点「新增」→ handleAdd() → 打开 TemplateDraftsEditDialog          (:481)
   └─ 填模板名/类型

③ 上传模板主文件 → fileUploadMain.vue 组件
   └─ 上传后拿到文件 ID/URL 存进模板

④ （可选）上传附件 → fileUploadAttachment.vue
   （可选）关联其它模板 → linkTemplate.vue

⑤ 保存 → addTemplateDrafts(data)（POST）→ 后端存草稿

⑥ 列表里点「发布」→ publishTemplateDrafts(id)                       (:467)
   └─ GET /template/templateDrafts/publish/{id}
   └─ 后端把模板状态改为「已发布」

⑦ 模板从「草稿」页消失，出现在「发布」页
   —— 之后合同起草时能选到这个模板（第 5 章 listContractTemplate）
```

### 5.2 【发布后改模板 → 创建新版本】

```
① 在「模板发布」页，找到模板 → 「更多」下拉 → 「创建新版本」        (templatePublish/index.vue:232)
   └─ addNewVersion(row) → this.$refs.newVersion.showDialog(row)     (:386-388)

② newVersion.vue 弹出（标题「创建新版本」）                         (newVersion.vue:48-55)
   └─ 预填当前版本号，用户填新版本号

③ 点确定 → submit() → addNewVersion({ newVersion, templateId })      (:56-62)
   └─ POST /template/templatePublish/newVersion
      （api/template/templatePublish.js:20-26）

④ 成功后 $emit('goToDraft') → 父组件跳回模板草稿页                  (:67；index.vue:347-349)
   —— 因为新版本要先在草稿态编辑，再发布

关键：不能直接改已发布模板（会被已引用的合同「静默变化」），只能发新版本

补充：如果只想把某个旧版本重新设为当前版本，走「版本管理」→ versionList.vue：
   manageVersion(row) → this.$refs.versionList.show(row)             (index.vue:389-391)
   → versionList({templateCode}) 拉版本列表                          (versionList.vue:83-88)
   → 点某版本「发布」→ changeVersion({templateId})                   (:89-100)
      → $emit('change') → 父组件 getList() 刷新                      (:96；index.vue:264)
```

### 5.3 【停用模板】

```
① 「模板发布」页点「停用」                                          (:216)
   └─ stopTemplateDrafts(id) → GET /template/templatePublish/stop/{id}   (:428-430)

② 模板从「发布」页消失，出现在「停用」页
   └─ 合同起草时不再能选到它（后端 listContractTemplate 过滤）

③ 若要恢复：在「停用」页点「重新发布」
   └─ rePublishTemplateDrafts(id) → GET /template/templateStop/rePublish/{id}
      （templateStop/index.vue:422-429）
```

## 六、面试高频问题

**Q1：模板有哪几种状态？**
A：草稿、发布、停用。草稿是编辑中（可改可删可发布），发布是正式可用（合同能引用，改要发新版本），停用是下架（不可选，可重新发布）。前端分三个文件夹 `templateDrafts` / `templatePublish` / `templateStop`。

**Q2：为什么模板要「发布」这一步，不能直接可用？**
A：发布态隔离了「编辑中」和「已上线」。草稿随便改不影响别人；发布后的模板可能已被合同引用，不能随便变。这是「历史不可变」原则在模板上的应用。

**Q3：为什么模板草稿目录里有 6 个文件？**
A：模板编辑拆分了——主表单（`TemplateDraftsEditDialog`）、查看（`ViewDialog`）、主文件上传（`fileUploadMain`）、附件上传（`fileUploadAttachment`）、关联模板（`linkTemplate`）各是一个组件。因为文件上传有独立逻辑和状态，拆开比塞一个大文件好维护。**但要如实补充**：当前实际启用的只有主表单、查看、主文件上传；附件改用通用 `FileUploadContract`，`fileUploadAttachment.vue` 没被引用；`linkTemplate.vue` 的入口被注释（`TemplateDraftsEditDialog.vue:109-116`）。

**Q4：已发布的模板要改怎么办？**
A：不能直接改，要「创建新版本」（`zxcm-ui/src/api/template/templatePublish.js:20-26` 的 `addNewVersion`）。因为已发布模板可能被很多合同引用了，直接改会让那些合同「静默变化」。新版本是新的，旧版本还在。

**Q5：模板的「关联模板」是干啥的？**
A：设计意图是：一份完整合同可能由多个文档组成（正文+保密协议+附件），通过 `linkTemplate.vue` 让一个模板关联其它模板，起草时一起合并，避免重复维护。**当前版本该入口在 `TemplateDraftsEditDialog.vue:109-116` 被注释，组件代码还在但线上不可点**；后端字段 `linkTemplateArray` 仍会被提交（`:304`）。回答时要把「设计」和「当前启用状态」分开说。

**Q6：模板列表的「发布」按钮做了什么？**
A：`publishTemplateDrafts(id)`（`zxcm-ui/src/views/template/templateDrafts/index.vue:467`）→ **`GET`** `/template/templateDrafts/publish/{id}`（`zxcm-ui/src/api/template/templateDrafts.js:45-49`），后端把状态改成已发布。之后模板从草稿页移到发布页。注意这个接口是 GET，不是 PUT/POST。

**Q7：模板版本列表（versionList）为什么单独一个小文件？**
A：`versionList.vue` 只有 104 行，只做「显示版本 + 切换版本」。因为「查看/切换版本」是独立小功能，单独成组件比写在 `index.vue` 下拉里 200 行更清晰。**刻意的「小而专」。**

**Q8：合同的模板是怎么选到的？**
A：合同起草页按合同类型调 `GET /template/templateDrafts/getLoginerCanUseTemplate`（`zxcm-ui/src/api/contract/contractDraft.js:13-19` 的 `listContractTemplate`），后端只返回**当前用户能用 + 已发布**的模板（第 5 章 §4.2、`:433`）。
**追问：停用的模板还能被选到吗？** 答：不能。停用后模板从发布列表消失，`getLoginerCanUseTemplate` 的后端过滤也不会再返回它（前端这一侧只负责传合同类型）；想恢复要在停用页点「重新发布」（`templateStop/index.vue:422-429`）。

**Q9：模板文件存在哪？**
A：上传后存对象存储（OSS/MinIO），模板记录里存文件 ID/URL。上传走 `fileUploadMain.vue` 等组件。具体存储机制看[后端重塑版 第 5 章](../后端重塑版/第5章-合同草拟.md)的文件存储部分。

**Q10：三个模板页面（草稿/发布/停用）代码是不是重复了？**
A：结构相似（都是列表），但**操作按钮不同**：草稿有发布、发布有停用+新版本+版本管理、停用有重新发布+重新编辑。所以是「同一骨架 + 不同操作」，不是纯粹重复。共用的列表骨架可以进一步抽象，但当前是分开写的——**这是一个可优化点**。

### 本章答辩卡（追问级）

**卡 1：「创建新版本」和「版本管理」是同一个弹窗吗？各自干什么？**
10 秒答案：不是。创建新版本打开 `newVersion.vue`，只填新版本号，提交 `POST /template/templatePublish/newVersion`，成功后跳回草稿页编辑；版本管理打开 `versionList.vue`，列出所有版本，把某个旧版本重新发布成当前版本（`changeVersion`）。
证据：`zxcm-ui/src/views/template/templatePublish/index.vue:263-264,386-391`；`newVersion.vue:56-69`；`versionList.vue:83-100`。

**卡 2：模板发布接口用的什么 HTTP 方法？为什么容易答错？**
10 秒答案：发布是 **GET** `/template/templateDrafts/publish/{id}`；在这几个版本操作里，停用、重新发布、切换版本也都是 GET，只有「创建新版本」是 POST。容易答错是因为这些操作都「像写操作」，但项目把它们写成了 GET。
证据：`zxcm-ui/src/api/template/templateDrafts.js:45-49`；`templatePublish.js:12-16,20-26,38-43`；`templateStop.js:12-16`。

**卡 3：模板编辑弹窗里的附件和关联模板，实际用的是哪套组件？**
10 秒答案：附件用全局 `FileUploadContract`（`:68-78`），不是目录里的 `fileUploadAttachment.vue`（未被引用）；关联模板 `linkTemplate.vue` 虽然 import 了，但表单入口被注释（`:109-116`），当前不可用。
证据：`zxcm-ui/src/views/template/templateDrafts/TemplateDraftsEditDialog.vue:57-78,109-116,138-152`。

## 七、选型对比

### 7.1 分文件夹（三态）vs 一个页面切状态

| | 三个文件夹（本项目） | 一个页面 + 状态 tab |
|---|---|---|
| 操作差异 | 各页只放自己的操作 | 要在一个页面塞所有操作 |
| 可读性 | 高（一眼知道这个状态能干吗） | 低（按钮混在一起） |
| 路由 | 三个菜单项 | 一个菜单项 |

**结论**：当「不同状态的操作差异很大」时，分页面更清晰。模板正好是这样。如果差异小，一个页面切 tab 更省。

### 7.2 弹窗拆多个组件 vs 一个大弹窗

| | 拆开（本项目） | 一个大弹窗 |
|---|---|---|
| 文件大小 | 各 140-490 行 | 一个 1500+ 行 |
| 复用 | 上传组件可复用 | 难复用 |
| 通信 | props/emit | 无 |

**结论**：涉及**文件上传**这种重逻辑时，拆组件更好（上传组件别处也能用）。模板草稿就是这么做的。

### 7.3 已发布模板：直接改 vs 版本化

| | 版本化（本项目） | 直接改 |
|---|---|---|
| 引用安全 | ✅ 旧引用不变 | ❌ 旧引用被静默改 |
| 存储 | 存多份 | 一份 |
| 复杂度 | 高（要管版本） | 低 |

**结论**：模板会被合同引用，直接改有「历史被篡改」风险。**版本化是正确选择**，代价是要管理版本。这和合同本身「创建新版本」是一致的思路。

## 本章小结

- 模板三态：**草稿 → 发布 → 停用**，三个文件夹 `templateDrafts` / `templatePublish` / `templateStop`。
- **发布态隔离「编辑中」和「已上线」**；发布后要改就「创建新版本」（`addNewVersion`），不改原版。
- 模板草稿拆成 6 个文件：主表单 / 查看 / 主文件上传 / 附件上传 / 关联模板——**组件化拆分的典型**。但当前实际启用的是前三个；附件改用 `FileUploadContract`，`fileUploadAttachment.vue` 未被引用，`linkTemplate.vue` 入口被注释。
- 「关联模板」的设计意图是文档组装（正文 + 保密协议 + 附件），当前版本未启用（见 §2.2 坦白点）。
- 模板被合同引用时，通过 `GET /template/templateDrafts/getLoginerCanUseTemplate` 只返回「已发布 + 当前用户可用」的。
- **优化空间**：三个模板页结构相似但操作不同，是「同骨架不同操作」，有进一步抽象空间。
