### 3.1 ★ M4 的表设计四条规律（面试前必背）

**① 用印为什么单独一套表，而不是在合同表加字段**

因为**一家公司有多个印章**（公章、合同专用章、法人章、财务章），每个章有**保管人**和**使用记录**：
- `contract_seal` —— 印章 / 申请本体
- `contract_seal_notes` —— **用印流水**（谁、何时、给哪份合同、用了哪个章）

> 🎯 **「notes」这张流水表是关键**：用印是**不可撤销的法律行为**，出事要追溯责任。
> **它和 M2 的 `contract_point_log` 是同一类东西 —— 不可篡改的事件流水。**

**② 作废为什么用多个列（宽表冗余）**

[[D0-底座表地图#6. contract_draft 合同草稿表（04 行 253）|`contract_draft`]] 上和作废有关的列有 **两个真正被写** + 一个概念列：

| 列 | 实测是否被 `cancelContract` 写 |
|---|---|
| `CONTRACT_STATUS='2'` | ✅ 写（用于**列表过滤**"显示所有已作废"）|
| `CONTRACT_CANCEL_REMARK` | ✅ 写（存原因，用于追责）|
| `CONTRACT_CANCEL` | ❌ **不写**（前端控制按钮显隐的布尔位，open-source 流程没回填）|

> 🎯 面试问「为什么不用一个状态字段」→ 答：「**查询性能 + 前端判断简单，代价是冗余和不一致风险**，
> 所以配套了事件日志（`contract_point_log`）作为对账依据。」
> **注意结构：先说好处，再说代价，最后说怎么兜底。** 只讲好处会被追问到死。

**③ 续签为什么不在原合同上改**

```
续签的完整语义 = 新建一份 contract_draft + 用 RELATED_CONTRACT_ID 指向原合同
```

因为原合同已经签署、已经履行过、可能已经归档——它是有法律效力的**既成事实，不能动**。`contract_draft` 上为此准备了一组列：`RELATED_CONTRACT_ID` / `_NAME` / `_CODE`（关联到哪份合同）、`RELATED_TYPE`（关联类型）、`RENEWAL` / `RENEWAL_TEXT`（是否续签）、`renewed_status`（续约状态）。

> ⚠️ **但开源版只实现了「延期」那一半**：后端 `renew` 接口**只改原合同的 `END_TIME`**，**不建新合同、不写 `RELATED_CONTRACT_ID`**；「新建合同 + 关联」的语义在前端一个**没接线**的方法里（`createContract.vue:renew`）。讲设计意图时可以说「续签应当不改原合同」，但别声称「这个项目的续签新建了合同」。

> 🏆 **「历史不可变」这条规律在 M4 里出现第 3 次了**：**作废不删、模板不就地改、续签不原地改**。面试时把这一条作为**整个系统的设计哲学**讲出来，比讲十个 CRUD 都有说服力。

**④ 报表为什么单独一个 Mapper（概念上）**

`ContractDraftStatMapper` 的设计意图是**统计 SQL 单独一个 Mapper**：
业务 SQL 查明细、统计 SQL 做聚合（`COUNT`/`SUM`/`GROUP BY`），**按变化原因分离** —— 优化报表不影响业务。

| | 业务 SQL（`ContractDraftMapper`） | 统计 SQL（`ContractDraftStatMapper`） |
|---|---|---|
| 查什么 | 具体合同记录（列多） | 聚合结果（`COUNT`/`SUM`/`GROUP BY`） |
| 有没有索引 | 有（`CONTRACT_STATUS` 等） | 全表扫是常态 |
| 用在哪 | 页面列表 | 报表页 |
| 怎么优化 | 加索引 | 加缓存 / 预计算 / 物化视图 |

> 📌 这条规律在 M2 也出现过一次（Activiti 的 `ACT_RU_*` 和 `ACT_HI_*` 按生命周期分表）。**「按变化原因分离」是贯穿整个系统的第二条主线**（第一条是「历史不可变」）。

> ⚠️ **但实测有个"名不副实"**：`ContractBookController` **走的是 `ContractDraftMapper.bookPage` / `bookList`**，
> **不是 `ContractDraftStatMapper`**。`ContractDraftStatMapper` 里大多是**注释掉的** SQL + 一堆争议/案件统计。
> **面试时讲"设计意图"没问题，但别说"这个报表用的是 StatMapper"——会被读过代码的人戳穿。**

### 3.3 架构视角：收尾功能为什么长在主表上

- **只新建 1 张表**（`conf_archives`）：用印时间、双章文件 id、作废原因、关联合同这些字段和合同同生命周期，放主表查询最省事；拆「合同收尾表」只会多一次 join。
- **归档卷必须独立**：一个卷装多份合同，是 N:1，而且归档案模块维护，不是合同的私有数据。
- **台账不是表**：它是 `contract_draft` 按状态过滤出来的视图，建物理表就会有一致性问题。
- **用印流水不可篡改**：`contract_seal_notes` 和 `contract_point_log` 同类，是追责依据，只增不改。
- **作废用宽表冗余**：`CONTRACT_STATUS='2'` + `CONTRACT_CANCEL_REMARK` 是真写的，`CONTRACT_CANCEL` 是前端控制位、流程里没回填——**冗余的代价是不一致，兜底靠事件日志**。
- **两张表根本不存在**：`contract_borrow`、`contract_archives_file` 是商业版裁剪遗留，别去脚本里找。

## 四、T1~T4 逐个怎么做

### T1 · 用印申请 + 上传双章合同（A 类）★★

**做什么**：审批通过 → 线下盖章 → 把带双章的正式合同**传回系统** → 合同进入"履行中"。

> 🔴 **一句话认清开源版的"用印"**：**没有电子签章**。系统管的是「流程 + 留痕」，
> **盖章是线下做的**，系统只负责「接收盖好的文件 + 推进状态」。

**`uploadSealContract` 的真实行为**（`ContractAuditServiceImpl:942-1048`）：

```
① 校验 fileGroupsId 非空 → 否则「合同的文件不能为空」
② 查合同；状态必须是以下三者之一，否则「当前合同未审批通过，不能上传双章合同」：
     · approved      = 状态 '3'(审批中) + APPROVE_STATUS='2'(审批通过)
     · signing       = 状态 '4'(待签署)
     · reviewFailed  = 状态 '5'(已签署) + REVIEW_STATUS='5'(复核失败)
③ 生效时间必传；END_TIME_TYPE='fixed' 必须有截止时间；'open'（无固定期限）忽略截止时间
④ 双章文件里必须有一个正文（type='0'）→ 否则「必须选择一个合同作为双章正文」
⑤ 把上传的文件存成一条独立的「双章文件记录」：
     contractDraftFilesService.insertByBo(fileType = FILE_TYPE_SEAL('2'))
   → 文件表 `contract_draft_files` 新增一组，合同只需记住这组的 id（回填 `SEAL_FILES_ID`）
⑥ 回填负责人 / 生效时间 / 截止时间
⑦ 一次性推进三个状态（★ 核心）：
     CONTRACT_STAMPED_STATUS = '2'  (签署完成)
     CONTRACT_STAMPED_TIME   = now
     CONTRACT_REVIEW_STATUS  = '6'  (复核通过)
     CONTRACT_STATUS         = '6'  (履行中 / fulfil)     ← ★ 不是 '5'
⑧ 更新审批单节点为「履行中 / 合同负责人」
⑨ 发通知「用印完成」给拟稿人
⑩ 发三个事件：uploadSeal / sealPass / reviewPass   ← 事件日志由此记录
```

### T3 · 合同续签（B 类）★★ —— 坑在「两套实现」

**做什么**：快到期 → 延长截止时间。

> ⚠️ **这是 M4 最"分裂"的地方：续签有两套实现，而且都不是完整闭环。**

**实现 A（后端，能跑）**：`ContractAuditController.renew`（`L328-344`）

```
renewInfo:  取原合同 END_TIME → +1 年 → 返回给前端预填
renew:      校验 newEndTime 非空、不早于 EFFECTIVE_TIME
            → draft.setEndTime(newEndTime); contractDraftMapper.updateById(draft)
            → 结束
```

> 🔴 **它只做一件事：改 `END_TIME`。**
> **不建新合同、不改状态、不写 `RELATED_CONTRACT_ID`、不写 `RENEWAL`。**
> 概览篇说的"新建一份合同"在这条链上**完全不存在**。
> 而且 **前端 `api/contract/contractAudit.js` 里没有 `renew` / `renewInfo` 函数** → 这两个接口**没有前端调用者**。

**实现 B（前端，语义正确但没接线）**：`createContract.vue:332` 的 `renew(row)`

```js
renew(row) {
  this.isRenew = true;
  this.form.relatedContractId = row.id;          // ← 这才是"关联原合同"
  this.form.relatedContractName = row.contractName;
  this.oldContract = row;
  this.getTemplate(...)                          // ← 走正常的"新建合同"流程，生成新合同
}
```

> 🔴 **它才是概览篇描述的语义**（新建合同 + `relatedContractId` 指向原合同）。
> **但没有任何地方调用它**（没有按钮绑定、没有父组件引用）→ **定义了却接不上**。

| 实现 | 语义 | 状态 |
|---|---|---|
| 后端 `renew` 接口 | **延长原合同** `END_TIME` | 能跑，但**前后端没接线** |
| 前端 `createContract.renew(row)` | **新建合同 + 关联原合同** | 语义对，**但没有调用者** |

> 💡 **面试怎么讲**：这是一个「**同一业务两套实现、都没打通**」的真实案例 ——
> **说明这功能在开源版是"砍到一半"的**。你可以说：「续签的完整语义是『新合同 + 关联字段』，
> 答案册里前端方法体现了这个语义，但没接上；后端的 `renew` 只做了『延期』这一半。」

✅ **验证（后端实现）**

```sql
SELECT ID, CONTRACT_CODE, END_TIME FROM contract_draft WHERE ID='<合同ID>';
-- 调 /renew 后 END_TIME 变了；CONTRACT_STATUS 不变（★ 别期待新合同）
```

## 六、技术栈 + 面试高频题

### 技术清单

| 技术 | 在 M4 里干什么 | 关键点 |
|---|---|---|
| **文件组（fileGroup）** | 双章文件以"一组 JSON + 一条文件记录"存 | `FILE_TYPE_SEAL='2'` 区分正文/审批件/双章件 |
| **easypoi** | 报表导出 Excel | `ExcelBuilder`；依赖在 `zxcm-third/zxcm-excel` |
| **MyBatis-Plus 原生 SQL** | 报表聚合查询 | ⚠️ `ContractDraftMapper` 里**大写表名**要改 |
| **事件发布** | 用印/复核/作废都发 `ContractEvent` | 由 M2 的 `ContractPointLogServiceImpl` 落成事件日志 |
| **状态机（枚举）** | `ContractStatusEnums` 等 | `'6'` 是履行中，**不是复核状态** |

### ★ Q1：合同审批通过之后到归档，整个流程是什么？

> **答法**：「审批通过（`'3'`/`'4'`）→ **上传双章合同**（线下盖章后传回）→ 系统一步把
> **用印状态置『签署完成』、复核置『通过』、合同状态置『履行中 `'6'`』** →
> 之后可以**作废（`'2'`）**、**续期（延 `END_TIME`）**、到期后**关闭（`'8'`）**或**归档**。
> **用印这一步在开源版是"自动完成"的**：传双章文件时直接用代码跳过复核节点。」

### ★ Q2：为什么用印要单独一套表？（M4 招牌题）

> **答法**：「因为**一家公司有多个印章**，每个章有**保管人**、有**使用记录**。
> 我把『印章/申请本体』和『用印流水』分成两张表 —— **流水表 `contract_seal_notes` 是关键**：
> **用印是不可撤销的法律行为**，出事要能查到『这个章是谁、何时、盖在哪份合同上』。
> **它和审批事件日志 `contract_point_log` 是同一类东西：不可篡改的事件流水。**」

### ★ Q3：这份数据为什么"加字段"而不是"改状态"？（宽表冗余）

> **答法**：「比如作废，我在 `contract_draft` 上既有状态位（`CONTRACT_STATUS='2'` 用于列表过滤），
> 又有原因列（`CONTRACT_CANCEL_REMARK` 用于追责）。
> **好处是查询快、前端判断直白；代价是冗余和潜在不一致**，所以配了事件日志做对账。
> **这是一次『用空间换查询性能』的取舍**，不是设计失误。」
> ⚠️ 注意：**`CONTRACT_CANCEL` 那一列在开源流程里其实没被写** —— 提"宽表"时别说死三列都同步。

### ★ Q4：续签为什么不在原合同上改？

> **答法**：「因为原合同**已经签署、已经履行过、可能已经归档** —— 它是有法律效力的**既成事实，不能动**。
> **续签的正确语义是『新建一份合同 + 用关联字段指向原合同』**。
> ⚠️ 但要诚实：**这个项目的开源版里，续签只实现了『延期』那一半**（改 `END_TIME`），
> 新建合同的语义在前端代码里但没接上 —— **我在读源码时发现了这个『两套实现都没打通』的情况**。」
> 这个"主动指出半成品"的答法，比假装功能完整更专业。

### Q5：你读 M4 的源码发现了什么问题？

| 现象 | 定性 |
|---|---|
| `ContractDraftMapper.bookPage/bookList` 用**大写表名** | **真 bug**（本机 `lower_case_table_names=0` 必挂）|

## 九、这个模块里的坑

| # | 现象 | 真因 |
|---|---|---|
| 1 | 合同报表页 500 `Table 'zxcm.CONTRACT_DRAFT' doesn't exist` | **`bookPage`/`bookList` 大写表名**（8.3，本机必炸）|
| 2 | 上传双章后状态是 `'6'` 不是 `'5'` | **正常**。开源流程直接进"履行中"，概览篇写错了 |
| 3 | `contract_seal` / `contract_review` 表里没有数据 | **正常**。主流程**不写**这三张表，用印+复核被合并成一步自动完成 |
| 4 | 哪里都找不到「借阅管理」「归档管理」页面/接口 | **它本来就不存在**（C 类），不是你没找到 |
| 5 | 上传双章 403 | 权限码是 `contract:contractDraft:uploadStampedContract`，**不是 `:edit`** |
| 6 | 申请用印报「该合同不可作废」/ 状态不对 | 合同必须**审批通过**（`'3'`+`APPROVE_STATUS='2'`、`'4'`、或复核失败重传）。先走完 M2 |
| 7 | 调 `/renew` 没生成新合同 | **正常**。后端 `renew` 只改 `END_TIME`；新建合同语义在前端**没接线**的方法里 |
| 8 | `contract_archives_file` / `contract_borrow` 建表语句找不到 | **答案册里就没有**，T5 要自己设计 |
| 9 | 报表导出中文乱码 / 格式错 | easypoi 导出链路的编码问题；`ContractBookController` 手写 `CellStyle`/`Font` |
| 10 | 复用了归档 Service 的裸 SQL 后报大写表名 | `ContractArchivesFileServiceImpl:402/442` 的 `CONTRACT_SEAL_NOTES` 要改小写 |
| 11 | 调 `/renew` 直接 500（不是业务中文提示）| `renew` 里用 `draft.getEffectiveTime().getTime()` 比时间——**原合同 `EFFECTIVE_TIME` 为空时 NPE**，走不到「合同截止时间不能小于合同开始时间」那句 |
| 12 | 合同关闭 / 状态 `8`、中止 `7` 找不到入口 | `closeContract`（置 `'8'`）和 `applySign`（续约设置）**只有 Service、没有 Controller/页面**；`'7'` 中止全项目没人写 |
| 13 | 报表查询很慢 | 统计 SQL 没有索引。加 `CONTRACT_STATUS` / `CREATE_TIME` 索引，或加缓存 |
| 14 | `getSeal` 返回空列表 | `contract_seal` 表里没有印章数据——**要先在「用印管理」里配印章**，而那个页面也是 C 类（不存在）。可以先手动往 `contract_seal` 插一条 |
| 15 | 上传双章报「必须选择一个合同作为双章正文」 | 双章文件里必须有一个 `type='0'` 的正文文件 |
| 16 | 上传双章报「合同截止时间不能为空」 | 合同是固定期限（`END_TIME_TYPE='fixed'`）就必须填截止时间；无固定期限用 `'open'` 时会**忽略**你传的截止时间 |

## 十、★ 你没考虑周全的地方

### A. 「历史不可变」——M4 里第 3 次出现（★ 面试的"哲学题"）

**事实**：**作废不删（置 `'2'`）、模板不就地改（开新版本）、续签不动原合同（本应新建）** ——
三处都在说同一件事：**已经产生法律/业务效力的记录，只能追加、不能覆盖。**

**Why 重要**：这不是三个孤立的实现，是**贯穿整个系统的设计哲学**。面试时把这一条**作为系统级判断讲出来**，
比讲十个 CRUD 都有说服力。

**How to apply（面试怎么讲）**：
- **识别**：「这个系统对『已生效数据』一律**不可变**。」
- **举证**：「作废加状态位不删行、模板改内容开新版本、续签想要新合同 —— 都是这个原则。」
- **讲代价**：「**代价是数据只能长、不能减**，所以要靠**归档**和**事件日志**来管理体量。」

### B. M4 暴露的「商业版裁剪」痕迹（★ 很值得讲）

**事实**：M4 是**裁剪最不干净**的一章 ——
`contract_borrow` / `contract_archives_file` **有 Java 无表**；`contract_seal` / `contract_review` **有表无写方**；
`getSeal` **空壳**、`renew` **半截**、`createContract.renew` **无调用者**。

**Why 重要**：说明这个开源版是**从商业版"切"出来的**，**切面没对齐**（源码切了 SQL 没切、或反过来）。
**这对求职者是有用的信息**：你要能**区分"我配错了"和"项目本身就没做"** —— 否则会白折腾半天。

**How to apply（面试怎么讲）**：
- **识别**：「我判断这是**开源版裁剪留下的**，不是环境问题 —— 因为有 Java 无表、有表无写方，是典型的裁剪不对齐。」
- **态度**：「发现后我没去硬补，而是**核对齐全套 91 张表 + 全项目 Controller 引用**，确认它真的没实现。」
- **升华**：「**读代码要能判断"这是残缺还是我漏了"** —— 靠交叉验证（表 ↔ 实体 ↔ Mapper ↔ Controller）。」

### C. M4 特有的两个提醒

| # | 问题 | 为什么重要 |
|---|---|---|
| 1 | **先验环境连通性，再验报表** | 报表依赖 `contract_audit_form` + `conf_archives` 的多表 JOIN，**任一表没建/大写表名都会 500**，且报错在 SQL 层，不直观 |
| 2 | **`CONTRACT_STATUS='6'`（履行中）是 M4 的"新常态"** | 传双章后合同就进 `'6'`。后续作废/关闭/归档都以 `'6'` 为起点 —— **别拿 `'5'` 去找合同** |

## 🎤 怎么对面试官讲

> 面试官问 M4，按「用印是法律行为 → 宽表取舍 → 历史不可变 → 会辨残缺」四句讲：
>
> 「M4 是审批**通过之后**的事：上传双章、作废、续签、报表。
> **用印**我单独一套表（`contract_seal` + `contract_seal_notes`），因为一家公司有**多个印章**、各有保管人；用印是**不可撤销的法律行为**，所以流水表**只增不改**，出事能查到『谁、何时、盖在哪份合同上』——它和审批的 `contract_point_log` 是同一类：不可篡改的事件流水。
> **作废**我用状态位（`CONTRACT_STATUS='2'`，便于列表过滤）+ 原因列（`CONTRACT_CANCEL_REMARK`，便于追责），这是**用空间换查询性能的宽表取舍**，代价是冗余、可能不一致。
> 贯穿全系统的原则是『**历史不可变**』：**作废不删、模板开新版本、续签本应新建合同而不是改原合同**。
> 我也能诚实指出开源版的残缺：`contract_borrow` **有代码没表**、`contract_seal` **有表没写方**、`renew` **只做了延期这一半** —— **能分清『是我配错了』还是『项目本来就没做』**，靠的是交叉验证（表 ↔ 实体 ↔ Mapper ↔ Controller）。」

## 🔎 本模块「账本」：被问「这功能用到哪些表 / 谁做的 / 为什么」就背这里

> **一句话口径**：M4 的表要**分成「存在」和「不存在」两类** —— 存量的（用印 / 报表）是**原作者设计**；**归档 / 借阅那两张表答案册直接裁掉了，是「要你自己设计」的**（作品集里**唯一能说「我设计的表」**的地方）。
> 字段级详解在 [D0 · 数据库表地图](../D0-底座表地图.md)（**同一主题只深讲一处**）。

**① 数据：用到了哪些表**

| 表 | 在本模块里的角色 | 谁设计的 / 谁建的 | 为什么这么设计（一句话）|
|---|---|---|---|
| **`contract_seal`** · `contract_seal_notes` | **用印**（★ 存量）| **肇新原作者**（`04-biz-tables.sql`）| ⚠️ **有表、但「谁写入」是缺的**（有表没写方）—— 这是可讲的残缺 |
| `contract_audit_form` · `contract_point_log` · `contract_review` | 审批单 / 事件流水 / 审阅 | 肇新原作者 | M2 建好、M4 复用 |
| `contract_draft` · [[D0-底座表地图#8. contract_draft_files 合同文件表（04 行 370）|`contract_draft_files`]] | 合同 / 文件 | 肇新原作者 | 作废 / 续签**改这里**（但原则是**历史不可变**）|
| `conf_archives`（13 列，0 行）| 归档元数据 | 肇新原作者（C 类）| 归档的存量半张表 |
| ~~**`contract_borrow`**~~ · ~~`contract_archives_file`~~ | **★ 借阅 / 归档文件** | **表「不存在」→ 要你自己设计** | 答案册**有 Java（Service 一整套）却没建表** → **T5 加分项：这是全项目唯一「不是复制、要你设计」的部分**，含金量最高 |

**② 组件：用到了哪些中间件 / 框架**

| 组件 | 谁做的 | 你这一站真正用到哪一步 | 为什么用它（面试答法）|
|---|---|---|---|
| **报表查询（多 Mapper）** | 原作者 | 报表走**独立 Mapper**（查询与写入分离）| 报表是只读重查询，和业务 CRUD 分开更清晰 |
| **文件存储组件** | 你部署 / 配置的中间件 | 双章图片 / 归档文件落存储 | 详见 [D4-存储与缓存链路](../D4-存储与缓存链路.md) |
| **⚠️ netty（误用）** | 开源库（**被误引**）| 代码里引了 netty 做不该做的事 | 这是「依赖误用」，**主动指出它** = code review 能力 |
| **（无 Redis / MQ 新增）** | — | 本站**没引入新的中间件** | 难点在**业务规则（历史不可变）**，不在中间件 |

> ✅ **面试标准答**：**用印 / 报表表是原作者设计（且部分残缺）**；**归档 / 借阅的 `contract_borrow` 表要你自己设计**（全项目唯一原创点）；核心讲 **「历史不可变」原则** + **诚实区分「我配错了」和「项目本来没做」**。
