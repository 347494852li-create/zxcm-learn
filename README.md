## 0. 这份手册怎么用

你的工作方式是**以「小目标」为单位**，不是一页一页读代码：

```
选一个小目标（某个页面能用 / 某个中间件搭起来）
        ↓
按任务卡的「复制清单」从答案册复制文件
        ↓
跑起来（三条验证：接口 / 页面 / 数据）
        ↓
读任务卡的「原理」一栏，能对面试官讲出来 —— 达标
```

所以每个**任务卡**固定给四样东西：

| 栏目      | 内容                              |
| ------- | ------------------------------- |
| 🎯 目标   | 这个小目标做完，什么能用                    |
| 🖥 前端入口 | 菜单在哪个一级目录下、路由是什么、对应哪个 `.vue` 文件 |
| 🔌 接口入口 | HTTP 方法和 URL，权限码是什么             |
| 📋 复制清单 | 答案册路径 → 本项目路径，逐条列               |
| ▶️ 操作步骤 | 照着敲就行，含命令                       |
| ✅ 跑通验证  | 接口 / 页面 / SQL 三查，全过才算完          |
| 🧠 原理   | 为什么这么写、底层发生了什么                  |

**记住这条主链**（M1→M4 就是沿着它走）：

```
签约主体 + 合作方 + 编号规则 + 合同类型     ← M1 前置：基础数据
        ↓
   合同草拟（写合同，选模板，生成文件）      ← M1 + M3
        ↓
      提交审批 → 审批流节点流转            ← M2
        ↓
   审批通过 → 申请用印 → 上传双章合同 → 作废/续签  ← M4
        ↓
        合同报表 + 事件日志（全程留痕）      ← M4
```

## 4. 每次开始前：环境检查

中间件在虚拟机 `192.168.56.10` 上，**虚拟机默认是关机的**，先确认它开着。

```bash
# ① 虚拟机通不通（不通就是没开机，去开 VMware）
ping -n 2 192.168.56.10

# ② 中间件在不在（能出 200 说明 MySQL+Redis+Web 都活着）
curl -s -o /dev/null -w "%{http_code}\n" http://localhost:8080/captchaImage

# ③ 前端在不在
curl -s -o /dev/null -w "%{http_code}\n" http://localhost
```

| 检查 | 通的样子 | 不通怎么办 |
|---|---|---|
| ① | 有回包 | 去开 VMware，别动 `my.ini` |
| ② | `200` | 看 IDEA 控制台有没有报错 |
| ③ | `200` | 到 `zxcm-learn/zxcm-ui` 下 `npm run dev`（**先 `$env:PATH = "E:\nvm\v24.9.0;$env:PATH"`**） |

### 6.2 完整版：只在重建整个环境时用

| 脚本 | 干什么 | 什么时候跑 |

```bash
cd "E:/Develop/project/zxcm-learn/script/sql"
for f in 02-biz-menu.sql 03-missing-base-tables.sql 04-biz-tables.sql; do

done
```

> ⚠️ `04` 是 `DROP TABLE IF EXISTS` + `CREATE`，**重跑会清空这 25 张表的数据**。日常按章推进时不要用它，用 `modules/`。

```sql
SELECT COUNT(*) FROM sys_menu;                    -- 预期 170
```

**跑完菜单脚本要重新登录**（菜单和权限码走 Redis 缓存，不重登不生效）。

| 阶段 | 表数 | 构成 |
|---|---|---|
| M0 · 跑完 01 + 启动后端 | **50** | 26 框架 + 24 Activiti |
