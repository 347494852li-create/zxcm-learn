# 第 3 章 · 实例选项与生命周期

> **这一章解决什么问题**：模板里的数据、方法、计算值、监听逻辑，全部来自 `<script>` 里那个大对象。这一章把这几个选项分别管什么、什么时候执行、彼此怎么配合讲清楚。
>
> **学完标准**：打开任意一个 `.vue` 的 `<script>`，你能一眼分出 `data`、`computed`、`watch`、`methods`、生命周期钩子；能说清「页面一打开，哪些代码按什么顺序跑」；能读懂分页组件里那段 `get/set`。

---

## 一、一个组件实例长什么样

每个 `.vue` 文件的 `<script>` 最后都导出一个对象：

```js
export default {
  name: 'Position',        // 组件名
  components: { Form },    // 局部注册的子组件
  props: { ... },          // 父组件传进来的数据
  data() { return { ... } },// 自己的数据
  computed: { ... },       // 计算属性
  watch: { ... },          // 侦听器
  created() { ... },       // 生命周期钩子
  mounted() { ... },
  methods: { ... }         // 自己的方法
}
```

这个对象就是**组件实例的说明书**。Vue 创建组件时，会按照它把实例装配起来。

项目里 `src/views/system/position/index.vue:158-183`：

```js
export default {
  components: { Form, Selector },
  dicts: ['PO_TYPE'],
  data() {
    return {
      treeData: [],
      tableData: [],
      params: { ... },
      total: 0,
      formVisible: false
    }
  }
}
```

> `dicts` 不是 Vue 自带的选项，是本项目安装的字典插件提供的（第 7 章讲插件时再说）。读代码时先把它当成「声明这个页面要用哪些字典」。

### 1.1 选项分三类

| 类别 | 选项 | 作用 |
|---|---|---|
| **数据** | `data`、`props`、`computed` | 提供模板要显示的值 |
| **行为** | `methods`、`watch`、生命周期钩子 | 处理事件、响应变化、在特定时机执行 |
| **装配** | `components`、`directives`、`mixins`、`name` | 告诉 Vue 这个组件由什么组成 |

本章讲数据和行为，装配部分放到第 4 章。

## 二、`data`：组件自己的数据

### 2.1 基本规则

```js
data() {
  return {
    count: 0,
    list: [],
    form: {}
  }
}
```

三条规则：

1. **必须是函数**，返回一个对象。原因第 1 章 §七讲过：组件会复用多份，函数保证每份数据互相独立。
2. **要用到的数据必须在这里先声明**。没声明的属性，后面临时加，Vue 不一定能感知（§九 详说）。
3. 模板里直接写名字就能用：`data` 里的 `count`，模板里写 `{{ count }}`，不用 `this.count`。

### 2.2 项目里的 `data`

`src/views/conf/billRule/index.vue:192-264` 是一个比较完整的 `data`：

| 字段 | 作用 |
|---|---|
| `billRuleList` | 所有编号规则，渲染成上方一排 tab |
| `currentData` | 当前选中的那条规则，下面表单绑它 |
| `queryParams` | 查询条件 + 分页参数 |
| `rules` | 表单校验规则 |
| `open`、`loading`、`total` | 弹窗开关、加载状态、总条数 |

在模板里 `{{ currentData.code }}`（`:23`）能直接用，就是因为 `currentData` 在 `data` 里声明过。

### 2.3 为什么查询条件里常写 `undefined`

`billRule/index.vue:219-230` 的 `queryParams` 里有多个 `undefined`。

`undefined` 表示「这个条件用户没填」。发请求时（第 7 章会讲请求参数处理），`undefined` 的字段会被丢掉，后端就收不到它——正好等于「不按这个条件过滤」。

如果写成空字符串 `''`，它会被当成一个真实参数发出去，可能变成 `where code = ''` 这种错误条件。

## 三、`methods`：组件自己的方法

### 3.1 定义与调用

```js
methods: {
  handleAddEdit(id) {
    this.formVisible = true
  }
}
```

- 模板里：`@click="handleAddEdit(scope.row.id)"`；
- 方法里调用另一个方法：`this.handleAddEdit(id)`；
- 访问数据：`this.formVisible`。

方法里的 `this` 指向**当前组件实例**，所以 `this.xxx` 能拿到 `data`、`computed`、其它 `methods`。

### 3.2 不要用箭头函数定义 methods

```js
// 错：this 不是组件实例
methods: {
  handleAddEdit: (id) => {
    this.formVisible = true   // this 指向外面，拿不到 data
  }
}
```

箭头函数没有自己的 `this`（第 0 章 §5.5）。`methods` 里请用普通函数简写。

> 反过来说，**回调里**要用箭头函数保住 `this`：
> ```js
> getList() {
>   listBillRule(this.queryParams).then((response) => {
>     this.billRuleList = response.rows   // 箭头函数继承 methods 里的 this
>   })
> }
> ```
> 项目里所有 `.then` 回调几乎都这么写（`billRule/index.vue:293`、`position/index.vue:193`）。

### 3.3 项目例子

`position/index.vue:227-231`：

```js
handleNodeClick(data) {
  if (this.params.organizeId === data.id) return
  this.params.organizeId = data.id
  this.type = data.type
  this.reset()
}
```

点左侧组织树 → 更新查询条件 → 调 `reset()` 重新查列表。方法之间靠 `this.` 串联。

## 四、`computed`：计算属性

### 4.1 它解决什么问题

模板里经常需要「由已有数据算出来的值」：

```html
<span>{{ firstName + ' ' + lastName }}</span>
```

这样写能跑，但有两个问题：

1. 表达式一长，模板就难读；
2. 模板重新渲染时会重新算，哪怕 `firstName`、`lastName` 根本没变。

`computed` 把这段计算抽出来，并且**缓存结果**：

```js
computed: {
  fullName() {
    return this.firstName + ' ' + this.lastName
  }
}
```

```html
<span>{{ fullName }}</span>
```

### 4.2 缓存是什么意思

- `fullName` 依赖 `firstName` 和 `lastName`；
- 这两个值不变，`fullName` 就**直接返回上次的结果**，不会重复执行；
- 其中任何一个变了，Vue 才重新计算。

对比一下 `methods`：`{{ getFullName() }}` 每次重新渲染都会执行一遍。所以「纯计算、不产生副作用」的值优先用 `computed`。

### 4.3 只读写法（最常见）

```js
computed: {
  values() {
    // ...
    return this.value.split(',')
  }
}
```

`src/components/DictTag/index.vue:39-47` 就是这种：把 `value` 字符串按逗号拆成数组，供模板判断「当前值在不在字典选项里」。

`src/layout/components/AppMain.vue:14-17`：

```js
computed: {
  cachedViews() {
    return this.$store.state.tagsView.cachedViews
  }
}
```

从 Vuex 里取「需要缓存的页面列表」。Vuex 状态一变，这个计算属性自动更新（第 6 章讲 Vuex）。

### 4.4 `get` / `set` 写法：分页组件为什么要这么写

`src/components/Pagination/index.vue:68-85`：

```js
computed: {
  currentPage: {
    get() {
      return this.page
    },
    set(val) {
      this.$emit('update:page', val)
    }
  },
  pageSize: {
    get() {
      return this.limit
    },
    set(val) {
      this.$emit('update:limit', val)
    }
  }
}
```

先看模板 `:5-6`：

```html
<el-pagination
  :current-page.sync="currentPage"
  :page-size.sync="pageSize"
/>
```

`.sync` 的意思是：把这个 prop 和父组件的数据双向同步。它展开后大致是：

```html
:current-page="currentPage"
@update:current-page="currentPage = $event"
```

于是当用户在页码框里输入「3」时：

```
Element UI 想改 current-page
  → 执行 currentPage 的 set(3)
  → set 里 this.$emit('update:page', 3)
  → 父组件上的 :page.sync="params.pageNum" 收到事件
  → params.pageNum = 3
  → get() 重新读到 this.page === 3
  → 分页条显示第 3 页
```

**为什么不能直接改 `this.page = val`？**

因为 `page` 是 `props`。Vue 的硬规则：**子组件不能直接改父组件传进来的 prop**。数据只能由父组件改，子组件通过 `$emit` 通知父组件「我想改成多少」。这个 get/set 就是「读的时候拿 prop，写的时候发事件」的桥。

> 这一段把 `computed`、`props`、`$emit`、`.sync` 串在了一起。第 4 章讲组件通信时会再完整拆一遍，现在只要理解：**计算属性不一定是「算」，也可以是「包装一个值，让读写走不同路径」。**

### 4.5 `computed` vs `methods`

| | `computed` | `methods` |
|---|---|---|
| 调用方式 | `{{ fullName }}`，不加括号 | `{{ getFullName() }}`，加括号 |
| 缓存 | 有，依赖不变不重算 | 无，每次渲染都执行 |
| 适合 | 由数据派生出的值 | 事件处理、发请求、有副作用的操作 |
| 能否传参 | 不能（要传参就用 methods） | 能 |

## 五、`watch`：侦听器

### 5.1 它解决什么问题

`computed` 负责「**算出一个值**」，`watch` 负责「**某个值变了以后做一件事**」——发请求、操作 DOM、存缓存、打日志。

```js
watch: {
  keyword(newVal, oldVal) {
    console.log('关键词从', oldVal, '变成', newVal)
  }
}
```

注意：`watch` 里的函数**不 return 值**，它是「变化发生时执行的动作」。

### 5.2 完整写法：`handler` + `immediate` + `deep`

```js
watch: {
  form: {
    handler(newVal) {
      console.log('form 变了', newVal)
    },
    immediate: true,   // 组件创建时立刻先执行一次
    deep: true         // 对象内部的属性变化也监听
  }
}
```

- `immediate: true`：不等变化，创建时就先跑一次；
- `deep: true`：默认只监听「对象引用有没有被换掉」，加了才监听内部属性。对象很大时慎用，有性能开销。

### 5.3 项目例子一：登录页监听 `$route`

`src/views/login.vue:181-188`：

```js
watch: {
  $route: {
    handler: function(route) {
      this.redirect = route.query && route.query.redirect
    },
    immediate: true
  }
}
```

作用：从 URL 的查询参数里取出「登录成功后要跳回哪」。

比如未登录时访问 `/system/position?redirect=%2Fsystem%2Fposition`，被路由守卫踢到登录页。登录页把 `redirect` 存下来，登录成功后跳回去，而不是一律跳首页。

- `$route` 是 Vue Router 注入的全局属性（第 5 章），用 `watch` 就能监听路由变化；
- `immediate: true` 是因为进入登录页时路由**没有发生变化**，不加就永远不会执行第一次，`redirect` 会是空。

### 5.4 项目例子二：用户页监听部门名

`src/views/system/user/index.vue:702-706`：

```js
watch: {
  // 根据名称筛选部门树
  deptName(val) {
    this.$refs.tree.filter(val)
  }
}
```

用户在输入框里打字 → `v-model` 更新 `deptName` → `watch` 触发 → 调用树组件的 `filter` 方法做本地过滤。

这里是典型的「值变了要**执行一个动作**（操作另一个组件）」，用 `watch`，不能用 `computed`。

### 5.5 项目例子三：监听来自 Vuex 的计算属性

`src/views/index.vue:147-157`：

```js
watch: {
  showNum(newVal, oldVal) {
    if (newVal) {
      this.updateShowNum()
    }
  }
},
computed: {
  showNum() {
    return this.$store.state.user.showNum
  }
}
```

`watch` 也可以监听 `computed`。Vuex 里的 `showNum` 一变，计算属性跟着变，`watch` 就被触发。

### 5.6 `computed` 还是 `watch`？

判断标准一句话：

> **要一个「值」→ `computed`；要执行「一件事」→ `watch`。**

| 场景 | 选什么 |
|---|---|
| 根据 `firstName`、`lastName` 拼出全名 | `computed` |
| 根据 `list` 算出「已选中几条」 | `computed` |
| 关键词变了就去请求后端 | `watch` |
| 路由变了就重置表单 | `watch` |
| 从 Vuex 取一个值显示 | `computed` |
| 登录状态变成 true 后弹一个提示 | `watch` |

## 六、`filters` 过滤器：Vue 2 有，但本项目不用

### 6.1 语法

Vue 2 支持过滤器，用于「显示前做一次格式化」：

```html
<!-- 局部过滤器 -->
{{ price | formatPrice }}
<span :title="price | formatPrice">...</span>

<script>
export default {
  filters: {
    formatPrice(value) {
      return '¥' + Number(value).toFixed(2)
    }
  }
}
</script>
```

多个过滤器可以串联：`{{ time | toDate | short }}`。

### 6.2 本项目的真实情况（坦白点）

在本项目 `src/` 下搜索 `filters:`，**一处都没有**。项目没有使用过滤器，而是用两种替代方式：

**方式一：全局方法**。`src/main.js:121`：

```js
Vue.prototype.parseTime = parseTime
```

挂到 `Vue.prototype` 上的方法，任何组件的 `this` 都能访问，模板里也能直接调：

`src/views/contract/contractAudit/auditList.vue:294`：

```html
<span>{{ parseTime(scope.row.effectiveTime, "{y}-{m}-{d}") }}</span>
```

**方式二：组件自己的 methods**。

所以读本项目时，看到 `{{ parseTime(...) }}` 不要找 `filters`，去 `main.js` 找 `Vue.prototype.parseTime`。

> 面试可能问过滤器，需要知道语法；但项目答辩时不要说「本项目用过滤器做日期格式化」，要说「项目用挂载在 `Vue.prototype` 上的 `parseTime` 方法」，这也是 Vue 3 移除 filters 后更通用的写法。

## 七、生命周期：组件从生到死的 10 个钩子

### 7.1 一句话理解

组件也要经历「创建 → 挂载到页面 → 数据更新 → 卸载」几个阶段。Vue 在每个阶段前后留了回调函数，叫**生命周期钩子**。你把这些函数写进组件选项，Vue 到点自动调用。

### 7.2 完整表格

| 钩子 | 什么时候执行 | 此时能干什么 | DOM 可用吗 |
|---|---|---|---|
| `beforeCreate` | 实例刚创建，数据还没初始化 | 很少用 | 否 |
| `created` | 数据、方法、计算属性都初始化完 | **发请求拿数据**、初始化非 DOM 状态 | 否 |
| `beforeMount` | 模板编译好，还没插入页面 | 很少用 | 否 |
| `mounted` | 组件已插入页面 | **操作 DOM**、初始化需要 DOM 的第三方库 | 是 |
| `beforeUpdate` | 数据变了，DOM 还没更新 | 更新前记录状态 | 是（旧 DOM） |
| `updated` | 数据变了，DOM 也更新完 | 更新后操作 DOM（慎用，容易死循环） | 是 |
| `beforeDestroy` | 实例销毁前 | **清理定时器、解绑事件、销毁第三方实例** | 是 |
| `destroyed` | 实例已销毁 | 收尾 | 否 |
| `activated` | 被 `keep-alive` 缓存的组件**重新显示** | 刷新数据、恢复状态 | 是 |
| `deactivated` | 被 `keep-alive` 缓存的组件**被切走** | 暂停定时器、保存状态 | 是 |

最常用的四个：**`created`、`mounted`、`beforeDestroy`、`activated`**。

### 7.3 `created`：项目里拉数据的主战场

项目里列表页几乎都在 `created` 里发第一次请求。

`src/views/conf/billRule/index.vue:265-267`：

```js
created() {
  this.getList()
}
```

`src/views/system/position/index.vue:185-187`：

```js
created() {
  this.getTreeselect()
}
```

`src/views/login.vue:189-193`：

```js
created() {
  this.getCode()
  this.getCookie()
  this.$store.dispatch('settings/getCompanyConfig')
}
```

**为什么放 `created` 而不是 `mounted`？**

- 拉数据不需要 DOM，`created` 时就能做；
- `created` 比 `mounted` 早，能早一点发请求，少等一帧；
- 这时候 `data`、`methods` 都已就绪，`this.getList()` 可以放心调。

### 7.4 `mounted`：只有需要 DOM 时才用

`src/components/Screenfull/index.vue:17-22`：

```js
mounted() {
  this.init()
},
beforeDestroy() {
  this.destroy()
},
methods: {
  init() {
    if (screenfull.isEnabled) {
      screenfull.on('change', this.change)   // 注册全屏状态监听
    }
  },
  destroy() {
    if (screenfull.isEnabled) {
      screenfull.off('change', this.change)  // 解绑
    }
  }
}
```

全屏库要操作真实的浏览器 DOM 和事件，所以放 `mounted`。

**为什么还要 `beforeDestroy`？**

`screenfull.on('change', this.change)` 是往全局事件上挂了一个回调。组件销毁了但回调还挂着，就会：

- 内存泄漏（组件实例被全局事件引用，回收不掉）；
- 组件已经没了，回调还在跑，可能报错。

所以「**注册了什么，就在 `beforeDestroy` 里解绑什么**」：定时器 `clearInterval`、事件 `off/removeEventListener`、第三方实例 `destroy()`。

> 这是面试高频点：「组件销毁时要做哪些清理？」答案就是这一条。

### 7.5 `updated` 为什么慎用

在 `updated` 里改数据 → 触发下一次更新 → 又进 `updated` → 无限循环。确实要在更新后操作 DOM，先想清楚条件和出口，或者用 `$nextTick`（§八）。

### 7.6 `activated` / `deactivated`：配合 `keep-alive`

`src/layout/components/AppMain.vue:3-6`：

```html
<keep-alive :include="cachedViews">
  <router-view :key="key" />
</keep-alive>
```

`keep-alive` 会把匹配的页面组件**缓存起来**，切走时不销毁，切回来时直接复用（保留滚动位置、表单内容、已加载的数据）。

被缓存的组件，切走时触发 `deactivated`，切回来时触发 `activated`，而 `created`/`mounted` 不会再次执行。

`src/views/tool/gen/index.vue:237-244`：

```js
activated() {
  const time = this.$route.query.t
  if (time != null && time != this.uniqueId) {
    this.uniqueId = time
    this.queryParams.pageNum = Number(this.$route.query.pageNum)
    this.getList()
  }
}
```

从代码生成页跳到编辑页再返回时，利用 `activated` 判断「是不是需要刷新」，需要就重新拉一次列表。

**一个容易踩的点**：`include` 里放的是**组件的 `name`**，不是文件路径。而 `tagsView` 存进 `cachedViews` 的是路由的 `name`（`src/store/modules/tagsView.js:16-18`），所以两边要对得上。

本项目多数页面在 `export default` 里写了 `name`，例如 `billRule/index.vue:180` 的 `name: 'BillRule'`；而 `position/index.vue:158-160` **没有写 `name`**，所以它实际不会被 `keep-alive` 缓存。读代码时这是个值得留意的真实细节。

### 7.7 父子组件的执行顺序（面试常问）

```html
<parent>
  <child />
</parent>
```

首次渲染顺序：

```
父 beforeCreate
父 created
父 beforeMount
  子 beforeCreate
  子 created
  子 beforeMount
  子 mounted
父 mounted
```

规律：**父组件先「准备」，子组件先「完成」**。所以父组件的 `mounted` 里可以放心访问子组件（`this.$refs.child`），因为此时子组件已经挂载好了。

销毁顺序则反过来：父 `beforeDestroy` → 子 `beforeDestroy` → 子 `destroyed` → 父 `destroyed`。

### 7.8 自己跑一遍：把顺序打印出来

新建一个 HTML，直接打开控制台看输出：

```html
<div id="app">
  <child />
</div>

<script src="https://cdn.jsdelivr.net/npm/vue@2.6.12/dist/vue.js"></script>
<script>
```

## 八、`$refs` 与 `$nextTick`：生命周期的两个搭档

### 8.1 `$refs`：拿到子组件或 DOM 元素

模板里给元素/组件起个名字：

```html
<Form ref="Form" />
```

脚本里就能直接访问：

```js
this.$refs.Form
```

`src/views/system/position/index.vue:147`：

```html
<Form v-if="formVisible" ref="Form" @refreshDataList="initData" />
```

`:233-241`：

```js
handleAddEdit(id) {
  this.formVisible = true
  this.$nextTick(() => {
    this.$refs.Form.init(
      id,
      this.params.organizeId
    )
  })
}
```

三个要点：

1. `$refs` 不是响应式的，不要在模板里依赖它；
2. **元素/组件渲染出来之后才有值**。`created` 里 `this.$refs.Form` 是 `undefined`，`mounted` 后才有；
3. 配合 `v-if` 时，条件为假时组件根本不存在，`$refs` 也是 `undefined`。

### 8.2 `$nextTick`：等 DOM 更新完再干活

Vue 更新 DOM 是**异步**的：你改了数据，Vue 不会立刻改 DOM，而是先把这一轮所有数据变化收集起来，等当前代码执行完，再统一更新一次（第 10 章讲原理）。

所以：

```js
this.formVisible = true
this.$refs.Form.init()   // 错：此时 <Form> 还没渲染出来
```

正确写法：

```js
this.formVisible = true
this.$nextTick(() => {
  this.$refs.Form.init()  // 等 DOM 更新完，Form 已存在
})
```

`$nextTick(callback)` 的含义：**把我这个回调排到「这次 DOM 更新完成之后」执行**。

`src/views/system/position/Form.vue:144-163` 里还有一次同样的用法：

```js
init(id, organizeId) {
  this.visible = true
  this.dataForm.id = id || ''
  this.formLoading = true
  this.$nextTick(() => {
    this.$refs['dataForm'].resetFields()   // 等弹窗里的表单渲染出来再重置
    treeselect({status:'0'}).then((response) => {
      this.treeData = response.data
    })
    // ...
  })
}
```

**记忆口诀**：**「先改数据，等 `$nextTick`，再碰 DOM / 子组件。」**

### 8.3 什么情况需要 `$nextTick`

| 场景 | 是否需要 |
|---|---|
| 改数据后立刻读 DOM | 需要 |
| 显示弹窗后立刻操作弹窗里的表单/树/表格 | 需要 |
| 发请求、改普通数据 | 不需要 |
| `mounted` 里操作自己的 DOM | 不需要（此时已挂载） |

### 8.4 完整案例：生命周期顺序与 `$nextTick`

## 九、响应式的两个坑（本章先认识）

第 10 章会讲 `Object.defineProperty` 的原理，这里先记住**怎么用不出错**。

### 9.1 坑一：给对象新增属性

```js
// data 里声明的是 { name: '张三' }
this.user.age = 20        // 页面不会更新！
```

Vue 2 在初始化时把已有属性逐个改造成响应式，**后来新增的属性没有被改造**。

解法：

```js
this.$set(this.user, 'age', 20)
// 或
Vue.set(this.user, 'age', 20)
```

### 9.2 坑二：用下标改数组

```js
this.list[0] = '新值'     // 页面不会更新！
```

解法：

```js
this.$set(this.list, 0, '新值')
this.list.splice(0, 1, '新值')
```

`push`、`pop`、`shift`、`unshift`、`splice`、`sort`、`reverse` 这些数组方法 Vue 2 做了拦截，可以正常触发更新；`list[0] = x` 和 `list.length = 0` 不行。

### 9.3 项目里的写法

项目里的常见做法是**整体替换**或**用会被拦截的方法**：

```js
this.tableData = res.rows                       // 整体替换（position/index.vue:206）
this.billRuleList = response.rows               // billRule/index.vue:294
this.currentData.ruleArray.splice(index, 1)     // 删除一行（billRule/index.vue:288）
```

整体替换是最省心的：引用变了，Vue 一定知道。

> 所以读项目时看到 `this.xxx = ...` 不要觉得「每次都重新赋值很浪费」，这是在保证响应式可靠。
