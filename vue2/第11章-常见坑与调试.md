# 第 11 章 · 常见坑与调试

> **这一章解决什么问题**：前面十章讲的是「应该怎么写」。真实开发里更多时间花在「为什么它不按我想的来」。这一章收集 **30 个高频坑**，每个都按「现象 → 根因 → 修法 → 项目里的例子」讲，再配一套**调试方法论**，让你遇到新问题也能自己定位。
>
> **学完标准**：看到控制台报错，能判断是数据问题、模板问题、组件通信问题还是请求问题；能熟练用 Console / Network / Vue Devtools / Sources 四件套；能把这一章的坑和项目真实代码对上号。

---

## 一、先建立排查顺序

遇到「页面不对」，按下面的顺序查，命中率最高：

```
1. Console 有没有红字？（报错第一现场）
      ↓
2. Network 请求发了吗？URL/参数/响应对不对？
      ↓
3. Vue Devtools 里组件 data 对不对？Vuex 对不对？
      ↓
4. 数据和模板的绑定关系对不对？（v-if / v-for / prop / 事件）
      ↓
5. 时序问题？（DOM 还没渲染 / 接口还没回来）
```

**不要一上来就改代码。** 先用这五步把问题缩小到「数据错」「渲染错」「时序错」「请求错」四类之一，再动手。

## 二、数据与响应式（坑 1~6）

### 坑 1：组件 `data` 写成了对象

**现象**：控制台警告 `The "data" property must be a function that returns a per-instance value in component definitions.`；多个实例共用一份数据。

```js
// 错
export default { data: { count: 0 } }

// 对
export default { data() { return { count: 0 } } }
```

**根因**：组件会被复用/创建多个实例。如果 `data` 是对象，所有实例引用同一个对象；函数每次调用返回新对象，才能每个实例独立。

**例外**：`new Vue({ data: {...} })` 根实例可以写对象，因为它只会有一个。

**项目**：所有 `.vue` 文件都是 `data() { return {...} }`，例如 `position/index.vue:161-183`。

---

### 坑 2：改了数据，页面没变

**现象**：`this.obj.newKey = 1`、`this.arr[0] = x`、`delete this.obj.key` 之后，Devtools 里数据变了，页面不动。

**根因**：第 10 章 §2.4 讲的响应式边界。

**修法**：

```js
// 新增属性
this.$set(this.obj, 'newKey', 1)
// 删除属性
this.$delete(this.obj, 'key')
// 改数组某一项
this.$set(this.arr, 0, x)
// 或
this.arr.splice(0, 1, x)
```

**项目**：

- `utils/dict/Dict.js:35-36,78` 用 `Vue.set` 给字典对象加键；
- `billRule/index.vue:282-289` 用 `push`/`splice` 增删动态行。

---

### 坑 3：直接修改 prop

**现象**：控制台警告 `Avoid mutating a prop directly since the value will be overwritten whenever the parent component re-renders.`

```js
// 子组件
props: ['visible'],
methods: { close() { this.visible = false } }   // 错
```

**根因**：props 是父组件的数据，子组件只有读权。子组件改了，父组件下一次渲染又会覆盖回去，数据流就乱了。

**修法**：

```js
// 子组件
this.$emit('update:visible', false)

// 父组件
<my-dialog :visible.sync="show" />
```

`.sync` 就是 `:visible` + `@update:visible` 的语法糖（第 4 章 §6）。

**项目**：`position/Form.vue:6` 的 `:visible.sync="visible"`——`visible` 实际是子组件自己的 data，`el-dialog` 通过 `update:visible` 改它；这是「组件 v-model 风格」，不是直接改父组件 prop。

---

### 坑 4：`Cannot read properties of undefined (reading 'xxx')`

**现象**：页面白屏，Console 报访问 `undefined.xxx`。

```html
<!-- user 初始是 null / undefined -->
<div>{{ user.name }}</div>
```

**根因**：接口还没回来，或接口没返回这个字段，模板已经去读嵌套属性。

**修法**：

1. 初始值给完整结构：

```js
data() {
  return { user: { name: '', dept: { name: '' } } }
}
```

2. 模板加保护：

```html
<div v-if="user">{{ user.name }}</div>
<div>{{ user && user.name }}</div>
```

3. 列表接口判空：

```js
if (response.rows && response.rows.length) {
  this.currentData = response.rows[0]
}
```

**项目反面教材**：`billRule/index.vue:296-297` 直接取 `response.rows[0].code`，无数据时就会触发这个错误（第 9 章 §2.7）。

---

### 坑 5：引用共享，改弹窗把列表也改了

**现象**：打开修改弹窗，表单里一改，背后的列表也立刻变；取消后列表数据已经脏了。

```js
// 错：直接把表格行对象给表单
this.form = row

// 对：浅拷贝（字段都是基本类型时够用）
this.form = { ...row }

// 嵌套对象/数组用深拷贝
this.form = JSON.parse(JSON.stringify(row))
```

**根因**：对象是引用类型，`this.form = row` 让两个变量指向同一个对象。

**项目**：`billRule/index.vue:272` 的 `this.currentData = this.billRuleList[i]` 就是引用共享。因为页面上没有列表展示，暂时无害；如果以后加列表预览就会出问题。

---

### 坑 6：`this` 不是组件实例

**现象**：`Cannot read properties of undefined (reading 'xxx')`，或改了数据没反应。

```js
// 错 1：methods 用箭头函数
methods: {
  getList: () => {
    this.loading = true   // this 不是组件
  }
}

// 错 2：回调里丢了 this
setTimeout(function() {
  this.loading = false   // this 是 window/undefined
}, 1000)
```

**根因**：箭头函数不绑定自己的 `this`，会沿外层作用域找；`function` 回调里的 `this` 取决于调用方式。

**修法**：

```js
// 方法用普通函数
methods: { getList() { ... } }

// 回调用箭头函数（继承外层 this）
setTimeout(() => { this.loading = false }, 1000)

// 或提前保存
const that = this
```

**项目**：大量 `.then((res) => { this.xxx = ... })` 都用箭头函数，就是为了让 `this` 指向组件（例如 `position/index.vue:203-209`）。

## 三、模板与组件（坑 7~13）

### 坑 7：`v-if` 和 `v-show` 用错

| | `v-if` | `v-show` |
|---|---|---|
| 本质 | 销毁/重建 DOM 与组件 | 切 `display: none` |
| 初始开销 | 条件为假时不渲染 | 总是渲染 |
| 切换开销 | 大（重建） | 小 |
| 适合 | 弹窗、权限块、不常切换 | 频繁切换的 Tab/面板 |

**项目**：弹窗一律 `v-if`（`position/index.vue:147-148`），因为不打开时没必要创建；`el-tabs` 内容用 `v-show` 风格（Element 内部）。权限按钮用 `v-hasPermi` 直接移除 DOM，比 `v-show` 更彻底。

**坑**：`v-if` 内用了 `ref`，条件为假时 `this.$refs.x` 是 `undefined`。

---

### 坑 8：`v-for` 的 key 重复或不存在

**现象**：控制台 `Duplicate keys detected: 'undefined'. This may cause an update error.`；列表重排后输入框内容串位。

```html
<!-- 错：item 没有 value 字段 -->
<div v-for="(item, index) in list" :key="item.value">

<!-- 对 -->
<div v-for="item in list" :key="item.id">
```

**根因**：第 10 章 §3.3。key 是 diff 判断「同一个节点」的依据。

**项目**：`billRule/index.vue:50` 就是 `:key="item.value"`，而规则项只有 `type`/`string`，属于真实错误（第 9 章 §2.7）。

---

### 坑 9：`v-for` 和 `v-if` 写在同一个元素上

```html
<!-- 不推荐：Vue 2 里 v-for 优先级更高，等于先循环再判断 -->
<li v-for="item in list" v-if="item.show">{{ item.name }}</li>
```

**问题**：每次渲染都要遍历全部再过滤，浪费；而且语义容易误读。

**修法**：先过滤，再渲染：

```js
computed: {
  visibleList() { return this.list.filter(item => item.show) }
}
```

```html
<li v-for="item in visibleList" :key="item.id">{{ item.name }}</li>
```

> 注：Vue 3 里 `v-if` 优先级更高，行为和 Vue 2 相反；这也是面试常问的版本差异。

---

### 坑 10：监听组件事件没反应，缺 `.native`

```html
<!-- 监听 el-input 的原生 keyup：无效 -->
<el-input @keyup.enter="search" />

<!-- 正确 -->
<el-input @keyup.enter.native="search" />
```

**根因**：组件上的 `@xxx` 默认监听**组件 `$emit` 的自定义事件**。原生 DOM 事件要加 `.native` 才会绑到根元素上。

**项目**：`position/index.vue:37` 的 `@keyup.enter.native="search"`、`:128` 的 `@click.native`（`el-dropdown-item` 没有对外 click 事件）。

**反例**：`el-button @click` 能直接工作，是因为 `el-button` 内部把点击 `$emit` 成了 `click`（Element 的约定），不是 Vue 自动帮你的。

---

### 坑 11：插槽写法混用

Vue 2.6 同时支持旧写法和新写法：

```html
<!-- 旧：具名插槽 -->
<template slot="footer">...</template>

<!-- 新：v-slot（2.6+） -->
<template v-slot:footer>...</template>

<!-- 旧：作用域插槽 -->
<template slot-scope="scope">...</template>

<!-- 新 -->
<template v-slot:default="scope">...</template>
```

**坑**：同一个组件里不要混用，否则容易报 `Duplicate slot names` 或插槽不渲染。项目整体是旧写法（`position/index.vue:108`、`Form.vue:57`），照抄即可。

---

### 坑 12：`this.$refs.xxx` 是 `undefined`

**三种常见原因**：

1. **元素/组件还没渲染**（在 `v-if` 为假时，或数据刚改还没更新 DOM）；
2. **ref 写在 `v-for` 里**：`this.$refs.item` 是**数组**，不是单个元素；
3. **在 `created` 里访问**：此时 DOM 还没挂载。

**修法**：

```js
this.visible = true
this.$nextTick(() => {
  this.$refs.form.init()
})
```

**项目**：`position/index.vue:233-241`、`Form.vue:148-149` 都是这个套路。

---

### 坑 13：组件没有 `name`，`keep-alive` 失效

**现象**：页签切走再切回，`created` 又执行了一次；或递归组件报 `max stack size exceeded`。

**根因**：`keep-alive` 的 `include` 匹配的是**组件选项里的 `name`**，不是路由 name，也不是文件名。

**项目**：`position/index.vue:158-160` 的导出对象没有 `name`，所以即使页签存在也不会被缓存；`billRule/index.vue:180` 有 `name: 'BillRule'`，可以被缓存。详见第 10 章 §5.3。

## 四、生命周期与时序（坑 14~17）

### 坑 14：在 `created` 里操作 DOM

**现象**：`this.$refs.xxx` 是 `undefined`，或 `document.querySelector` 拿不到元素。

**根因**：`created` 时模板还没渲染成 DOM；`mounted` 才有。

**修法**：DOM 操作放 `mounted`；数据请求放 `created` 即可（越早越好）。

**项目**：`Screenfull/index.vue` 在 `mounted` 里初始化全屏监听（`mounted:17-19`），`beforeDestroy` 清理（`:20-22`）。

---

### 坑 15：改了数据立刻读 DOM，读到旧值

```js
this.show = true
const h = this.$refs.box.offsetHeight   // 旧值 / undefined

this.$nextTick(() => {
  const h2 = this.$refs.box.offsetHeight // 新值
})
```

**根因**：Vue 的 DOM 更新是异步批量的（第 10 章 §4）。

**修法**：`$nextTick` 或 `await this.$nextTick()`。

---

### 坑 16：事件监听/定时器没清理

**现象**：组件销毁后仍报错、重复触发、内存泄漏。

```js
mounted() {
  window.addEventListener('resize', this.onResize)
  this.timer = setInterval(this.poll, 5000)
},
beforeDestroy() {
  window.removeEventListener('resize', this.onResize)
  clearInterval(this.timer)
}
```

**项目**：`layout/mixin/ResizeHandler.js:14-19` 是标准示范；`components/Screenfull/index.vue:17-22` 同理。

**keep-alive 注意**：被缓存的组件不会执行 `beforeDestroy`，如果希望离开时暂停，要放在 `deactivated`。

---

### 坑 17：缓存页第二次进入不刷新

**现象**：第一次进入看到最新数据，切走再回来还是旧数据；`created` 不再执行。

**根因**：`keep-alive` 复用了组件实例，`created` 只执行一次。

**修法**：

1. 在 `activated` 里按需刷新：

```js
activated() {
  if (this.needRefresh) this.getList()
}
```

2. 或使用项目的 `/redirect` 刷新套路（第 5 章 §7.3）：先 `delCachedView`，再跳 `/redirect`。

**项目**：`tool/gen/index.vue:237-244` 用路由 query 里的时间戳判断是否刷新。

---

## 五、路由（坑 18~22）

### 坑 18：`query` 和 `params` 用混

```js
// query：拼在 URL 上，刷新还在
this.$router.push({ path: '/contract/draft', query: { id: 1 } })
// URL: /contract/draft?id=1
// 读：this.$route.query.id

// params：命名路由才有，刷新会丢（除非写进 path）
this.$router.push({ name: 'DraftDetail', params: { id: 1 } })
// 读：this.$route.params.id
```

**结论**：需要刷新后保留的参数用 `query`；`params` 适合不落 URL 的临时状态。

**项目**：`tool/gen/index.vue:324` 用 `query` 传 `pageNum`；动态路由 `router/index.js:185-190` 的 `params` 用在路径参数上。

---

### 坑 19：history 模式刷新 404

**现象**：从首页点进 `/system/position` 正常，直接刷新或在新标签页打开就 404。

**根因**：`mode: 'history'`（`router/index.js:210`）去掉了 `#`，刷新时浏览器请求的是服务器上的真实路径 `/system/position`，Nginx/后端没有这个文件。

**修法**：服务器把所有非静态资源请求回退到 `index.html`：

```nginx
location / {
  try_files $uri $uri/ /index.html;
}
```

开发环境由 webpack devServer 的 `historyApiFallback` 处理，所以本地不出现。

---

### 坑 20：控制台 `NavigationDuplicated`

**现象**：重复点击当前菜单，Console 报 `NavigationDuplicated: Avoided redundant navigation to current location`。

**根因**：Vue Router 3.1+ 的 `push` 返回 Promise；跳到当前路由会 reject。

**修法**：

```js
this.$router.push('/xxx').catch(() => {})
```

**项目**：`views/index.vue:241,244,248` 都是这样写的。也可以用全局补丁统一吞掉（本项目没做）：

```js
const originalPush = Router.prototype.push
Router.prototype.push = function (location) {
  return originalPush.call(this, location).catch(err => err)
}
```

---

### 坑 21：刷新后动态路由丢失 / 页面 404

**根因**：项目的业务路由是登录后由后端菜单生成的（`store/modules/permission.js:75-111`，`router.addRoutes`）。刷新后内存里的路由没了，需要重新走一遍「拿用户信息 → 拿菜单 → 生成路由」。

**项目已经处理**：`src/permission.js:88-117` 的守卫会在 `roles.length === 0` 时重新 `GetInfo` + `GenerateRoutes` + `addRoutes`，然后 `next({ ...to, replace: true })` 重新进入目标路由（第 5 章 §10.1）。

**常见错误**：

- 自己写页面时把路由加到了 `constantRoutes` 之外，却没经过权限流程；
- 热更新后 `addRoutes` 重复添加，出现重复路由警告；
- 守卫里忘了 `next()`，页面一直白屏。

---

### 坑 22：401 死循环 / 请求没带 token

**现象**：登录后所有请求 401，页面在 `/login` 和首页之间反复跳；Network 里请求头没有 `Authorization`。

**排查顺序**：

1. Network 看请求头有没有 `Authorization: Bearer xxx`（项目在 `utils/request.js:92-94` 统一加）；
2. 看 token 是否存进了 cookie（`utils/auth.js:3`，key 是 `Admin-Token`）；
3. 看后端返回的 code 是否是 401（`request.js:200-227`）；
4. 401 处理里是否调用了 `LogOut` + 跳登录（`request.js:210-222`），以及是否排除登录接口本身。

**根因**：token 过期、跨域导致 cookie 没带上、或响应拦截器对 401 的处理和登录页互相跳。

**项目**：登录接口 `api/login.js:61-68` 特意设置了 `isToken: false`，避免登录请求也去拿 token、触发 401 逻辑。

## 六、Vuex（坑 23~25）

### 坑 23：直接修改 state

```js
// 错
this.$store.state.user.token = 'xxx'

// 对
this.$store.commit('SET_TOKEN', 'xxx')
```

**根因**：Vuex 要求所有状态变更可追踪。直接改能生效（因为 state 是响应式的），但 Devtools 记录不到，严格模式下还会报错。

**项目坦白点**：`store/modules/settings.js:56-58` 的 `setTitle` action 直接改了 `state.title`；`store/index.js` 没有开启 `strict: true`，所以不会报错。这是真实的历史写法（第 6 章 §9.2）。

---

### 坑 24：`commit` 和 `dispatch` 用混

| | 调用什么 | 能不能异步 | 用途 |
|---|---|---|---|
| `commit` | mutation | 不能 | 同步改 state |
| `dispatch` | action | 能 | 调接口、组合多个 mutation |

```js
this.$store.commit('SET_TOKEN', token)       // 同步改
this.$store.dispatch('Login', form)          // 异步流程
```

**记忆**：`dispatch` 派发 action，action 里面再 `commit` mutation。

---

### 坑 25：刷新后 Vuex 状态没了

**现象**：刷新页面后用户信息/权限没了，但还处于登录态。

**根因**：Vuex 存在内存里，刷新即清空。

**项目的处理**：

- token 持久化到 cookie：`store/modules/user.js:57` 的 `token: getToken()`，从 cookie 初始化；
- 其他用户信息（roles/permissions）刷新后由路由守卫重新 `GetInfo` 拉取；
- 主题、布局等设置存 cookie（`store/modules/settings.js:8-25`）。

**自己写项目时**：要么像项目这样「重新拉」，要么用 `vuex-persistedstate` 持久化到 localStorage，注意别把敏感信息存进去。

## 七、工程与请求（坑 26~30）

### 坑 26：改了 `.env` 不生效

**现象**：把 `.env.development` 里的 `VUE_APP_BASE_API` 改了，刷新页面没变化。

**根因**：环境变量在 **webpack 编译时**被静态替换进代码（第 7 章 §5.3），不是运行时读取。devServer 启动后不会重新读 `.env`。

**修法**：停掉 `npm run dev`，重新启动。

---

### 坑 27：环境变量没加 `VUE_APP_` 前缀

**现象**：`process.env.MY_API` 是 `undefined`。

**根因**：Vue CLI 只把 `VUE_APP_` 开头的变量注入客户端代码（另外 `NODE_ENV`、`BASE_URL` 是内置的）。

**修法**：

```
VUE_APP_MY_API=http://xxx
```

```js
console.log(process.env.VUE_APP_MY_API)
```

**安全提醒**：`VUE_APP_` 变量会被打进前端包，**不要放密钥**。

---

### 坑 28：代理不生效 / 请求 404

**现象**：请求发到了 `http://localhost:80/dev-api/...`，没有转到后端。

**排查**：

1. 请求 URL 是否以 `VUE_APP_BASE_API`（`/dev-api`）开头；
2. `vue.config.js:35-44` 的 `proxy` 的 key 是否匹配；
3. `pathRewrite` 是否把 `/dev-api` 去掉了；
4. 后端地址、端口是否写对；
5. 改完 `vue.config.js` **必须重启** devServer。

**项目**：`baseURL` 在 `utils/request.js:54-66` 取自 `process.env.VUE_APP_BASE_API`；`vue.config.js:35-44` 配置了 `/dev-api` 代理（第 7 章 §4.3、§7.2）。

---

### 坑 29：返回结构理解错，`res.rows` 是 `undefined`

**根因**：项目的响应拦截器已经 `return res.data`（`utils/request.js:247`），所以页面拿到的**就是后端 JSON 本身**，不是 axios 的 `response`。

```js
// 错
.then(response => {
  this.list = response.data.rows   // 多了一层
})

// 对
.then(res => {
  this.list = res.rows
  this.total = res.total
})
```

**项目**：`position/index.vue:205-208` 就是正确写法。

**排查**：Network → Response 看 JSON 顶层到底是 `{ code, msg, rows, total }` 还是别的结构；以下载为例，`download` 用 `responseType: 'blob'`，返回结构和普通接口不同。

---

### 坑 30：下载失败却存成一个「坏文件」

**现象**：导出的 Excel 打不开；用文本编辑器打开发现是 `{"code":500,"msg":"..."}`。

**根因**：后端出错时返回的是 JSON，但前端按 `blob` 接收，直接把错误信息存成了 `.xlsx`。

**修法**：判断 blob 类型/内容，若是 JSON 则解析并提示：

```js
const isBlob = blobValidate(response.data)
if (isBlob) {
  saveAs(response.data, filename)
} else {
  const resText = await response.data.text()
  const rspObj = JSON.parse(resText)
  this.$modal.msgError(rspObj.msg)
}
```

**项目**：`utils/request.js:283-325` 的 `download` 已经做了 `blobValidate` 判断，`utils/ruoyi.js:261+` 是判断实现，可以直接参考。

## 八、还有几个环境类高频问题

| 现象 | 根因 | 修法 |
|---|---|---|
| `Module not found: Error: Can't resolve '@/xxx'` | 路径写错 / 大小写不一致 | `@` 指向 `src`（`vue.config.js:56-60`）；Windows 不区分大小写，Linux 区分，提交前统一小写 |

| 样式不生效 | `<style scoped>` 隔离 / 权重不够 | 用 `>>>` / `::v-deep` 穿透子组件（`billRule/index.vue:421-433`） |
| 图片 404 | 静态资源路径 / OSS 地址配置 | 看 Network 的实际 URL 和后端文件服务 |

## 九、调试方法论

### 9.1 Console：先看第一条红字

**看报错的三件事**：

1. **消息**：哪个变量/属性是 undefined；
2. **堆栈**：点开 `at ...` 找到自己的文件行号（忽略 `vue.runtime.esm.js` 之类的框架内部帧）；
3. **上下文**：报错前后有没有 `[Vue warn]`。

常见警告对照：

| 警告 | 含义 | 去哪查 |
|---|---|---|
| `Property or method "xxx" is not defined` | 模板用了 `data`/`methods` 里没有的名字 | 拼写、是否忘了 `return` |
| `Avoid mutating a prop directly` | 子组件改了 prop | 改成 `$emit` |
| `Duplicate keys detected` | `v-for` key 重复 | 换唯一 id |
| `Avoid using non-primitive value as key` | key 用了对象/数组 | 用字符串/数字 |
| `Failed to resolve component` | 组件没注册或路径错 | `components` / 全局注册 |
| `Unknown custom element` | 同上，通常是 Element 组件名写错 | 对照文档 |
| `The "data" property must be a function` | 坑 1 | 改函数 |
| `NavigationDuplicated` | 坑 20 | `.catch(() => {})` |

**小技巧**：

```js
console.log('params', JSON.parse(JSON.stringify(this.params)))
```

直接打印响应式对象，Console 里展开看到的是「当前最新值」，不一定是你打印那一刻的值；序列化一次能拍到快照。

### 9.2 Network：请求到底发生了什么

按顺序看：

1. **有没有发出去**（列表里有没有这条请求）；
2. **URL 对不对**（`/dev-api` 前缀、路径、query）；
3. **Method 对不对**（GET/POST/PUT/DELETE）；
4. **请求体/参数**（Payload / Query String Parameters）；
5. **状态码**（200/401/404/500）；
6. **响应体**（Response，看 `code/msg/data/rows/total`）；
7. **请求头**（`Authorization` 有没有）。

**过滤技巧**：在 Filter 输入接口路径（如 `position`），避免被图片/静态资源淹没；勾选 `Preserve log` 防止跳转后记录被清空。

### 9.3 Vue Devtools：看组件和状态

安装扩展后，F12 多一个 **Vue** 面板：

- **Components**：组件树 → 选中组件 → 右侧看 `data`、`props`、`computed`，还能直接改值做实验；
- **Vuex**：看 state、mutation 时间线；点某条 mutation 可以「时间旅行」；
- **Events**：看组件 `$emit` 了哪些事件（排查父子通信神器）；
- **Routing**：看当前路由和参数。

**典型用法**：页面数据不对 → Components 找到对应组件 → 看 `data` 里的 `tableData` 是不是空 → 如果是空，去 Network 看接口；如果不空但页面没渲染，去看模板绑定。

### 9.4 Sources：断点调试

在 `Sources` 面板找到 `webpack://` 下的源码（dev 模式有 source-map），在方法里点行号打断点，或直接写：

```js
debugger
```

刷新/触发操作后会停住，可以：

- 鼠标悬停看变量值；
- 在 Console 里执行 `this.params`；
- 单步执行（F10）/ 进入函数（F11）。

**什么时候用**：逻辑复杂、靠日志猜不出来时；比如「为什么这个 `if` 没进」「这个变量的值从哪来的」。

### 9.5 二分法定位

页面一大片不对，不要逐行读。用二分法：

1. 注释掉一半模板/逻辑，看问题是否还在；
2. 缩小到具体区块后，再逐行查；
3. 对数据问题，先 `console.log` 关键节点（进入方法时、请求前、请求后、赋值后）。

### 9.6 一张排查决策表

| 现象 | 优先查 |
|---|---|
| 白屏 + Console 红字 | Console 第一条错误 |
| 页面在但数据空 | Network 请求 → 响应结构 → data 赋值 |
| 数据有但页面不更新 | 是否直接改下标/新增属性 → `$set`/`splice` |
| 点击没反应 | 事件是否绑对（`.native`）→ 方法是否执行 |
| 弹窗里表单拿不到 | `v-if`/`$nextTick`/`ref` |
| 切页回来数据旧 | keep-alive → `activated` |
| 刷新 404 | history 模式服务器回退 |
| 请求 401 | token 头 → cookie → 拦截器 |
| 打包后空白 | `publicPath` → Console/Network |
