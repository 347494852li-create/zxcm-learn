# 第 2 章 · 模板语法全解

> **这一章解决什么问题**：把 `<template>` 里可能出现的符号一次讲全。学完这一章，项目里 95% 的模板代码你都能逐字读懂。
>
> **学完标准**：看到一个模板，能说出每个 `:`、`@`、`v-` 开头的东西在干什么，以及它是从哪个数据来的。

---

## 一、模板是什么

你写的：

```html
<h1>{{ message }}</h1>
```

Vue 会在构建（或运行时）把它**编译成一个 JS 渲染函数**，大致相当于：

```js
h('h1', this.message)
```

所以模板不是「特殊的 HTML」，而是**写起来像 HTML 的渲染声明**。理解这一点，后面的规则都很自然：

- `{{ }}` 里是 JS 表达式；
- 以 `:` 开头的属性，值是 JS 表达式而不是字符串；
- 以 `@` 开头的属性，值是事件处理函数或表达式。

> 本项目用 Vue CLI 构建，模板在打包时已经被编译好，浏览器里没有「模板编译器」。

## 二、插值 `{{ }}`

### 2.1 能放什么

```html
{{ message }}              <!-- 变量 -->
{{ 1 + 2 }}                <!-- 运算 -->
{{ user.name }}            <!-- 对象属性 -->
{{ list.length }}          <!-- 数组长度 -->
{{ ok ? '是' : '否' }}      <!-- 三元表达式 -->
{{ formatDate(time) }}     <!-- 调用方法 -->
```

### 2.2 不能放什么

```html
{{ if (ok) { return '是' } }}    <!-- 错：不能放语句 -->
{{ let x = 1 }}                  <!-- 错：不能声明变量 -->
```

### 2.3 项目里的例子

`src/views/conf/billRule/index.vue:23`：

```html
规则设置（编号：{{ currentData.code }}）:
```

`currentData` 是 `data()` 里的对象，`.code` 是它的属性。数据一变，这行文字自动更新。

### 2.4 `{{ }}` 只能渲染文本

如果值是 HTML 字符串：

```js
data: { html: '<strong>加粗</strong>' }
```

```html
{{ html }}            <!-- 页面上显示字面量 <strong>加粗</strong> -->
<span v-html="html"></span>  <!-- 真正渲染成加粗 -->
```

`v-html` 有 XSS 风险（等于让数据里的 HTML 执行），**只对可信内容用**。项目里使用极少。

## 三、`v-bind` / `:`：把数据绑到属性上

### 3.1 普通属性是写死的

```html
<el-button size="mini">新增</el-button>
```

这里的 `"mini"` 就是字符串 `mini`，永远不变。

### 3.2 `:` 让属性跟着数据走

```html
<el-button :size="buttonSize">新增</el-button>
```

`buttonSize` 是 `data` 里的变量。变量变，按钮大小跟着变。

**完整写法是 `v-bind:size`，`:` 是简写。**

### 3.3 项目里的例子：`el-tree` 的属性从哪来

`position/index.vue:12-19`：

```html
<el-tree
  :data="treeData"
  :props="defaultProps"
  :expand-on-click-node="false"
  node-key="id"
  @node-click="handleNodeClick"
/>
```

这段最容易懵的地方是：`data`、`props`、`expand-on-click-node`、`node-key` 这些名字**不是页面自己随便起的**，而是 **Element UI 的 `el-tree` 组件规定好的参数名**。

#### ① `el-tree` 的 props 定义在哪

Element UI 的源码里，`el-tree` 声明了它接收哪些参数：

```text
E:\Develop\project\zxcm-learn\zxcm-ui\node_modules\element-ui\packages\tree\src\tree.vue:66-117
```

关键几行：

- `:67`：`data`（数组）
- `:80`：`nodeKey`（字符串）
- `:83-86`：`expandOnClickNode`（布尔值，默认 `true`）
- `:110-117`：`props`（对象，默认 `{ children:'children', label:'label', disabled:'disabled' }`）

模板里写的是 **kebab-case**（短横线），对应源码里的 **camelCase**（驼峰）：

| 模板里写 | 源码里的 prop |
|---|---|
| `node-key` | `nodeKey` |
| `expand-on-click-node` | `expandOnClickNode` |

#### ② `props` 这个词有两次含义，别混

- **Vue 的 props**：组件对外接收的参数，统称 props；
- **`el-tree` 的 `props` 参数**：它本身是一个**配置对象**，告诉树「节点里的哪个字段是显示文字、哪个字段是子节点」。

`:props="defaultProps"` 的意思是：

> 把页面里的 `defaultProps` 这个对象，传给 `el-tree` 的 `props` 参数。

#### ③ 这些值从页面哪里来

| 模板里的值 | 页面里的定义 | 作用 |
|---|---|---|
| `treeData` | `position/index.vue:163` 的 `data()` | 树的数据数组 |
| `defaultProps` | `position/index.vue:177-180` | 告诉树：子节点字段是 `children`，显示文字字段是 `fullName` |
| `handleNodeClick` | `position/index.vue:227` 的 `methods` | 点击节点时执行的方法 |

`defaultProps` 长这样：

```js
defaultProps: {
  children: 'children',
  label: 'fullName'
}
```

意思是：每个节点对象里，`children` 放子节点，`fullName` 用来显示文字。

#### ④ 哪些名字能改，哪些不能

| 名字 | 能不能改 | 说明 |
|---|---|---|
| `data` | ❌ 不能 | Element UI 规定的 prop 名 |
| `props` | ❌ 不能 | Element UI 规定的 prop 名 |
| `expand-on-click-node` | ❌ 不能 | Element UI 规定的 prop 名 |
| `node-key` | ❌ 不能 | Element UI 规定的 prop 名 |
| `node-click` | ❌ 不能 | Element UI 规定的事件名 |
| `treeData` | ✅ 能 | 你自己的变量，改成 `menuTree` 也行，但模板和 `data()` 要一起改 |
| `defaultProps` | ✅ 能 | 你自己的变量，改成 `treeProps` 也行 |
| `handleNodeClick` | ✅ 能 | 你自己的方法名，改成 `onNodeClick` 也行 |
| `defaultProps` 里的 `label: 'fullName'` | ✅ 能 | 可以改成你数据里的其他字段，如 `label: 'name'` |

一句话：

> **`data` / `props` / `expand-on-click-node` / `node-key` 是 `el-tree` 的“接口名”，不能改；`treeData` / `defaultProps` / `handleNodeClick` 是你的“变量名”，可以改。**

#### ⑤ `:` 和不带 `:` 的区别

一句话：**有 `:` 当 JS 表达式算，没 `:` 当字符串。**

| 写法 | 实际传的值 |
|---|---|
| `:expand-on-click-node="false"` | 布尔 `false` |
| `expand-on-click-node="false"` | 字符串 `"false"` |
| `node-key="id"` | 字符串 `"id"`（字段名） |
| `:data="treeData"` | `treeData` 数组 |

为什么 `"false"` 不行：

```js
Boolean("false")   // true
```

非空字符串都是真值。`el-tree` 的 `expandOnClickNode` 是 Boolean 类型，收到字符串 `"false"` 会警告 `Expected Boolean, got String`，而且 `if ("false")` 仍会进入。

规则：

- **变量 / 对象 / 数组 / 布尔 / 数字 / 表达式** → 加 `:`
- **固定字符串 / 字段名** → 不加 `:`
- 所以 `node-key="id"` 不能写成 `:node-key="id"`，否则会去找变量 `id`

#### ⑥ 如果你想用自己的参数名

不能直接改 `el-tree` 的 `data`/`props`。  
如果你想要一个自己的组件，比如：

```vue
<MyTree :tree-data="treeData" :tree-props="defaultProps" />
```

那就自己包一层：

```vue
<!-- MyTree.vue -->
<template>
  <el-tree :data="treeData" :props="treeProps" v-bind="$attrs" />
</template>

<script>
export default {
  props: {
    treeData: Array,
    treeProps: Object
  }
}
</script>
```

外层叫 `treeData`/`treeProps`，里面再转给 `el-tree` 的 `data`/`props`。

#### ⑦ 顺便发现一个项目小缺口

`defaultProps.label` 写的是 `fullName`，但自定义节点插槽里写的是：

```vue
<span slot-scope="{ data }">
  <span class="text">{{ data.label }}</span>
</span>
```

`slot-scope` 拿到的是原始节点对象，`data.label` 取的是 `label` 字段。  
如果后端节点里只有 `fullName` 没有 `label`，这里可能显示空白。要么改成 `data.fullName`，要么给节点补一个 `label` 字段。这是读代码时可以主动发现的缺口。

### 3.4 `:` 里的值是 JS 表达式

```html
<el-button :disabled="list.length === 0">删除</el-button>
<el-button :loading="loading">保存</el-button>
<el-col :span="6"> ... </el-col>
```

`billRule/index.vue:59`：

```html
<el-select :disabled="form.id" ...>
```

意思是：`form.id` 为真（有值）时下拉框禁用。

### 3.5 `:class` 和 `:style`

**对象语法**（键是类名，值是是否启用）：

```html
<div :class="{ active: isActive, 'text-danger': hasError }"></div>
```

**数组语法**：

```html
<div :class="[activeClass, errorClass]"></div>
```

**项目例子** `Pagination/index.vue:2`：

```html
<div :class="{'hidden': hidden}" class="pagination-container">
```

- `class="pagination-container"` 是固定类名；
- `:class="{'hidden': hidden}"` 是动态类名：`hidden` 为 true 时加上 `hidden` 类，对应样式 `:111-113` 的 `display: none`。

这个组件用 `hidden` 这个 prop 控制整个分页条是否隐藏。

### 3.6 完整案例：商品卡片（`v-bind` 全家桶）

> 目标：把 `:src`、`:alt`、`:title`、`:disabled`、`:class`、`:style` 一次用全。  
> 用法：新建 `bind-demo.html`，把下面整段复制进去，用浏览器打开。

```html
<!DOCTYPE html>
<html lang="zh-CN">
<head>
  <meta charset="UTF-8">
  <title>v-bind 完整案例</title>
  <style>
    .card { width: 240px; padding: 16px; border: 2px solid #409EFF; border-radius: 8px; }
    .card.soldout { opacity: 0.5; }
    .price { font-weight: bold; }
  </style>
</head>
<body>
  <div id="app">
    <div
      class="card"
      :class="{ soldout: product.stock === 0 }"
      :style="{ borderColor: themeColor }"
    >
      <img :src="product.image" :alt="product.name" width="120" />
      <h3 :title="product.name">{{ product.name }}</h3>
      <p>价格：<span class="price" :style="{ color: themeColor }">￥{{ product.price }}</span></p>
      <p>库存：{{ product.stock }}</p>

      <button :disabled="product.stock === 0" @click="buy">购买</button>
      <p v-if="message">{{ message }}</p>
    </div>

    <button @click="toggleTheme">切换主题色</button>
  </div>

  <script src="https://cdn.jsdelivr.net/npm/vue@2.6.12/dist/vue.js"></script>
  <script>
    new Vue({
      el: '#app',
      data: {
        product: {
          name: '企业合同管理实战',
          price: 99,
          stock: 2,
          image: 'https://via.placeholder.com/120'
        },
        themeColor: '#409EFF',
        message: ''
      },
      methods: {
        buy() {
          // 库存为 2 时，`this.product.stock <= 0` 的结果是 `2 <= 0` → **false**，`if` 里的 `return` **不会执行**，函数继续往下走，于是 `this.product.stock--` 照常执行，库存变成 1。`return` 只有在小括号里的条件成立（为 `true`）时才会被执行，执行了才会「提前结束函数」。
          if (this.product.stock <= 0) return
          this.product.stock--
          this.message = this.product.stock === 0
            ? '已售罄'
            : '购买成功，剩余 ' + this.product.stock + ' 件'
        },
        toggleTheme() {
          this.themeColor = this.themeColor === '#409EFF' ? '#E6A23C' : '#409EFF'
        }
      }
    })
  </script>
</body>
</html>
```

**逐行看关键绑定**：

| 代码 | 传的是什么 | 不加 `:` 会怎样 |
|---|---|---|
| `:src="product.image"` | `product.image` 这个变量（URL 字符串） | `src="product.image"` 会把字面量 `product.image` 当 URL |
| `:alt="product.name"` | 变量 | `alt="product.name"` 传字面量 |
| `:title="product.name"` | 变量 | 鼠标悬停显示 `product.name` 这串字 |
| `:disabled="product.stock === 0"` | 布尔值 | `disabled="false"` 是字符串，仍然会禁用 |
| `:class="{ soldout: product.stock === 0 }"` | 对象，条件为真时加 `soldout` 类 | 写成 `class="{...}"` 会被当成普通类名字符串 |
| `:style="{ borderColor: themeColor }"` | 对象，动态设置边框颜色 | 写成 `style="{...}"` 样式不会生效 |

**交互时发生了什么**：

1. 初始 `stock=2`，按钮可点；
2. 点「购买」两次：`stock` 变成 0，按钮 `:disabled` 为 `true`，卡片加上 `soldout` 类变半透明；
3. 点「切换主题色」：`themeColor` 变，边框和价格颜色跟着变，因为 `:style` 绑的是变量。

**常见错误**：

- `src="product.image"`：浏览器会去找名为 `product.image` 的图片；
- `:disabled="false"` 和 `disabled="false"` 不是一回事；
- `:class="{ soldout: product.stock = 0 }"`：把 `===` 写成 `=`，变成赋值。

2. 把库存改成 0，观察按钮和卡片样式；
3. 把 `:src` 的冒号去掉，看图片是否裂开。

## 四、`v-on` / `@`：事件绑定

### 4.1 基本写法

```html
<button @click="count++">加 1</button>
<button @click="increment()">加 1</button>
<button @click="increment">加 1</button>
```

三种都合法：

- `@click="表达式"`：直接执行一段表达式；
- `@click="方法名"`：事件触发时调用方法，**Vue 自动传入事件对象**；
- `@click="方法名()"`：显式调用，不传参。

> 只写方法名时传参是事件对象 `$event`；写了括号就必须自己传 `$event`。

### 4.2 常见事件

| 事件 | 触发时机 | 例子 |
|---|---|---|
| `click` | 点击 | `@click="handleAdd"` |
| `change` | 值改变（下拉、日期等） | `@change="typeChange"` |
| `input` | 输入时 | `@input="onInput"` |
| `keyup.enter` | 回车键 | `position/index.vue:37` |
| `node-click` | 树节点被点击（Element UI 自定义事件） | `position/index.vue:19` |
| `size-change` / `current-change` | 分页大小/页码变化 | `Pagination/index.vue:12-13` |

### 4.3 事件修饰符：`.prevent` 到底在阻止什么

#### 4.3.1 先理解「浏览器的默认行为」

很多 HTML 元素被操作时，浏览器会**自动做一件事**，这叫默认行为：

| 元素/操作 | 浏览器默认行为 |
|---|---|
| 点 `<a href="...">` | 跳转到 href 地址 |
| 提交 `<form>` | 把表单数据发给服务器，并**刷新/跳转页面** |
| 在输入框里按回车（表单内） | 触发表单提交 |
| 右键 | 弹出浏览器右键菜单 |

有时候我们不想让浏览器做这件事，就要「阻止默认行为」。

#### 4.3.2 `.prevent` = 调用 `event.preventDefault()`

```html
<form @submit.prevent="onSubmit">
```

- `@submit`：监听表单提交事件；
- `.prevent`：在事件回调里自动调用 `event.preventDefault()`；
- `onSubmit`：你自己的处理函数。

等价于手写：

```js
function onSubmit(event) {
  event.preventDefault()   // 阻止浏览器提交表单
  // 然后做自己的事
}
```

**如果不加 `.prevent` 会怎样？**

在表单里的输入框按回车，或者点「提交」按钮，浏览器会真的提交表单：

- 页面刷新；
- Vuex 里的状态、当前页面数据全丢；
- 可能跳到 `?username=...` 这样的 URL；
- 开发时看起来像「页面闪了一下」「刚填的东西没了」。

在 SPA（单页应用）里，我们通常用 axios 自己发请求，不希望浏览器刷新页面，所以搜索表单、登录表单经常要 `.prevent`。

#### 4.3.3 项目里的 `@submit.native.prevent`

`position/index.vue:29`：

```html
<el-form @submit.native.prevent>
```

拆开看：

| 部分 | 作用 |
|---|---|
| `@submit` | 监听原生 `submit` 事件 |
| `.native` | 把事件绑到 `el-form` 组件内部的**根原生元素**上（因为 `el-form` 是 Vue 组件，不是原生 `<form>`） |
| `.prevent` | 阻止表单默认提交 |

**为什么没有写处理函数也能工作？**

`@submit.native.prevent` 只有修饰符、没有方法名，Vue 会生成一个只做 `preventDefault()` 的空处理函数。它的目的就是「按回车别刷新页面」，不需要额外逻辑。

**不加会怎样？**

在搜索框里按回车，浏览器可能提交表单并刷新页面，你刚选的查询条件、分页状态都会丢。

#### 4.3.4 其他常见修饰符

| 修饰符 | 作用 | 例子 |
|---|---|---|
| `.prevent` | 阻止默认行为 | `@submit.prevent` |
| `.stop` | 阻止事件冒泡 | `@click.stop` |
| `.once` | 只触发一次 | `@click.once` |
| `.self` | 只有点在自己身上才触发 | `@click.self` |
| `.enter` | 只在回车键触发 | `@keyup.enter` |
| `.native` | 绑到组件根原生元素上（Vue 2 特有） | `@keyup.enter.native` |

### 4.4 事件里的 `$event` 是什么

先看一个最常见的困惑：

> 同样是 `$event`，为什么 `@click` 的 `$event` 有 `.target`，而 `el-select @change` 的 `$event` 直接就是选中的值？

因为 **`$event` 不是固定对象，它只是事件回调收到的第一个参数**。谁触发事件，谁决定这个参数是什么。

子组件通知父组件，用的是 `$emit`：

```js
this.$emit('add', payload)
```

父组件监听：

```html
<child @add="handle" />
```

```js
handle(payload) {
  // payload 就是子组件 $emit 的第二个参数
}
```

在模板里写 `@add="handle($event)"` 时，这个 `$event` 就是 `payload`。

原生事件由浏览器触发，所以 `$event` 是浏览器的事件对象；组件事件由子组件触发，所以 `$event` 是子组件想传的数据。

> **`$event` 的类型不固定，它只是「这次事件递过来的第一个参数」。**

#### 4.4.1 一句话

`$event` 是 **Vue 在模板里提供的事件对象/事件参数**。

- 原生事件（click/input/keyup）里，它是**浏览器原生事件对象**；
- 组件自定义事件（如 `el-select` 的 `change`）里，它是**组件 `$emit` 传出来的值**。

#### 4.4.2 三种写法

```html
<!-- 1. 只写方法名：Vue 自动把事件对象作为第一个参数 -->
<button @click="handle">点我</button>

<!-- 2. 显式传 $event -->
<button @click="handle($event)">点我</button>

<!-- 3. 还要传别的参数：必须自己写 $event -->
<button @click="handle('删除', $event)">点我</button>
```

对应的方法：

```js
methods: {
  handle(event) {
    console.log(event)
  }
}
```

> 方法里的参数名叫 `event`、`e`、`evt` 都行；`$event` 只是**模板里的特殊变量**。

#### 4.4.3 原生事件里的 `$event`

```html
<input @input="message = $event.target.value" />
```

- `$event` 是 `InputEvent`；
- `$event.target` 是触发事件的 `<input>` 元素；
- `$event.target.value` 是输入框当前的值。

#### 4.4.4 组件自定义事件里的 `$event`

`billRule/index.vue:60`：

```html
@change="typeChange($event, currentData.ruleArray[index])"
```

`el-select` 的 `change` 事件不是原生 DOM 事件，它 `$emit('change', 新选中的值)`。所以：

- `$event` = **新选中的值**（不是 DOM 事件，也没有 `.target`）；
- 第二个参数 = 当前行的数据。

对应方法大概是：

```js
typeChange(type, row) {
  // type 是 el-select 新选中的值
  // row 是当前行的 ruleArray[index]
}
```

#### 4.4.5 常见错误

| 写法 | 问题 |
|---|---|
| 在方法里写 `$event` | 方法里没有这个变量，应该用参数名 `event` |
| 对 `el-select` 的 `$event` 用 `.target.value` | `$event` 已经是值，不是 DOM 事件 |
| `@click="handle"` 却在方法里写 `handle()` 不带参数 | 方法收不到事件对象 |
| `@click="handle($event)"` 和 `@click="handle"` 混着理解 | 前者显式传，后者 Vue 自动传 |

```js
  // ...
```

然后：

#### 4.4.7 遇到一个不认识的组件事件，怎么查 `$event` 是什么

不要猜，按这三步：

1. **看官方文档的事件表**：Element UI 每个组件页面都有「Events」表，写着 `change`、`node-click` 的参数；
2. **在组件源码里搜 `$emit`**：
   ```js
   this.$emit('change', value)
   ```
   第二个参数就是父组件 `$event` 收到的值；
3. **实在不确定，打印出来**：
   ```js
   handleEvent($event) {
     console.log('$event =', $event)
     console.log('arguments =', arguments)
   }
   ```

比如：

- `el-select` 的 `change` 是 `$emit('change', 新值)`，所以 `$event` 是新值；
- `el-tree` 的 `node-click` 是 `$emit('node-click', data, node, component)`，所以 `$event` 是节点数据，第二个参数才是内部 node；
- `el-pagination` 的 `size-change` 是 `$emit('size-change', 新每页条数)`，所以 `$event` 是数字。

### 4.5 完整案例：待办清单（事件全家桶）

> 目标：把 `@submit.prevent`、`@click`、`@click.stop`、`@keyup.enter`、`$event` 一次用全。  
> 用法：新建 `event-demo.html`，整段复制后用浏览器打开。

```html
<!DOCTYPE html>
<html lang="zh-CN">
<head>
  <meta charset="UTF-8">
  <title>v-on 完整案例</title>
  <style>
    .done { color: #999; text-decoration: line-through; }
    li { margin: 6px 0; cursor: pointer; }
  </style>
</head>
<body>
  <div id="app">
    <!-- 表单：回车或点“添加”都会走 submit -->
    <form @submit.prevent="addTodo">
      <input v-model.trim="text" placeholder="输入待办，回车添加" />
      <button type="submit">添加</button>
    </form>

    <!-- 单独的搜索框：演示 @keyup.enter -->
    <p>
      <input v-model="keyword" @keyup.enter="search" placeholder="输入关键字，回车搜索" />
      <span>搜索词：{{ lastSearch }}</span>
    </p>

    <ul>
      <li
        v-for="(todo, index) in todos"
        :key="todo.id"
        :class="{ done: todo.done }"
        @click="toggle(todo)"
      >
        <span>{{ todo.text }}</span>
        <!-- .stop：阻止冒泡，避免删除时也触发 li 的 toggle -->
        <button @click.stop="remove(index, $event)">删除</button>
      </li>
    </ul>

    <p>剩余：{{ remaining }} 条</p>
  </div>

  <script src="https://cdn.jsdelivr.net/npm/vue@2.6.12/dist/vue.js"></script>
  <script>
    new Vue({
      el: '#app',
      data: {
        text: '',
        keyword: '',
        lastSearch: '',
        nextId: 3,
        todos: [
          { id: 1, text: '读第 2 章', done: false },
          { id: 2, text: '写一个待办清单', done: true }
        ]
      },
      computed: {
        remaining() {
          return this.todos.filter(t => !t.done).length
        }
      },
      methods: {
        addTodo() {
          const text = this.text.trim()
          if (!text) return
          this.todos.push({ id: this.nextId++, text, done: false })
          this.text = ''
        },
        toggle(todo) {
          todo.done = !todo.done
        },
        remove(index, event) {
          console.log('删除按钮的 $event =', event)
          this.todos.splice(index, 1)
        },
        search() {
          this.lastSearch = this.keyword
        }
      }
    })
  </script>
</body>
</html>
```

**关键点逐条看**：

| 写法 | 作用 |
|---|---|
| `@submit.prevent="addTodo"` | 回车/点「添加」触发表单提交，但阻止页面刷新 |
| `@keyup.enter="search"` | 只在搜索框按回车时触发 `search` |
| `@click="toggle(todo)"` | 点整行切换完成状态 |
| `@click.stop="remove(index, $event)"` | 点删除只删这一条，**不冒泡**到 `li` 的 `toggle` |
| `$event` | 删除按钮的原生点击事件对象，`console.log` 能看到 |

**如果不加修饰符会怎样**：

- 去掉 `.prevent`：按回车页面刷新，待办全没了；
- 去掉 `.stop`：点删除会先删除，然后事件冒泡到 `li`，又触发一次 `toggle`；
- 把 `@keyup.enter` 同时写在表单里的输入框上：按回车会先触发 `keyup`，再触发表单 `submit`，可能添加两次。本案例把搜索框放在表单外，就是为了避免这个问题。

**练习**：

1. 给每个 `li` 加一个「编辑」按钮，点击时 `@click.stop`，弹出 `prompt` 改文字；
2. 把 `@click.stop` 改成 `@click`，观察删除时是否还会切换完成状态；
3. 在 `remove` 里打印 `event.target` 和 `event.currentTarget`，理解事件对象。

## 五、`v-model`：双向绑定

### 5.1 什么是双向

```html
<input v-model="message" />
<p>{{ message }}</p>
```

- 用户输入 → `message` 自动更新 → `<p>` 自动更新；
- 代码里修改 `message` → 输入框自动更新。

**一变两边都变**，所以叫双向绑定。

它本质上是语法糖：

```html
<input :value="message" @input="message = $event.target.value" />
```

### 5.2 项目里的用法

`position/index.vue:33`：

```html
<el-input v-model="params.keyword" />
```

`position/index.vue:43`：

```html
<el-select v-model="params.flowCode"> ... </el-select>
```

`billRule/index.vue:4`：

```html
<el-tabs v-model="activeName" ...>
```

`billRule/index.vue:107`：

```html
<el-input-number v-model="currentData.startNumber" :min="1" :max="1000" />
```

### 5.3 修饰符

```html
<input v-model.trim="name" />     <!-- 自动去掉首尾空格 -->
<input v-model.number="age" />    <!-- 转成数字类型 -->
<input v-model.lazy="msg" />      <!-- 失去焦点时才同步 -->
```

### 5.4 `v-model` 用在自定义组件上

`src/views/system/position/index.vue:141-142`：

```html
:page.sync="params.pageNum"
:limit.sync="params.pageSize"
```

`.sync` 是 `.vue` 里另一种「双向」写法，第 4 章讲组件时详细说。

### 5.5 完整案例：用户资料表单（`v-model` 全家桶）

> 目标：把输入框、数字、下拉、复选框、文本域、修饰符、computed 一次用全。  
> 用法：新建 `model-demo.html`，整段复制后用浏览器打开。

```html

  <div id="app">
    <form @submit.prevent="submit">
      <label>
        姓名：
        <input v-model.trim="form.name" placeholder="请输入姓名" />
      </label>

      <label>
        年龄：
        <input v-model.number="form.age" type="number" min="1" />
      </label>

      <label>
        城市：
        <select v-model="form.city">
          <option disabled value="">请选择</option>
          <option value="beijing">北京</option>
          <option value="shanghai">上海</option>
          <option value="taiyuan">太原</option>
        </select>
      </label>

      <label>
        <input type="checkbox" v-model="form.agree" />
        同意用户协议
      </label>

      <label>
        备注：
        <textarea v-model.lazy="form.remark" rows="3"></textarea>
      </label>

      <button type="submit" :disabled="!canSubmit">提交</button>
    </form>

    <p>能不能提交：{{ canSubmit ? '可以' : '还差必填项' }}</p>

    <pre>{{ form }}</pre>

  <script src="https://cdn.jsdelivr.net/npm/vue@2.6.12/dist/vue.js"></script>

          name: '',
          age: 18,
          city: '',
          agree: false,
          remark: ''
        },
        message: ''
      },

        canSubmit() {
          return this.form.name.trim() !== ''
            && this.form.age >= 18
            && this.form.city !== ''
            && this.form.agree
        }
      },
      methods: {
        submit() {
          this.message = '提交成功：' + this.form.name + '，' + this.form.age + ' 岁'
```

**逐项看**：

| 写法 | 作用 |
|---|---|
| `v-model.trim="form.name"` | 双向绑定，并自动去掉首尾空格 |
| `v-model.number="form.age"` | 双向绑定，并把输入转成数字（不是字符串） |
| `v-model="form.city"` | 下拉框选中值直接写进 `form.city` |
| `v-model="form.agree"` | 复选框的布尔值 |
| `v-model.lazy="form.remark"` | 输入时不实时同步，失焦/回车时才同步 |
| `:disabled="!canSubmit"` | 用 computed 控制按钮是否可点 |
| `{{ form }}` | 把整个对象打印出来，实时看到每个字段 |

**`v-model` 的本质**：

```html
<input v-model="form.name" />
<!-- 等价于 -->
<input :value="form.name" @input="form.name = $event.target.value" />
```

所以它不是魔法，就是「把 value 绑上去 + 监听 input 写回来」。

**常见错误**：

- 在子组件里直接 `v-model` 绑 `props`：会改父组件数据，Vue 会警告；
- 复选框 `v-model` 绑数组时，选中的是 `value` 值，不是 `true/false`；
- `v-model.number` 输入框清空时，值可能是空字符串 `''`，不是数字；
- 忘记 `form.name.trim()`，只写 `form.name !== ''`，全是空格也能通过。

2. 给「备注」加字数统计 `{{ form.remark.length }}/100`；
3. 把 `.trim` 去掉，输入前后空格，观察 `form.name` 的变化。

## 六、条件渲染：`v-if` 与 `v-show`

### 6.1 用法

```html
<div v-if="visible">看得到我</div>
<div v-else>看不到上面那个时显示我</div>

<div v-show="visible">我也能隐藏</div>
```

### 6.2 区别（高频面试题）

| | `v-if` | `v-show` |
|---|---|---|
| 原理 | 条件为假时**销毁/不创建**元素 | 元素始终存在，只是 `display: none` |
| 初始开销 | 假时不渲染，省 | 总要渲染一次 |
| 切换开销 | 高（反复创建销毁） | 低（只改样式） |
| 适用 | 很少切换 | 频繁切换 |

### 6.3 项目里的例子

`billRule/index.vue:72-86`：

```html
<el-input
  v-if="currentData.ruleArray[index].type == '1'"
  v-model="currentData.ruleArray[index].string"
/>
<el-input
  v-if="currentData.ruleArray[index].type == '2'"
  value="格式：年月日"
  :disabled="true"
/>
```

根据规则类型显示不同的输入框：类型 1 显示可编辑文本，类型 2 显示禁用的「年月日」。

`billRule/index.vue:146`：

```html
<template v-if="false">
```

一块被 `v-if` 永久关闭的「扩展设置」代码。这是项目里的一种「临时隐藏」写法——不是好习惯，但读代码时会遇到。

### 6.4 完整案例：Tab 切换 + 加载/错误状态

> 目标：把 `v-if` / `v-else-if` / `v-else` / `v-show` 一次用全，并亲眼看到 DOM 差异。  
> 用法：新建 `if-demo.html`，整段复制后用浏览器打开。

```html
<!DOCTYPE html>
<html lang="zh-CN">
<head>
  <meta charset="UTF-8">
  <title>v-if / v-show 完整案例</title>
  <style>
    button { margin-right: 8px; }
    section { margin-top: 12px; padding: 12px; border: 1px solid #ddd; }
    .tip { color: #E6A23C; }
  </style>
</head>
<body>
  <div id="app">
    <button @click="tab = 'profile'">资料</button>
    <button @click="tab = 'orders'">订单</button>
    <button @click="tab = 'settings'">设置</button>

    <!-- 加载 / 错误 / 正常三态 -->
    <p v-if="loading">加载中...</p>
    <p v-else-if="error" style="color: red">{{ error }}</p>
    <div v-else>
      <section v-if="tab === 'profile'">
        <h3>资料</h3>
        <p>这里是个人资料。</p>
      </section>

      <section v-else-if="tab === 'orders'">
        <h3>订单</h3>
        <p>这里是订单列表。</p>
      </section>

      <section v-else>
        <h3>设置</h3>
        <p>这里是设置页。</p>
      </section>
    </div>

    <hr />

    <!-- v-show：元素始终在 DOM 里，只是 display:none -->
    <p v-show="showTip" class="tip">提示：v-show 的元素还在 DOM 里。</p>
    <button @click="showTip = !showTip">显示/隐藏提示</button>

    <hr />
    <button @click="loading = !loading">切换 loading</button>
    <button @click="error = error ? '' : '网络错误'">切换 error</button>
  </div>

  <script src="https://cdn.jsdelivr.net/npm/vue@2.6.12/dist/vue.js"></script>
  <script>
    new Vue({
      el: '#app',
      data: {
        tab: 'profile',
        loading: false,
        error: '',
        showTip: true
      }
    })
  </script>
</body>
</html>
```

**关键点**：

| 写法 | 行为 |
|---|---|
| `v-if="loading"` | 为 true 时创建 `<p>`，为 false 时**销毁** |
| `v-else-if="error"` | 前面条件不成立时才判断 |
| `v-else` | 前面都不成立时显示 |
| `v-if="tab === 'profile'"` | 只渲染当前 tab 对应的 `<section>` |
| `v-show="showTip"` | `<p>` 一直在 DOM 里，只是加 `style="display:none"` |

**打开 F12 → Elements 观察**：

1. 点「订单」：`profile` 那个 `<section>` 从 DOM 里**消失**，`orders` 那个**新出现**；
2. 点「显示/隐藏提示」：`v-show` 的 `<p>` 一直在，只是 `display` 变成 `none`；
3. 点「切换 loading」：加载中的 `<p>` 被创建/销毁。

**为什么要有两个**：

- `v-if`：切换时创建/销毁，适合**不常切换**、或创建成本高的内容；
- `v-show`：只改 CSS，适合**频繁切换**的内容（比如下拉菜单、提示条）。

**常见错误**：

- 同一個元素上同时写 `v-if` 和 `v-for`：Vue 2 里 `v-for` 优先级更高，容易算错，最好用 `<template v-for>` 包一层；
- `v-show` 不支持 `<template>`，也不适合放在需要「销毁重建」的组件上；
- `v-if` 为 false 时，子组件的 `created/mounted` 不会执行；`v-show` 会执行。

**练习**：

1. 把「设置」页改成 `v-show`，观察切换时 DOM 是否保留；
2. 在「订单」里放一个 `<input>`，输入内容后切到「资料」再切回来，对比 `v-if` 和 `v-show` 哪个会丢输入；
3. 用 `<template v-if="loading">` 包住两个 `<p>`，看多元素条件渲染怎么写。

## 七、列表渲染：`v-for`

### 7.1 基本写法

```html
<ul>
  <li v-for="(item, index) in list" :key="item.id">
    {{ index + 1 }}. {{ item.name }}
  </li>
</ul>
```

- `item`：当前元素；
- `index`：当前下标（可选）；
- `in` 也可以写成 `of`；
- `:key` 强烈建议写。

### 7.2 遍历对象

```html
<div v-for="(value, key, index) in user" :key="key">
  {{ index }} - {{ key }}: {{ value }}
</div>
```

### 7.3 `:key` 是干什么的

Vue 更新列表时，需要知道「哪些项是同一个、哪些被删了/加了」。`key` 是这一项的**唯一身份**。

**反例**：用数组下标当 key，删除中间项时，Vue 可能复用错元素，导致输入框内容、组件状态错位。

**正确**：用数据自身的唯一 id：

```html
<el-tab-pane
  v-for="item in billRuleList"
  :key="item.id"
/>
```

`billRule/index.vue:9-13` 就是这么写的。

### 7.4 项目里的例子

`position/index.vue:44-50`：

```html
<el-option
  v-for="dict in dict.type.PO_TYPE"
  :key="dict.value"
  :label="dict.label"
  :value="dict.value"
/>
```

把字典数组渲染成下拉选项。

`DictTag/index.vue:3`：

```html
<template v-for="(item, index) in options">
  <template v-if="values.includes(item.value)">
    <span ...>{{ item.label }}</span>
  </template>
</template>
```

先遍历所有选项，再用 `v-if` 过滤出值匹配的项，最后显示标签。

```html
  <div id="app">
    <p>
      <input v-model.trim="keyword" placeholder="按名称搜索" />
      <select v-model="sortBy">
        <option value="name">按名称</option>
        <option value="price">按价格</option>
      </select>
      <button @click="add">添加一条</button>
    </p>

    <ul>
      <li
        v-for="(item, index) in filteredList"
        :key="item.id"
        @click="select(item)"
      >
        {{ index + 1 }}. {{ item.name }} —— ￥{{ item.price }}
        <button @click.stop="remove(item.id)">删除</button>
      </li>
    </ul>

    <p v-if="filteredList.length === 0" class="empty">没有匹配的条目</p>
    <p>当前选中：{{ selectedName || '无' }}</p>
  </div>

  <script src="https://cdn.jsdelivr.net/npm/vue@2.6.12/dist/vue.js"></script>
  <script>
    new Vue({
      el: '#app',
      data: {
        keyword: '',
        sortBy: 'name',
        selectedName: '',
        nextId: 4,
        items: [
          { id: 1, name: '合同草拟', price: 100 },
          { id: 2, name: '合同审批', price: 200 },
          { id: 3, name: '合同归档', price: 50 }
        ]
      },
      computed: {
        filteredList() {
          const kw = this.keyword.toLowerCase()
          const list = this.items.filter(item =>
            item.name.toLowerCase().includes(kw)
          )
          // 注意：先复制再排序，不要直接改 this.items
          return [...list].sort((a, b) => {
            if (this.sortBy === 'price') return a.price - b.price
            return a.name.localeCompare(b.name)
          })
        }
      },
      methods: {
        add() {
          this.items.push({
            id: this.nextId++,
            name: '新条目 ' + this.nextId,
            price: Math.floor(Math.random() * 300)
          })
        },
        remove(id) {
          const index = this.items.findIndex(item => item.id === id)
          if (index !== -1) this.items.splice(index, 1)
        },
        select(item) {
          this.selectedName = item.name
        }
      }
    })
  </script>
</body>
</html>
```

**关键点**：

| 写法 | 作用 |
|---|---|
| `v-for="(item, index) in filteredList"` | 遍历计算后的列表，`item` 是当前项，`index` 是显示顺序 |
| `:key="item.id"` | 用稳定唯一 id 标识每一项，删除/排序时 Vue 能正确复用 DOM |
| `filteredList`（computed） | 搜索 + 排序都放在计算属性里，模板只负责显示 |
| `@click.stop="remove(item.id)"` | 删除按钮阻止冒泡，避免触发 `li` 的 `select` |
| `v-if="filteredList.length === 0"` | 空状态提示 |

**为什么 `:key` 不用 `index`**：

假设列表是 `[A, B, C]`，你删掉 B：

- 用 `index` 当 key：原来的 key 0/1/2 变成 0/1，Vue 可能把 C 复用到 B 的位置，输入框、组件状态会错位；
- 用 `item.id` 当 key：A 的 key 还是 A，C 的 key 还是 C，Vue 知道 B 被删了，只移除 B。

**常见错误**：

- `v-if` 和 `v-for` 写在同一个元素上：Vue 2 里 `v-for` 优先级更高，容易把条件算错；用 `<template v-for>` 包一层；
- `this.items[0] = newItem`：Vue 2 检测不到数组下标赋值，要用 `this.$set(this.items, 0, newItem)` 或 `splice`；
- `this.items.length = 0`：也检测不到，要用 `splice(0)`；
- 排序时直接 `this.items.sort()`：会改原数组，违反「计算属性不产生副作用」的原则。

**练习**：

1. 把 `:key="item.id"` 改成 `:key="index"`，删除中间一项，观察输入框/状态是否错位；
2. 给列表加一个「价格 > 100 才显示」的筛选；
3. 用 `<template v-for>` + `v-if` 过滤出价格大于 100 的项。

### 9.2 `v-hasPermi`：按权限隐藏按钮

```html
<el-button v-hasPermi="['conf:contractCounterpart:add']">新增</el-button>
```

`src/views/conf/contractCounterpart/index.vue:122`。

它的实现 `src/directive/permission/hasPermi.js:44-99`：

```js
inserted(el, binding, vnode) {
  const { value } = binding                    // ['conf:contractCounterpart:add']
  const permissions = store.getters.permissions // 当前用户拥有的权限码
  const hasPermissions = permissions.some(permission => {
    return all_permission === permission || value.includes(permission)
  })
  if (!hasPermissions) {
    el.parentNode && el.parentNode.removeChild(el)  // 没权限：把按钮从页面上删掉
  }
}
```

**关键点**：

1. `inserted` 是指令的生命周期：元素插入页面时执行一次；
2. 没权限时**直接删除元素**，不是隐藏——所以在页面上根本看不到这个按钮；
3. 权限码来自 Vuex 的 `permissions`（第 6 章讲它怎么来的）。

> 前端隐藏按钮只是体验优化，**真正的拦截在后端** `@SaCheckPermission`。前端删了按钮，用户仍然可以绕过界面直接调接口，所以后端必须再校验一次。

### 9.3 完整案例：自定义权限指令 `v-permission`

> 目标：自己写一个和项目 `v-hasPermi` 同类的指令，理解 `inserted`、`binding.value`、`vnode.context`。  
> 用法：新建 `directive-demo.html`，整段复制后用浏览器打开。

```html
<!DOCTYPE html>
<html lang="zh-CN">
<head>
  <meta charset="UTF-8">
  <title>自定义指令完整案例</title>
</head>
<body>
  <div id="app">
    <p>当前权限：{{ permissions.join(', ') || '无' }}</p>

    <!-- 有 user:add 才显示 -->
    <button v-permission="'user:add'">新增用户</button>

    <!-- 有 user:delete 才显示 -->
    <button v-permission="'user:delete'">删除用户</button>

    <p>
      <button @click="toggleDelete">切换 user:delete 权限</button>
    </p>

    <p style="color: #999">
      注意：指令在元素插入时只执行一次；元素被删除后，再给权限也不会自动回来。
      需要动态显示/隐藏时，用 v-if + 方法判断更合适。
    </p>
  </div>

  <script src="https://cdn.jsdelivr.net/npm/vue@2.6.12/dist/vue.js"></script>
  <script>
    // 1. 注册一个全局指令，名字叫 permission（模板里写 v-permission）
    Vue.directive('permission', {
      // inserted：元素被插入父节点时执行一次
      inserted(el, binding, vnode) {
        const need = binding.value          // 模板里传的权限码，如 'user:add'
        const permissions = vnode.context.permissions  // 当前 Vue 实例的 permissions

        if (!permissions.includes(need)) {
          // 没权限：把元素从 DOM 里删掉
          el.parentNode && el.parentNode.removeChild(el)
        }
      }
    })

    new Vue({
      el: '#app',
      data: {
        permissions: ['user:add']
      },
      methods: {
        toggleDelete() {
          const i = this.permissions.indexOf('user:delete')
          if (i === -1) {
            this.permissions.push('user:delete')
          } else {
            this.permissions.splice(i, 1)
          }
        }
      }
    })
  </script>
</body>
</html>
```

**关键点**：

| 代码 | 作用 |
|---|---|
| `Vue.directive('permission', {...})` | 注册全局指令，模板里写 `v-permission` |
| `inserted(el, binding, vnode)` | 元素插入页面时执行一次 |
| `binding.value` | 模板里传的值，`v-permission="'user:add'"` 里就是 `'user:add'` |
| `vnode.context` | 当前 Vue 实例，所以能拿到 `permissions` |
| `el.parentNode.removeChild(el)` | 把按钮从 DOM 里删掉 |

**指令的四个常用钩子**：

| 钩子 | 时机 |
|---|---|
| `bind` | 指令第一次绑定到元素时，只执行一次 |
| `inserted` | 元素插入父节点时 |
| `update` | 组件更新时 |
| `unbind` | 指令解绑时，只执行一次 |

**这个例子的局限**：

- `inserted` 只执行一次；
- 元素被 `removeChild` 删除后，再给 `user:delete` 权限，按钮也不会自动回来；
- 所以它适合「登录后权限固定」的场景，本项目就是这样；
- 如果要动态变化，用 `v-if="hasPermission('user:delete')"` + 方法判断更稳。

**常见错误**：

- 指令名写成 `v-permission`：`Vue.directive` 里不要带 `v-`；
- 把 `binding.value` 当成字符串变量：`v-permission="'user:add'"` 里要再套一层引号，否则会去找变量 `user:add`；
- 以为前端删了按钮就安全：前端只是体验，后端必须校验。

**练习**：

1. 把 `v-permission` 改成 `v-perm`，同步改 `Vue.directive('perm', ...)` 和模板；
2. 给指令加 `binding.arg`，写成 `v-permission:disable="'user:add'"`，没权限时不禁用按钮而不是删除；
3. 用 `v-if` + `methods.hasPermission` 实现同样效果，比较两者差异。

## 十、`slot-scope`：项目模板里最常见但最难懂的符号

`position/index.vue:90-95`：

```html
<el-table-column prop="type" label="岗位类型">
  <template slot-scope="scope">
    <dict-tag
      :options="dict.type.PO_TYPE"
      :value="scope.row.flowCode"
    />
  </template>
</el-table-column>
```

拆开看：

- `<el-table-column>` 是表格的一列；
- 默认情况下它只显示 `prop` 指定的字段；
- 但这一列想显示**自定义内容**（一个字典标签），于是用 `<template slot-scope="scope">` 接管这一列的渲染；
- `scope` 是 Element UI 传进来的「当前行上下文」，`scope.row` 就是**当前这一行的数据对象**。

`position/index.vue:108-137` 的操作列也一样：

```html
<template slot-scope="scope">
  <el-button @click="handleAddEdit(scope.row.id)">修改</el-button>
</template>
```

理解 `slot-scope="scope"` 的口诀：**「这一格里，当前行叫 scope.row」**。

它是「作用域插槽」的旧写法（Vue 2.6 推荐 `v-slot:default="scope"`，但本项目使用旧写法）。第 4 章详细讲插槽。

### 10.1 完整案例：自己写一个作用域插槽组件

> 目标：自己写一个 `<user-list>`，让父组件决定每一行怎么显示。  
> 用法：新建 `slot-demo.html`，整段复制后用浏览器打开。

```html
<!DOCTYPE html>
<html lang="zh-CN">
<head>
  <meta charset="UTF-8">
  <title>作用域插槽完整案例</title>
  <style>
    li { margin: 8px 0; }
  </style>
</head>
<body>
  <div id="app">
    <h3>用户列表</h3>

    <!-- 父组件决定“每一行长什么样” -->
    <user-list :users="users">
      <template slot-scope="scope">
        <span>
          {{ scope.index + 1 }}. {{ scope.row.name }}
          （{{ scope.row.age }} 岁）
        </span>
        <button @click="remove(scope.index)">删除</button>
      </template>
    </user-list>
  </div>

  <script src="https://cdn.jsdelivr.net/npm/vue@2.6.12/dist/vue.js"></script>
  <script>
    // 子组件：只负责“列表结构”和“把当前行传出去”
    Vue.component('user-list', {
      props: {
        users: {
          type: Array,
          default: () => []
        }
      },
      template: `
        <ul>
          <li v-for="(user, index) in users" :key="user.id">
            <!-- 把 row 和 index 作为“插槽参数”传给父组件 -->
            <slot :row="user" :index="index"></slot>
          </li>
        </ul>
      `
    })

    new Vue({
      el: '#app',
      data: {
        users: [
          { id: 1, name: '张三', age: 28 },
          { id: 2, name: '李四', age: 32 },
          { id: 3, name: '王五', age: 25 }
        ]
      },
      methods: {
        remove(index) {
          this.users.splice(index, 1)
        }
      }
    })
  </script>
</body>
</html>
```

**关键点**：

| 位置 | 代码 | 作用 |
|---|---|---|
| 子组件 | `<slot :row="user" :index="index"></slot>` | 把当前行 `user` 和下标 `index` 作为插槽参数传出去 |
| 父组件 | `<template slot-scope="scope">` | 接收子组件传出来的参数，`scope` 是一个对象 |
| 父组件 | `scope.row` | 当前行的数据对象 |
| 父组件 | `scope.index` | 当前行的下标 |

**为什么需要作用域插槽**：

- 子组件负责「列表结构」：`ul`、`li`、`v-for`、`:key`；
- 父组件负责「每一行怎么显示」：显示名字、年龄、按钮；
- 两者通过 `<slot :row="user">` 把「当前行数据」传出去。

**和项目里的 `el-table` 对照**：

```html
<el-table-column prop="type" label="岗位类型">
  <template slot-scope="scope">
    <dict-tag :options="dict.type.PO_TYPE" :value="scope.row.flowCode" />
  </template>
</el-table-column>
```

- `el-table-column` 就是子组件；
- `:value="scope.row.flowCode"` 里的 `scope.row` 就是当前行；
- 原理和上面的 `<user-list>` 完全一样，只是 Element UI 帮你把 `ul/li/table` 都写好了。

**Vue 2.6+ 的新写法**（了解即可，项目里主要用旧写法）：

```html
<user-list :users="users">
  <template v-slot:default="scope">
    {{ scope.row.name }}
  </template>
</user-list>
```

**常见错误**：

- `slot-scope` 写在 `<user-list>` 上而不是 `<template>` 上：作用域不对；
- 子组件 `<slot>` 没有传 `:row`，父组件拿不到 `scope.row`；
- `scope` 只在 `<template slot-scope>` 内部有效，不能拿到外面用。

**练习**：

1. 在父组件里加一列「邮箱」，数据里补 `email` 字段；
2. 把子组件的 `:index="index"` 去掉，父组件改成 `scope.row.id` 删除；
3. 给 `<slot>` 起个名字 `<slot name="row" :row="user">`，父组件用 `v-slot:row` 接收。
