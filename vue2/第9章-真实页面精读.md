# 第 9 章 · 真实页面精读：两个页面，逐行拆开

> **这一章解决什么问题**：第 8 章你照着模板写了一个标准 CRUD 页。但项目里的页面不全是标准页——有的长着完全不同的骨架（Tab 页、左树右表页），还有不少历史代码、死代码和小瑕疵。这一章挑两个最有代表性的真实页面，**从第一行模板到最后一行方法**全部拆开，让你具备「拿到任意一个陌生 `.vue` 文件都能自己读下去」的能力。
>
> **学完标准**：给你一个没见过的页面文件，你能在 30 分钟内说清：它对应哪个菜单、调了哪些接口、页面分几块、每一块的数据从哪来、每个按钮点下去发生什么；能一眼看出哪些代码是死的、哪些写法有坑。
>
> **选的两个页面**：
>
> | 页面 | 文件 | 为什么选它 |
> |---|---|---|
> | 编号规则 | `src/views/conf/billRule/index.vue` | 不是表格页：Tab 切换 + 动态表单行 + 整体保存，模板写法很「非常规」 |
> | 岗位管理 | `src/views/system/position/index.vue` | 最典型的「左树右表」：树筛选列表、独立表单组件、成员选择器、字典标签 |

## 一、精读方法：拿到一个陌生页面，先做这五步

不要打开文件就从第一行逐字读。先建立全局印象，再往下钻。

| 步骤 | 做什么 | 在本章两个页面里 |
|---|---|---|
| ① 点界面 | 在浏览器里把页面上每个按钮、每个下拉都点一遍 | 编号规则：切 Tab、加行、删行、保存；岗位：点树节点、搜索、新增、修改、删除、岗位成员 |
| ② 找入口 | 这个页面从哪来？菜单 → 路由 → 文件路径 | 两个页面都由**后端菜单**下发动态路由（第 5 章 §10.1），文件路径与菜单组件路径对应 |
| ③ 找接口 | 看 `<script>` 顶部的 `import ... from '@/api/...'` | `api/conf/billRule.js`、`api/system/position.js` |
| ④ 读模板 | 按「布局 → 搜索 → 工具栏 → 表格/主体 → 分页 → 弹窗」切块 | 编号规则没有表格；岗位页五段齐全 |
| ⑤ 画数据流 | 哪份数据从接口来、存进哪个变量、被模板哪一段消费 | 见 §2.6、§3.8 的两张图 |

**一个很实用的判断**：先看 `<script>` 里 `data()` 返回了什么，就能猜出页面有哪些状态；再看 `created()` 里调了什么，就知道进页面先请求什么。这两段看完，页面已经懂了一半。

## 二、编号规则页：`src/views/conf/billRule/index.vue`

### 2.1 这个页面是干什么的

合同系统里很多单据要自动生成编号，比如合同编号、审批单号、归档号。编号不是乱生成的，而是由「规则」拼出来的，例如：

```
HT-20261017-0001
│   │         └─ 流水号（每次 +1，补零到 4 位）
│   └─────────── 日期（年月日）
└─────────────── 固定文本
```

页面上每一行就是编号规则的一个「片段」：文本、日期、流水号。规则可以加行、删行、调整顺序；不同类型（合同、审批单、归档……）各有一条规则，所以用 Tab 区分。

这解释了页面的两个特殊之处：

1. **没有列表表格**——它管理的不是「很多条数据」，而是「每一种编号的一条规则」；
2. **表单不是固定字段**——片段数量是用户动态增删的，所以模板里必然出现 `v-for`。

### 2.2 接口清单

来自 `src/api/conf/billRule.js`：

| 函数 | 方法 + URL | 文件行号 | 页面里谁在调 |
|---|---|---|---|
| `listBillRule(query)` | GET `/conf/billRule/list` | `:13-19` | `getList()`，进页面加载全部规则 |
| `getBillRule(id)` | GET `/conf/billRule/{id}` | `:22-27` | `handleUpdate()`（**本页实际没用到**） |
| `addBillRule(data)` | POST `/conf/billRule` | `:30-36` | `submitForm()` 新增分支 |
| `updateBillRule(data)` | PUT `/conf/billRule` | `:39-45` | `submitForm()` 修改分支 |
| `delBillRule(id)` | DELETE `/conf/billRule/{id}` | `:48-53` | `handleDelete()`（**本页没有入口**） |

> 注意：`getBillRule` 和 `delBillRule` 被 import 进来了，但页面上没有对应的按钮。这不是你看漏了，是**历史遗留**——这个页面从「标准 CRUD 页」改造成了「规则配置页」，删掉了表格，但没删干净。§2.7 会集中列这类问题。

### 2.4 模板逐块精读

#### 2.4.1 Tabs：`:1-14`

```html
<el-tabs v-model="activeName" @tab-click="handleClick">
  <el-tab-pane
    v-for="item in billRuleList"
    :key="item.id"
    :label="item.name"
    :name="item.code"
  />
</el-tabs>
```

逐行看：

| 写法 | 含义 |
|---|---|
| `v-model="activeName"` | 当前选中的 Tab。`activeName` 里存的是 Tab 的 **name**，不是下标 |
| `v-for="item in billRuleList"` | Tab 不是写死的，而是**接口返回几条规则就生成几个 Tab** |
| `:key="item.id"` | 列表渲染必须给稳定 key（第 2 章 §7.3） |
| `:label="item.name"` | 显示给用户看的文字，如「合同编号规则」 |
| `:name="item.code"` | Tab 的**程序标识**，如 `CONTRACT_CODE`；`v-model` 绑的是它 |
| `@tab-click="handleClick"` | 用户点 Tab 时触发，参数是当前 Tab 对象 |

**关键认知**：Element UI 的 `el-tabs` 只负责「切换高亮」和「告诉你切到了哪个 name」，**Tab 内容并不放在 `el-tab-pane` 里**——注意这里是自闭合的 `<el-tab-pane ... />`。真正的表单在所有 Tab 下方共用一份，靠 `handleClick` 换数据。这是这个页面最不常规、也最值得学的一点。

#### 2.4.2 表单绑定的是「当前选中的那条规则」：`:15-24`

```html
<el-form ref="form" :model="currentData" :rules="rules" label-width="100px">
  <h3>规则设置（编号：{{ currentData.code }}）:</h3>
```

- `:model="currentData"`：整个表单的数据源是 `currentData`（当前选中的规则对象），不是常见的 `form`。
- `{{ currentData.code }}`：插值显示规则编码（第 2 章 §2.1）。
- `:rules="rules"`：校验规则，后面按 `prop` 去 `currentData` 里取字段（第 8 章 §4.2）。

**问：`rules` 里声明了 `name`、`code`、`thisNumber` 等必填，为什么页面上没看到对应输入框？**

答：只有模板里写了 `el-form-item` 且 `prop="xxx"` 的字段才会被校验。`rules` 里多出来的键是**没有消费者的配置**，不会报错，也不起作用。下面 §2.7 会把这个也列为历史遗留。

#### 2.4.3 动态行：`:46-100`

```html
<el-row v-for="(item, index) in currentData.ruleArray" :key="item.value">
  <el-col :span="1">{{ index + 1 }}</el-col>
  <el-col :span="6">
    <el-select
      v-model="currentData.ruleArray[index].type"
      :disabled="form.id"
      @change="typeChange($event, currentData.ruleArray[index])"
    >
      <el-option
        v-for="dict in dict.type[currentData.code + '_TYPE']"
        :key="dict.value"
        :label="dict.label"
        :value="dict.value"
      />
    </el-select>
  </el-col>
  <el-col :span="6">
    <el-input
      v-if="currentData.ruleArray[index].type == '1'"
      v-model="currentData.ruleArray[index].string"
      placeholder="请输入文本内容"
    />
    <el-input
      v-if="currentData.ruleArray[index].type == '2'"
      value="格式：年月日"
      :disabled="true"
    />
  </el-col>
  <el-col :span="4">
    <el-link icon="el-icon-delete" @click="deleteLine(currentData.ruleArray, index)">删除</el-link>
  </el-col>
</el-row>
<el-link icon="el-icon-circle-plus-outline" @click="addNewLine(currentData.ruleArray)">添加一行</el-link>
```

一块一块拆：

**① `v-for` 遍历的是什么**

`currentData.ruleArray` 是一个数组，后端实体里它是 `JSONArray` 类型：

- `zxcm-contract/src/main/java/com/ruoyi/conf/domain/vo/ConfBillRuleVo.java:74` — `private JSONArray ruleArray = new JSONArray();`
- 数组每项形如 `{ "type": "1", "string": "HT-" }`（`ConfBillRuleServiceImpl.java:150-158` 按 `type` / `string` 取值校验）。

所以「规则」在数据库里是一个 JSON 字符串，前端拿到后直接当数组用。

**② 下标寻址：`currentData.ruleArray[index].type`**

动态行有两种绑定写法：

```html
<!-- 写法 A：用 v-for 的 item -->
<el-input v-model="item.string" />

<!-- 写法 B：用 index 重新定位（本项目用这种） -->
<el-input v-model="currentData.ruleArray[index].string" />
```

两种都能改到同一个对象，效果一样。项目统一用 B，好处是**一眼能看出数据挂在哪**，坏处是路径长、容易写错下标。理解一个即可。

**③ `@change="typeChange($event, currentData.ruleArray[index])"`**

- `$event` 是事件回调的第一个参数。`el-select` 的 `change` 事件传的是**新选中的值**，所以 `param1` 是新的 `type`。
- 第二个参数把当前行对象传过去，`typeChange` 里执行 `param2.string = ''`（`:278-280`）——**换了类型，就把上一类型的文本清空**，否则「文本片段」改成「日期片段」后还残留一段文字，保存时数据就脏了。

**④ 按类型显示不同输入控件**

```html
<el-input v-if="...type == '1'" v-model="...string" />   <!-- 文本：可输入 -->
<el-input v-if="...type == '2'" value="格式：年月日" :disabled="true" /> <!-- 日期：只读展示 -->
```

类型 3/4/5 在本模板里**没有任何输入控件**——它们是流水号类型，不需要额外参数。后端校验里也能看到这个分类：`ConfBillRuleServiceImpl.java:153` 要求 `type=1` 必须有 `string`，`:156` 把 `type=3/4/5` 计为流水号。

**⑤ 类型下拉的选项从哪来**

```html
v-for="dict in dict.type[currentData.code + '_TYPE']"
```

`dict.type` 是一个「字典类型 → 选项数组」的映射（`src/utils/dict/Dict.js:20,36`）。这里用**拼接**的方式动态取字典：

```
currentData.code = 'CONTRACT_CODE'
→ 'CONTRACT_CODE' + '_TYPE' = 'CONTRACT_CODE_TYPE'
→ dict.type['CONTRACT_CODE_TYPE'] = [{ label: '文本', value: '1' }, ...]
```

这也是为什么 `dicts` 选项里要提前列出 9 个字典类型（`:181-191`）——进页面时统一把选项拉回来，Tab 切到哪个就用哪个。

**⑥ 增行 / 删行**

```js
addNewLine(data) { data.push({ type: '1' }) },
deleteLine(data, index) { data.splice(index, 1) }
```

这两个方法直接操作数组。**`push` 和 `splice` 是 Vue 2 能监听到的数组方法**（第 10 章 §2.4），所以页面会立即更新。如果你写 `data[index] = ...` 或 `data.length = 0`，Vue 2 就监听不到（第 3 章 §9.2）。

#### 2.4.4 流水号设置：`:102-134`

```html
<el-input-number v-model="currentData.startNumber" :min="1" :max="1000" />
<el-input-number v-model="currentData.numberLength" :min="2" :max="10" />
```

`el-input-number` 是数字输入框，`v-model` 拿到的就是 number 类型，不用自己 `parseInt`。`:min/:max` 只是 UI 限制，后端仍会再校验。

#### 2.4.5 保存按钮、死代码与空弹窗：`:135-166`

```html
<el-button :loading="buttonLoading" type="primary" @click="submitForm">保存</el-button>

<template v-if="false">
  <h3>扩展设置:</h3>
  ...
</template>

<el-dialog :title="title" :visible.sync="open" width="500px" append-to-body ... />
```

- `:loading="buttonLoading"`：提交中显示转圈并禁用按钮，防止连点（配合请求层的防重复提交，第 7 章 §7.3）。
- `<template v-if="false">`：**永远不会渲染**的代码块。`template` 本身不产生 DOM，`v-if` 为假时里面整段被跳过。这是开发时留下的半成品（「扩展设置」），上线前没删。
- 最后的 `el-dialog` 是**空弹窗**：有标题、有开关，但里面没有任何内容，页面上也没有任何按钮把 `open` 设为 `true`。同样是改造时留下的残骸。

### 2.5 `<script>` 逐段精读

#### 2.5.1 `dicts`：项目自定义的全局选项

```js
export default {
  name: 'BillRule',
  dicts: ['APPROVE_ORDER_RULE_TYPE', ...]
}
```

`dicts` 不是 Vue 自带选项。项目在 `src/main.js:180` 调用 `DictData.install()`，它注册了一个**全局 mixin**（`src/utils/dict/index.js:6-32`）：只要组件写了 `dicts`，就自动在 `data` 里注入 `this.dict`，并在 `created` 时按类型请求字典。

所以：

```html
dict.type.PO_TYPE          <!-- 选项数组：[{label, value}] -->
dict.label.PO_TYPE['1']    <!-- 反查：value → 文字 -->
```

这套机制替代了每个页面手写 `getDicts().then(...)`，是 RuoYi 系的惯例。面试里如果问「项目里下拉框的选项怎么来的」，这就是答案。

#### 2.5.2 `data()`：`:192-264`

| 字段 | 用途 | 备注 |
|---|---|---|
| `activeName: 'APPROVE_ORDER_RULE'` | 当前 Tab 名 | 初始值只是占位，`getList` 会覆盖 |
| `buttonLoading` | 保存按钮 loading | 真正被模板使用 |
| `loading: true` | 加载遮罩 | **模板里没有用**（没有用到它的元素），死状态 |
| `ids/single/multiple/showSearch/total/title/open` | 标准 CRUD 页遗留 | 只有 `title/open` 被空弹窗用到 |
| `billRuleList` | 规则列表 | Tab 数据源 |
| `currentData` | 当前规则 | 表单数据源 |
| `form` | 另一套表单对象 | 只有 `handleUpdate` 用，而它没有入口 |
| `rules` | 校验规则 | 只有 `startNumber/numberLength` 真正生效 |

> 特别看 `currentData` 的初始值：`{ rules: [{ type: '1', string: 'abc' }] }`（`:216-218`）。它写的是 `rules`，而模板读的是 `ruleArray`——**字段名都对不上**。这进一步证明它是从旧版复制来的占位值；页面一进 `getList()` 就会被接口数据整体替换，所以不影响运行。

#### 2.5.3 `created` + `getList`：`:265-300`

```js
created() { this.getList() },

getList() {
  this.loading = true
  listBillRule(this.queryParams).then((response) => {
    this.billRuleList = response.rows
    this.total = response.total
    this.activeName = response.rows[0].code
    this.currentData = response.rows[0]
    this.loading = false
  })
}
```

流程：

1. 进页面立刻请求全部规则；
2. 拿到 `rows` 赋给 `billRuleList`，Tab 自动生成；
3. 默认选中第一条：`activeName = rows[0].code`，`currentData = rows[0]`。

**隐患**：`response.rows[0]` 没有判空。如果数据库里一条规则都没有（或接口返回空数组），这里会抛 `Cannot read properties of undefined (reading 'code')`，页面白屏。写健壮代码应该是：

```js
const first = response.rows[0]
if (first) {
  this.activeName = first.code
  this.currentData = first
}
```

这是第 11 章「常见坑」里会反复出现的模式：**`[0]` 之前先判长度**。

#### 2.5.4 `handleClick`：`:269-277`

```js
handleClick(tab, event) {
  for (var i in this.billRuleList) {
    if (tab.name == this.billRuleList[i].code) {
      this.currentData = this.billRuleList[i]
    }
  }
}
```

- `tab` 是 Element 传的 Tab 对象，`tab.name` 就是 `el-tab-pane` 上 `:name="item.code"` 的值；
- 遍历列表找到对应规则，赋给 `currentData`，表单内容随之整体切换。

**一个值得注意的细节**：`this.currentData = this.billRuleList[i]` 是**引用赋值**。之后你在表单里改 `currentData.startNumber`，改的其实就是 `billRuleList` 里的那个对象。因为页面上没有别处展示这份列表（Tab 只显示 `name`），所以不会看到「列表跟着变」的副作用。但如果以后加一个列表预览，这里就要注意浅拷贝（第 11 章 坑 5）。

#### 2.5.5 `submitForm`：`:362-389`

```js
submitForm() {
  this.$refs['form'].validate((valid) => {
    if (valid) {
      this.buttonLoading = true
      if (this.currentData.id != null) {
        updateBillRule(this.currentData).then(() => {
          this.$modal.msgSuccess('修改成功')
          this.open = false
          // this.getList();   ← 被注释掉了
        }).finally(() => { this.buttonLoading = false })
      } else {
        addBillRule(this.currentData).then(() => {
          this.$modal.msgSuccess('新增成功')
          this.open = false
          this.getList()
        }).finally(() => { this.buttonLoading = false })
      }
    }
  })
}
```

逐点：

1. `this.$refs['form'].validate(callback)`：触发整张表单校验，`valid` 为 `true` 才提交（第 8 章 §5.6）。
2. `currentData.id != null`：有 id 就是修改，没有就是新增。
3. 修改成功后**没有重新拉列表**（`getList` 被注释）。因为 `currentData` 就是列表项的引用，本地数据已经是最新的；但 `thisNumber` 这类由后端计算、前端不知道的字段不会刷新。属于「能用但不严谨」。
4. `finally` 里统一关 loading，成功失败都会执行。
5. `this.$modal` 是项目挂到 `Vue.prototype` 上的全局对象（`main.js` 中 `plugins`），封装了 Element 的 `$message/$confirm`（第 7 章 §6.2）。

#### 2.5.6 「僵尸方法」们：`:301-417`

| 方法 | 为什么说它死了 |
|---|---|
| `reset()` `:307-326` | 只被 `cancel()` 调；`cancel()` 没有被模板调用 |
| `cancel()` `:302-305` | 模板无入口 |
| `handleQuery()` `:328-331` | 模板没有搜索按钮 |
| `resetQuery()` `:333-336` | 同上 |
| `handleSelectionChange()` `:338-342` | 页面没有多选表格 |
| `handleAdd()` `:344-348` | 页面没有「新增」按钮 |
| `handleUpdate()` `:350-360` | 页面没有「修改」按钮；它把数据塞进 `this.form`，而提交读的是 `currentData`，**即使被调用也不会生效** |
| `handleDelete()` `:391-407` | 页面没有「删除」按钮 |
| `handleExport()` `:409-417` | **模板里没有导出按钮**，但方法本身写法是标准的：`this.download(url, params, filename)` |

这些方法大多来自代码生成器生成的「标准 CRUD 模板」，改造页面时没删。**读项目时学会识别它们，比逐个读懂更重要**——不要花时间研究不会执行的代码。

#### 2.5.7 `handleExport` 顺带看 `this.download`

```js
handleExport() {
  this.download('conf/billRule/export', { ...this.queryParams }, `billRule_${new Date().getTime()}.xlsx`)
}
```

`download` 在 `main.js:128` 挂到原型，实现在 `utils/request.js:283-325`：以 `responseType: 'blob'` 发请求，拿到二进制流后用临时 `<a>` 标签触发下载。文件名带时间戳，避免重复下载时覆盖。这个模式在项目所有「导出」按钮里都一样。

#### 3.4.2 搜索区：`:28-66`

```html
<el-form @submit.native.prevent>
  <el-col :span="6">
    <el-form-item label="关键字">
      <el-input v-model="params.keyword" clearable @keyup.enter.native="search" />
    </el-form-item>
  </el-col>
  <el-col :span="6">
    <el-form-item label="岗位类型">
      <el-select v-model="params.flowCode">
        <el-option v-for="dict in dict.type.PO_TYPE" :key="dict.value" :label="dict.label" :value="dict.value" />
      </el-select>
    </el-form-item>
  </el-col>
  <el-col :span="6">
    <el-form-item>
      <el-button @click="search()">搜索</el-button>
      <el-button @click="reset()">重置</el-button>
    </el-form-item>
  </el-col>
</el-form>
```

两个 `.native` 是这一块的重点：

**① `@submit.native.prevent`**

`el-form` 在浏览器里最终还是一个 `<form>`。原生表单按回车会提交并刷新页面。这里做两件事：

- `.native`：把事件绑到组件的**根 DOM 元素**上，而不是监听组件自定义的 `submit` 事件；
- `.prevent`：等价于 `event.preventDefault()`，阻止浏览器默认提交行为。

所以它是「**别刷新页面，回车由输入框自己的 keyup 处理**」的组合拳。

**② `@keyup.enter.native="search"`**

监听原生键盘事件，只在按 Enter 时触发。`input` 是 Element 组件，不加 `.native` 监听不到 DOM 的 `keyup`（第 2 章 §4.3）。

**③ 岗位类型下拉**

`dict.type.PO_TYPE` 来自 `dicts: ['PO_TYPE']`（`:160`），机制同 §2.5.1。注意它绑定的是 `params.flowCode`（流程编码），不是 `params.type`——这个项目里岗位类型实际就是用流程编码字段存的，看后端和 `Form.vue` 也能对上。

#### 3.4.4 `JTable`：`:86`


`JTable` 是项目的表格封装，源码在 `src/components/JTable/index.vue`：

```html
<el-table
  ref="JTable"
  :data="data"
  v-bind="$attrs"
  v-on="$listeners"
>
  <el-table-column v-if="hasC" type="selection" ... />
  <el-table-column v-if="hasNO" type="index" label="序号" ... />
  <slot />
</el-table>
```

它做了四件事：

1. **默认加一列「序号」**（`hasNO` 默认 `true`，`:39-42`）；
2. 可选加多选列（`hasC`，默认 `false`）；
3. 用 `<slot />` 把父组件写的 `<el-table-column>` 原样塞进 `el-table`；
4. `v-bind="$attrs"` / `v-on="$listeners"`：把父组件写在 `<JTable>` 上的**非 props 属性和事件监听继续传给内部 `el-table`**（`$attrs`/`$listeners` 是 Vue 2.4+ 的透传机制）。

一句话：**`JTable` 不是新表格，只是给 `el-table` 加了一层默认配置**。父组件写法和普通 `el-table` 几乎一样，所以读起来不费劲。

它还监听 `data` 变化（`:65-80`），变化后延时执行 `doLayout()`：

```js
doLayout() {
  setTimeout(() => {
    this.$nextTick(() => {
      this.$refs.JTable.doLayout()
    })
  }, 100)
}
```

`el-table.doLayout()` 会重新计算列宽。表格在隐藏容器里（比如弹窗、Tab 页）第一次渲染时，宽度可能是 0，出现列错位；数据变化后等 DOM 更新完、再等 100ms 重算一次，就能修正。这是 Element UI 表格的常见补丁，不是业务逻辑。

### 3.5 `<script>` 逐方法精读

#### 3.5.1 `data()`：`:161-183`

核心状态：

```js

  flowCode: undefined,    // 岗位类型筛选
```

#### 3.5.2 `created` → `getTreeselect` → `initData`：`:185-213`

```js
created() { this.getTreeselect() },

getTreeselect() {
  this.treeLoading = true
  treeselect({ status: '0' })
    .then((response) => {
      this.treeData = response.data
      this.treeLoading = false
      this.initData()          // ← 树加载完才查列表
    })
    .catch(() => { this.treeLoading = false })
},

initData() {
  this.listLoading = true
  getPositionList(this.params)
    .then((res) => {
      this.tableData = res.rows
      this.total = res.total
      this.listLoading = false
    })
    .catch(() => { this.listLoading = false })
}
```

为什么列表请求放在树的 `.then` 里，而不是和树并行？

- 从功能上看两者没有硬依赖（列表查询不依赖树数据），可以并行；
- 但这样写有明确的「先有筛选条件、再查列表」的顺序感，且组织树加载失败时不会白白发一次列表请求。

`{ status: '0' }` 是过滤条件：只要启用状态的组织。

**注意 `initData` 里 `listLoading = false` 写在 `.then` 和 `.catch` 两处**，没有用 `.finally`。写法能跑，但重复；第 8 章推荐用 `.finally` 统一收尾。

#### 3.5.3 `search` / `reset` / `handleNodeClick`：`:214-231`

```js
search() {
  this.params = { ...this.params, pageNum: 1, pageSize: 10 }
  this.initData()
},
reset() {
  this.params.keyword = ''
  this.params.flowCode = undefined
  this.search()
},
handleNodeClick(data) {
  if (this.params.organizeId === data.id) return
  this.params.organizeId = data.id
  this.type = data.type
  this.reset()
}
```

- `search` 用对象展开新建了一个 `params` 对象，目的只是改页码和条数。**注意它把 `pageSize` 从初始的 20 改成了 10**——第一次进页面是 20 条/页，只要点一次搜索就变成 10 条/页。这是一个不一致（小瑕疵）。
- `reset` 只清空两个筛选条件，**不清 `organizeId`**——保留了左树选择，符合「重置搜索条件」而不是「重置整个页面」的语义。
- `handleNodeClick` 先判断「点的还是当前节点」就直接返回，避免重复请求；否则设置 `organizeId`，再走 `reset()`（清关键字/类型 + 回到第 1 页 + 查询）。
- `this.type = data.type`：给 `data()` 里的 `type` 赋值，但**全文件没有任何地方读 `this.type`**，是死状态。

#### 3.5.4 `handleAddEdit`：`:233-241`

```js

  this.formVisible = true
  this.$nextTick(() => {
    this.$refs.Form.init(id, this.params.organizeId)
  })
}
```

为什么必须 `$nextTick`？

`formVisible = true` 只是把数据改了，Vue 要等本轮同步代码执行完、进入异步更新队列，才会真正创建 `Form` 组件。**你立刻访问 `this.$refs.Form` 还是 `undefined`**。`$nextTick` 的回调在 DOM 更新之后执行，那时 ref 才有值（第 3 章 §8.2、第 10 章 §4）。

第二个参数 `this.params.organizeId`：新增岗位时，默认把当前左树选中的组织带进表单，减少用户操作。

### 3.6 子组件 `Form.vue` 精读

文件：`src/views/system/position/Form.vue`

#### 3.6.1 弹窗骨架：`:1-10`

```html

  :close-on-click-modal="false"
```

- 标题用三元表达式：有 id 是修改，没有是新增；
- `:visible.sync="visible"`：点右上角 × 时，`el-dialog` 会 `$emit('update:visible', false)`，同步回父组件的 `visible`（第 4 章 §6）；
- 禁止点遮罩关闭、禁止 Esc 关闭，防止误触丢失填写内容。

#### 3.6.2 表单与校验：`:11-64`

```html
<el-form ref="dataForm" :model="dataForm" :rules="dataRule" label-width="90px">
  <el-form-item label="所属组织" prop="organizeId">
    <treeselect v-model="dataForm.organizeId" :options="treeData" ... />
  </el-form-item>
  ...
  <el-form-item label="岗位类型" prop="flowCode">
    <el-select v-model="dataForm.flowCode"> ... </el-select>
  </el-form-item>
  <el-form-item label="流程编码" prop="flowCode">
    <el-input v-model="dataForm.flowCode" readonly />
  </el-form-item>
```

三个值得注意的点：

1. **`treeselect` 是组件级 `v-model`**：`value` + `input` 事件的标准实现，绑定的就是一个 id 值。它来自第三方库 `@riophae/vue-treeselect`，在 `:75-76` 局部引入并加载了 CSS。
2. **两个表单项用了同一个 `prop="flowCode"`**：一个是「岗位类型」下拉（写入 `dataForm.flowCode`），一个是只读的「流程编码」输入框（显示同一个值）。从产品角度像是「选类型自动带出编码」，但用同一个字段、同一个 prop 不是好写法：校验会重复执行，语义也不清晰。更合理的是类型存 `type`、编码存 `flowCode`（`data()` 里其实有 `type: ''`，但没有任何表单项绑定它）。
3. **自定义校验器**：

```js
fullName: [
  { required: true, message: '请输入岗位名称', trigger: 'blur' },
  { validator: this.formValidate('fullName', '岗位名称不能含有特殊符号'), trigger: 'blur' },
  { max: 50, message: '岗位名称最多为50个字符！', trigger: 'blur' }
]
```

`formValidate` 不是组件方法，而是项目挂到 `Vue.prototype` 上的全局函数（`main.js:141` 挂载，实现在 `src/utils/formValidate.js:63-73`）。它返回一个 Element 要求的校验函数 `(rule, value, callback) => {}`：

```js
const formValidate = (type, msg) => {
  return (rule, value, callback) => {
    const reg = regularList[type] ? regularList[type].rule : type
    if (!reg.test(value)) callback(new Error(msg))
    else callback()
  }
}
```

`regularList` 里预置了手机号、身份证、编码、中文名等常用正则（`:4-53`）。这是「项目自造的小工具函数」，面试问「表单校验怎么做」时可以作为加分细节。

#### 3.6.3 `init`：`:144-163`

```js
init(id, organizeId) {
  this.visible = true
  this.dataForm.id = id || ''
  this.formLoading = true
  this.$nextTick(() => {
    this.$refs['dataForm'].resetFields()

    treeselect({ status: '0' }).then((response) => {
      this.treeData = response.data
    })

    if (this.dataForm.id) {
      getPositionInfo(this.dataForm.id).then((res) => {
        this.dataForm = res.data
      })
    } else {
      this.dataForm.organizeId = organizeId
    }
    this.formLoading = false
  })
}
```

流程：

1. 打开弹窗；
2. `$nextTick` 后表单已经渲染，才能 `resetFields()` 清掉上次的校验提示和值；
3. 拉组织树选项；
4. 修改模式 → 查详情并整体赋给 `dataForm`；新增模式 → 把父组件传的组织 id 填上。

**两个问题**：

- `this.formLoading = false` 写在请求发出之后、没有等 Promise，所以 loading 遮罩几乎立刻消失，**起不到加载提示作用**。正确做法是放进 `.then/.finally`。
- `resetFields()` 依赖表单项的 `prop` 和 `:model` 正确绑定；它会把字段恢复成**组件创建时的初始值**，这也是为什么 `dataForm` 里要预先声明所有字段（`:87-97`）。

#### 3.6.4 提交：`:167-190`

```js
dataFormSubmit() {
  this.$refs['dataForm'].validate((valid) => {
    if (valid) {
      this.btnLoading = true
      const formMethod = this.dataForm.id ? updatePosition : createPosition
      formMethod(this.dataForm).then((res) => {
        this.$message({
          message: res.msg,
          type: 'success',
          duration: 1500,
          onClose: () => {
            this.visible = false
            this.btnLoading = false
            this.$emit('refreshDataList')
          }
        })
      }).catch(() => { this.btnLoading = false })
    }
  })
}
```

- `const formMethod = 有id ? 修改 : 新增`：把函数当值赋给变量，再统一调用。**函数是一等公民**，这是 JS 基础，但读项目时很常见（`:171`）。
- 成功后 `$emit('refreshDataList')`，父组件在模板上监听（`:147`），触发 `initData` 刷新表格。
- 失败时关闭 loading，但**没有重新抛出错误**；请求拦截器已经弹过错误提示（第 7 章 §7.4）。

#### 3.7.1 穿梭框

#### 3.7.2 `init`：`:50-80`

```js
init(id, fullName, type) {
  this.visible = true
  this.dataForm.objectId = id
  this.dataForm.objectType = type
  this.dataForm.userIds = []
  this.loading = true
  this.$nextTick(() => {
    this.$refs.transfer && (this.$refs.transfer.filterText = '')
    if (type === 'Position') this.pageTitle = '岗位成员' + '- ' + fullName

    request({ url: '/conf/treeSelect/userSelect', method: 'get' }).then((res) => {
      this.treeData = res.data
      getUserRelationList(this.dataForm.objectId).then((res) => {
        res.data.forEach((element) => { element.id = element.userId })
        this.dataForm.userIds = res.data
        this.loading = false
      })
    })
  })
}
```

几个值得学的写法：

- **直接调用 `request`**：`request` 就是 axios 实例（第 7 章 §7.2），这里为了一个临时接口绕过了 `api/` 封装。项目里少量存在这种写法，不是最佳实践，但能工作。
- **`element.id = element.userId`**：穿梭框认 `id` 字段，后端成员关系返回的是 `userId`，所以补一个 `id`。这是**前端适配后端数据结构**的典型小改造。
- **`this.$refs.transfer && (...)`**：`$nextTick` 时如果 `v-if` 还没渲染出子组件，ref 可能是 `undefined`，加个短路保护。
- **嵌套请求**：先拿用户树，再拿已选成员。两者无依赖，其实可以并行（`Promise.all`），这里写成了串行。

## 四、两个页面放一起看：标准页 vs 定制页

| 维度 | 标准 CRUD 页（第 8 章 / 岗位页） | 定制页（编号规则） |
|---|---|---|
| 骨架 | 搜索 → 工具栏 → 表格 → 分页 → 弹窗 | Tabs → 表单 → 动态行 → 保存 |
| 数据主形态 | 数组 + 分页（`rows`/`total`） | 单对象（`currentData`） |
| 模板重点 | `v-for` 渲染列、作用域插槽 | `v-for` 渲染**表单行** |
| 新增/修改 | 弹窗 + 表单校验 | 直接改当前对象 + 整体 PUT |
| 复用方式 | 复制整个页面换字段 | 在旧标准页上「减法改造」 |
| 读法 | 先看 API 再看列 | 先看 `data()` 再看动态行绑定 |

**结论**：项目里绝大多数业务页都是标准页（岗位页是代表）；少数配置页是定制页（编号规则页是代表）。遇到新页面，先用「有没有表格 + 分页」判断它属于哪一类，再套对应读法。

再看两个页面的共性——**它们都在做同一件事**：

```
用户操作 → 改 data → Vue 自动更新视图
             ↑
       接口返回 → 改 data
```

模板里没有一行「手动操作 DOM」。这就是第 1 章讲的**数据驱动**：你只需要维护数据，Vue 负责把数据映射成界面。现在你应该能在真实页面里随处看到这条主线。

## 七、下一章前瞻

到这里，你已经把项目的两个代表性页面拆到了每一行。第 10 章开始回答「为什么」：
