## 一、Vue 基础（1~6）

### Q1. 说说你对 MVVM 和数据驱动的理解

**一句话**：MVVM 是把「视图（View）」和「数据（Model）」通过「视图模型（ViewModel）」双向连接起来；Vue 的核心是**数据驱动视图**——你只改数据，Vue 负责把变化映射到 DOM。

**展开**：

- 传统 jQuery 写法：先找 DOM，再改 DOM，数据和界面是两份状态，容易不同步；
- Vue 写法：模板里写 `{{ list }}`，代码里只写 `this.list = res.rows`，DOM 由框架更新；
- ViewModel 在 Vue 里就是组件实例：`data` 是 Model，模板是 View，`this` 是桥梁。

**项目印证**：`position/index.vue:202-213` 的 `initData()` 只做了 `this.tableData = res.rows`，表格自动刷新，没有一行 DOM 操作。

### Q2. Vue 2 和 Vue 3 有什么区别？

**一句话**：Vue 3 用 `Proxy` 重写响应式、用 Composition API 组织逻辑、用 `createApp` 创建应用、用 Pinia 替代 Vuex、移除 `filters`，并改善了 Tree-shaking 和性能。

**展开**（挑 4~5 点即可）：

| 维度 | Vue 2 | Vue 3 |
|---|---|---|
| 创建应用 | `new Vue({ el, render })` | `createApp(App).mount('#app')` |
| 响应式 | `Object.defineProperty` | `Proxy` |
| 逻辑复用 | mixin / 高阶组件 | Composition API（`setup`） |
| 状态管理 | Vuex 3 | Pinia（Vuex 4 也可用） |
| 过滤器 | `filters` | 已移除，用方法/计算属性 |
| 多根节点 | 只能一个根 | 支持 Fragment |
| 性能 | — | 静态提升、Patch Flag、更小的包 |

**项目印证**：本项目是 Vue 2.6.12（`package.json:64`），入口是 `main.js:209-214` 的 `new Vue({ el: '#app', router, store, render: h => h(App) })`。

### Q3. `v-if` 和 `v-show` 的区别？怎么选？

**一句话**：`v-if` 是真正的条件渲染，条件为假时不渲染/销毁；`v-show` 始终渲染，只切换 `display`。

**展开**：

- 初始渲染：`v-if` 为假时开销小；`v-show` 无论如何都要渲染；
- 切换开销：`v-if` 要销毁/重建组件和事件；`v-show` 只改样式；
- 选择：不常切换（弹窗、权限块）用 `v-if`；频繁切换（Tab、折叠面板）用 `v-show`；
- `v-if` 与 `v-for` 同用时，Vue 2 先执行 `v-for`。

**项目印证**：弹窗用 `v-if`（`position/index.vue:147-148`）；权限按钮用 `v-hasPermi` 直接移除 DOM，比 `v-show` 更彻底（`directive/permission/hasPermi.js:89-91`）。

### Q4. `computed`、`watch`、`methods` 有什么区别？

**一句话**：`computed` 有缓存、依赖不变不重算，适合「由已有数据推导新数据」；`watch` 适合「数据变化时执行副作用」；`methods` 每次调用都执行，适合事件处理。

**展开**：

- `computed` 本质是计算 Watcher，`dirty` 标记控制缓存；模板里多次使用只算一次；
- `watch` 支持 `immediate`（立即执行）和 `deep`（深度监听）；异步请求、路由变化常放这里；
- `methods` 不缓存，模板里 `{{ fn() }}` 每次渲染都会调用，别在模板里做重计算。

**项目印证**：

- `login.vue:170-179` 用 `computed` 拼登录表单的校验规则；
- `user/index.vue:702-706` 用 `watch` 监听部门名变化；
- `Pagination/index.vue:68-85` 用 `computed` 的 get/set 实现 `.sync` 双向绑定。

### Q5. Vue 的生命周期有哪些？父子组件执行顺序？

**一句话**：创建阶段 `beforeCreate → created → beforeMount → mounted`，更新阶段 `beforeUpdate → updated`，销毁阶段 `beforeDestroy → destroyed`；`keep-alive` 额外有 `activated/deactivated`。

**展开**：

- `created`：实例创建完，data/methods 可用，**DOM 还没生成**；
- `mounted`：DOM 挂载完，可以操作 DOM、初始化第三方库；
- `beforeDestroy`：清理定时器、事件监听；
- 父子顺序（初始渲染）：父 `beforeCreate/created/beforeMount` → 子 `beforeCreate/created/beforeMount/mounted` → 父 `mounted`；
- 更新时：父 `beforeUpdate` → 子 `beforeUpdate/updated` → 父 `updated`；
- 销毁时：父 `beforeDestroy` → 子 `beforeDestroy/destroyed` → 父 `destroyed`。

**项目印证**：`Screenfull/index.vue:17-22` 在 `mounted` 初始化、`beforeDestroy` 清理；`tool/gen/index.vue:234-244` 同时用了 `created` 和 `activated`。

### Q6. `v-model` 的原理？组件上的 `v-model` 怎么实现？

**一句话**：表单元素上是「`:value` + `@input`」的语法糖；组件上是「`:value` + `@input`」或自定义 `model` 选项。

**展开**：

```html
<input v-model="msg" />
<!-- 等价于 -->
<input :value="msg" @input="msg = $event.target.value" />
```

组件：

```html
<my-input v-model="msg" />
<!-- 等价于 -->
<my-input :value="msg" @input="msg = $event" />
```

```js
export default {
  props: ['value'],
  methods: {
    onInput(e) { this.$emit('input', e.target.value) }
  }
}
```

`.sync` 则是 `:prop` + `@update:prop` 的语法糖，可绑定多个属性。

**项目印证**：`Form.vue:19-24` 的 `treeselect v-model` 是第三方组件的标准 v-model；`Form.vue:6` 的 `:visible.sync` 是 `.sync`。

## 二、组件化（7~12）

### Q7. 父子组件怎么通信？有哪些方式？

**一句话**：父传子用 `props`；子传父用 `$emit`；跨层级用 `provide/inject` 或 Vuex；任意组件用事件总线；父调子用 `ref`。

**展开**（按场景选）：

| 场景 | 方式 |
|---|---|
| 父 → 子 | `props` |
| 子 → 父 | `$emit('event', payload)` |
| 双向 | `v-model` / `.sync` |
| 父调子方法 | `ref` |
| 子调父方法 | `$parent`（不推荐） |
| 兄弟/任意 | EventBus（`new Vue()`）或 Vuex |
| 深层注入 | `provide/inject`（项目里主要是第三方库用） |

**项目印证**：

- props：`Pagination/index.vue:23-63`；
- `$emit`：`Form.vue:181`、`RightToolbar/index.vue:57`；
- ref：`position/index.vue:233-241`；

### Q8. `.sync` 的本质是什么？

**一句话**：`.sync` 是「prop + `update:propName` 事件」的语法糖。

```html
<comp :visible.sync="show" />
<!-- 展开 -->
<comp :visible="show" @update:visible="show = $event" />
```

**注意**：

- 子组件要 `this.$emit('update:visible', false)`；
- 事件名里的 prop 名会被 camelize，例如 `:show-search.sync` 对应 `update:showSearch`；
- Vue 3 移除了 `.sync`，统一用 `v-model:propName`。

**项目印证**：`RightToolbar/index.vue:57` 发 `update:showSearch`；`position/index.vue:141-142` 的 `:page.sync` / `:limit.sync`。

### Q9. 插槽有哪几种？作用域插槽是什么？

**一句话**：默认插槽、具名插槽、作用域插槽。作用域插槽让**子组件把内部数据传给父组件的插槽内容**。

```html
<!-- 子 -->
<slot name="item" :row="row" :index="index" />

<!-- 父 -->
<template slot="item" slot-scope="scope">
  {{ scope.row.name }}
</template>
```

**项目印证**：`position/index.vue:90-95` 用 `slot-scope="scope"` 拿到当前行，再传给 `dict-tag`；`Form.vue:57` 的 `slot="footer"` 是具名插槽。

### Q10. `ref`、`$parent`、`$children`、EventBus 怎么选？

**一句话**：`ref` 用于父组件明确调用子组件；`$parent/$children` 耦合强、顺序不稳定，少用；EventBus 适合跨层级但难追踪，Vue 2 项目里常见，Vue 3 建议用 Pinia 或 provide/inject。

**项目印证**：

- `position/index.vue:147` 的 `<Form ref="Form">`，父组件调用 `init`；
- `main.js:137` 的 `Vue.prototype.$EventBus = new Vue()`；
- `Sidebar/index.vue:86,95,126` 用它做菜单与布局的通信。

**追问「EventBus 的坑」**：组件销毁时要 `$off` 解绑，否则重复注册、内存泄漏。

### Q11. `keep-alive` 的原理和作用？

**一句话**：`keep-alive` 是抽象组件，缓存内部组件实例，切换时触发 `activated/deactivated`，避免重复创建和请求。

**展开**：

- `include/exclude` 匹配**组件 `name`**；
- `max` 可限制缓存数量（LRU）；
- 被缓存组件不会 `destroyed`；
- 需要「每次进入刷新」时用 `activated` 或 `/redirect` 套路。

**项目印证**：`AppMain.vue:4-6` 用 `include="cachedViews"`；`tagsView.js:15-20` 收集 `view.name`。岗位页没有 `name`，缓存实际不生效（真实细节，见第 10 章 §5.3）。

### Q12. mixin、自定义指令、插件分别解决什么问题？

**一句话**：mixin 复用**组件选项/逻辑**；指令封装**对 DOM 的底层操作**；插件是**一次性给 Vue 安装能力**（挂原型、注册全局组件/指令/mixin）。

| 机制 | 项目例子 | 适用 |
|---|---|---|
| mixin | `layout/index.vue:35` 引入 `ResizeHandler` | 多个组件共享生命周期/watch/方法 |
| 指令 | `v-hasPermi`、`v-dialogDrag`（`directive/index.js:9-17`） | 操作 DOM、权限移除 |
| 插件 | `plugins/index.js:7-20` 挂 `$modal/$tab` | 全局能力 |
| 全局组件 | `main.js:151-164` 注册 `Pagination/JTable` | UI 复用 |

**追问「mixin 的缺点」**：来源不透明、命名冲突、隐式依赖；大型项目倾向 Composition API。

## 三、响应式原理（13~18）

### Q13. Vue 2 响应式的原理？

**一句话**：`Observer` 用 `Object.defineProperty` 把 data 的每个属性改成 getter/setter；getter 里 `dep.depend()` 收集 Watcher，setter 里 `dep.notify()` 通知 Watcher；Watcher 更新后触发重新渲染。

**展开**：

1. `new Vue()` → `initState` → `observe(data)`；
2. `Observer` 递归遍历，`defineReactive` 每个属性；
3. 渲染时读取属性 → getter → 当前渲染 Watcher 存入 Dep；
4. 属性赋值 → setter → `dep.notify()` → Watcher 入队；
5. nextTick 后统一 flush → 重新 render → patch。

**项目印证**：`utils/dict/Dict.js:35-36,76-78` 用 `Vue.set`/`splice` 保证字典数据的响应式，正是这套机制的边界。

---

### Q14. 为什么修改数组下标/对象新增属性不触发更新？怎么解决？

**一句话**：Vue 2 只拦截已存在属性的 get/set，数组下标没有逐个 `defineProperty`，所以监听不到；用 `Vue.set/$set`、`$delete`，数组用 7 个被改写的方法（`push/pop/shift/unshift/splice/sort/reverse`）。

**展开**：

```js
this.$set(this.obj, 'newKey', 1)
this.$delete(this.obj, 'key')
this.$set(this.arr, 0, 'x')   // 内部转 splice
this.arr.splice(0, 1, 'x')
```

**Vue 3 对比**：`Proxy` 能拦截新增/删除和下标，不再需要 `$set`。

**项目印证**：`billRule/index.vue:282-289` 用 `push/splice`；`Dict.js:35,78` 用 `Vue.set`。

---

### Q15. `$nextTick` 是干什么的？原理？

**一句话**：把回调推迟到「本轮 DOM 更新完成之后」执行；原理是 Vue 的异步更新队列，DOM 更新在微任务里批量 flush，`nextTick` 的回调排在 flush 之后。

**展开**：

- 同一轮同步代码里多次改数据，只会渲染一次；
- `this.$nextTick(cb)`，不传 cb 返回 Promise；
- 典型场景：改 `visible` 后拿 `$refs`、渲染后重置表单、操作表格 `doLayout`。

**项目印证**：`position/index.vue:235-240`、`Form.vue:148-149`、`Selector.vue:56-57`。

---

### Q16. 虚拟 DOM 是什么？diff 怎么做的？key 有什么用？

**一句话**：虚拟 DOM 是用 JS 对象描述真实 DOM；diff 在同层比较，通过 `key` 判断节点能否复用，只更新变化部分；`key` 必须稳定唯一，帮助 Vue 正确复用/移动节点。

**展开**：

- 模板 → render 函数 → VNode → patch 真实 DOM；
- 同层比较 O(n)，不跨层；
- `sameVnode` 判断 key + tag；
- 列表头插时，用 index 当 key 会导致所有节点内容重写。

**项目印证**：`Sidebar/Item.vue` 是 `functional` 组件 + `render(h, context)` + JSX，可以直接看到 VNode 的创建。

---

### Q17. computed 为什么有缓存？和 watch 的底层区别？

**一句话**：`computed` 对应计算 Watcher，依赖不变时 `dirty=false`，直接返回缓存值；`watch` 对应用户 Watcher，数据变化就执行回调。

**展开**：

- 计算 Watcher 是 lazy 的：第一次读取才求值；
- 依赖变化 → `dirty=true`，下次读取重算；
- `computed` 适合派生数据；`watch` 适合副作用（请求、路由、弹窗）；
- `watch` 的 `deep` 会递归遍历对象，大对象慎用。

**项目印证**：`login.vue:170-179`（computed）、`user/index.vue:702-706`（watch）。

---

### Q18. Vue 2 和 Vue 3 响应式的差异？

**一句话**：Vue 2 用 `Object.defineProperty` 劫持属性，Vue 3 用 `Proxy` 代理对象；Proxy 能监听新增/删除/数组下标，且惰性递归，性能更好；但不支持 IE。

**展开**：

| | Vue 2 | Vue 3 |
|---|---|---|
| API | defineProperty | Proxy |
| 新增属性 | 需要 `$set` | 自动 |
| 数组下标 | 需要 `$set`/splice | 自动 |
| 初始化 | 递归遍历全部属性 | 访问时才递归（惰性） |
| 兼容性 | IE9+ | 不支持 IE |
| API | `Vue.set` | `reactive/ref` |

## 四、路由（19~24）

### Q19. hash 和 history 模式的区别？

**一句话**：hash 用 `#` 后面的部分，刷新不会请求服务器；history 用真实路径，需要服务器把所有路径回退到 `index.html`，否则刷新 404。

**项目印证**：`router/index.js:210` 用 `mode: 'history'`。

**追问**：history 模式下 Nginx 配置 `try_files $uri $uri/ /index.html;`；开发环境 devServer 已处理。

---

### Q20. `$router` 和 `$route` 的区别？

**一句话**：`$router` 是路由实例（全局唯一），用来跳转（`push/replace/go`）；`$route` 是当前路由对象（只读），包含 `path/query/params/meta`。

**项目印证**：`login.vue:276` 用 `this.$router.push` 跳转；`position/index.vue:238` 读 `this.$route` 不涉及；`tool/gen/index.vue:238` 读 `this.$route.query.t`。

---

### Q21. query 和 params 的区别？

**一句话**：`query` 拼在 URL 上，刷新保留；`params` 不显示在 URL 上（`name` 路由时），刷新会丢，除非参数是路径的一部分（`/user/:id`）。

**项目印证**：`tool/gen/index.vue:324` 用 query 传 `pageNum`；`router/index.js:185-190` 的 `/tool/gen-edit/:tableId` 是路径参数。

---

### Q22. 路由守卫有哪些？项目的登录流程怎么走？

**一句话**：全局 `beforeEach/beforeResolve/afterEach`，路由独享 `beforeEnter`，组件内 `beforeRouteEnter/beforeRouteUpdate/beforeRouteLeave`。

**项目登录流程**（`src/permission.js`）：

1. 白名单（`/login` 等）直接放行；
2. 无 token → 跳 `/login?redirect=...`；
3. 有 token 且 `roles.length === 0`：
   - `dispatch('GetInfo')` 拿用户信息、角色、权限；
   - `dispatch('GenerateRoutes')` 请求后端菜单并生成路由；
   - `router.addRoutes(accessRoutes)`；
   - `next({ ...to, replace: true })` 重新进入目标路由；
4. 否则 `next()`。

**项目印证**：`src/permission.js:78-150`、`store/modules/permission.js:75-111`。

---

### Q23. 后端的菜单怎么变成前端路由？

**一句话**：登录后前端调 `getRouters` 拿菜单树，递归转成路由对象（把 `component` 字符串映射成 `() => import(...)`），再用 `router.addRoutes` 动态注册。

**展开**：

- 菜单里有 `path/name/component/meta`；
- `filterAsyncRouter` 处理 `Layout/ParentView` 等特殊组件；
- 动态路由放在 `router/index.js` 的 `dynamicRoutes` 之外，由后端下发；
- 刷新后内存路由丢失，守卫会重新生成。

**项目印证**：`store/modules/permission.js:124-224`、`router/index.js:135-207` 的 `dynamicRoutes`。

---

### Q24. 刷新页面后动态路由没了怎么办？

**一句话**：在全局守卫里判断 `roles.length === 0`，重新拉用户信息、重新生成路由，再用 `next({ ...to, replace: true })` 重新进入目标路径。

**项目印证**：`src/permission.js:88-117`。`replace: true` 是为了不留下一条「还没注册路由时的错误历史记录」。

## 五、Vuex（25~29）

### Q25. 为什么用 Vuex？五个核心概念是什么？

**一句话**：Vuex 是集中式状态管理，解决「跨组件共享状态、状态变更不可追踪」的问题；五个概念是 `state/getters/mutations/actions/modules`。

**展开**：

| 概念 | 作用 | 类比 |
|---|---|---|
| state | 唯一数据源 | data |
| getters | 派生状态（带缓存） | computed |
| mutations | 同步修改 state | methods |
| actions | 异步流程，提交 mutation | 业务方法 |
| modules | 拆分模块 | 命名空间 |

**项目印证**：`store/index.js:11-23` 组装 6 个模块；`store/getters.js:30-82` 统一暴露 getters。

---

### Q26. `commit` 和 `dispatch` 的区别？

**一句话**：`commit` 触发 mutation（同步改 state）；`dispatch` 触发 action（可异步，内部再 commit）。

**项目印证**：`src/store/modules/user.js:117-162` 的 `Login` action 里先 `setToken` 再 `commit('SET_TOKEN')`。

---

### Q27. `namespaced` 是什么？项目哪些模块用了？

**一句话**：开启 `namespaced: true` 后，模块的 state/getters/mutations/actions 都要带模块前缀访问，避免命名冲突。

**项目**：`app/settings/tagsView` 开了命名空间（`src/store/modules/app.js:52`、`src/store/modules/settings.js:74`、`tagsView.js:203`）；`user/permission/notify` 没开，所以可以 `dispatch('GetInfo')` 直接调用。

**代价**：不开命名空间时，不同模块的同名 mutation 会冲突；项目里靠命名约定避免。

---

### Q28. 描述一下项目的登录流程

**一句话**：登录页提交 → `Login` action → `login` 接口 → 存 token 到 cookie 和 Vuex → 路由守卫发现 `roles` 为空 → `GetInfo` 拉用户信息 → `GenerateRoutes` 拉菜单 → `addRoutes` → 进入首页。

**详细链路**：

```
login.vue 表单提交
  → this.$store.dispatch('Login', { username, password, code, uuid, tenantId })
  → POST /login
  → setToken(res.data.token) + commit('SET_TOKEN')
  → this.$router.push('/')
  → permission.js beforeEach
  → roles.length === 0 → dispatch('GetInfo')
  → GET /getInfo → roles/permissions/user
  → dispatch('GenerateRoutes')
  → GET /getRouters → 递归转路由 → commit('SET_ROUTES')
  → router.addRoutes(accessRoutes)
  → next({ ...to, replace: true })
```

**项目印证**：`store/modules/user.js:117-227`、`src/permission.js:78-117`、`src/permission.js:140-146`。

---

### Q29. 刷新后 Vuex 状态为什么丢了？项目怎么处理？

**一句话**：Vuex 在内存里，刷新即清空；token 存 cookie 并从 cookie 初始化，用户信息和权限由路由守卫重新拉取。

**项目印证**：`src/store/modules/user.js:57` 的 `token: getToken()`；`src/permission.js:88-117` 重新 `GetInfo`。

### Q31. devServer 的 proxy 是干什么的？为什么能解决跨域？

**一句话**：开发时浏览器请求同源的 `/dev-api/...`，devServer 收到后转发到后端真实地址，浏览器看到的仍是同源请求，所以没有跨域限制。

**展开**：

```js
proxy: {
  '/dev-api': {
    target: 'http://localhost:8080',
    changeOrigin: true,
    pathRewrite: { '^/dev-api': '' }
  }
}
```

**项目坦白点**：本项目后端本身开了宽松 CORS（`ResourcesConfig.java:50-67`），代理的价值更多是**统一前缀 + 环境一致**，不只是绕跨域。

**项目印证**：`vue.config.js:35-44`、`utils/request.js:54-66`。

### Q32. axios 拦截器在项目里做了什么？

**一句话**：请求拦截器加 token、序列化参数、防重复提交；响应拦截器统一处理业务码、401 跳登录、把 `res.data` 返回给页面。

**展开**：

- 请求头 `Authorization: Bearer xxx`；
- `tansParams` 把对象转成 query 参数（数组、嵌套对象）；
- 1 秒内相同请求拦截，提示「数据正在处理，请勿重复提交」；
- 响应 `code !== 200` 弹错误；401 清 token 跳登录；
- `return res.data` 让页面少写一层。

**项目印证**：`utils/request.js:92-167`（请求）、`:73-131`（响应）。

### Q33. `.env` 文件怎么用？为什么改了要重启？

## 七、性能与实战（35~37）

### Q35. Vue 项目有哪些性能优化手段？

**一句话**：减少首屏体积（懒加载、拆包、按需引入）、减少渲染量（分页、虚拟列表、`v-if`/`v-show` 合理使用）、减少重复计算（computed 缓存、避免模板里调方法）、减少无效请求（防抖、缓存、防重复提交）、利用缓存（keep-alive）。

**展开**（挑 5~6 点）：

1. 路由懒加载 / 组件异步加载；
2. `v-for` 正确 key，避免大列表全量重渲染；
3. 长列表分页或虚拟滚动；
4. `computed` 替代模板内复杂表达式；
5. `keep-alive` 缓存页签；
6. 图片懒加载、CDN、gzip；
7. 避免 `deep watch` 大对象；
8. 生产环境关闭 devtools、压缩代码。

**项目印证**：见第 10 章 §8.1 的表格。

---

### Q36. 一个页面渲染很卡，你怎么排查？

**一句话**：先用 Performance 面板看耗时在脚本、渲染还是绘制；再看是否是「数据量大 / 重复渲染 / 复杂计算 / 频繁更新」四类问题。

**展开**：

1. Vue Devtools 看组件重渲染次数；
2. `console.time` 包住可疑方法；
3. 大列表 → 分页/虚拟滚动；
4. 模板里有没有 `{{ heavyFn() }}` → 改 computed；
5. `watch deep` 是否监听大对象；
6. 是否在 `updated` 里又改数据造成循环更新。

**项目相关**：合同编辑页等超大组件是典型风险点，拆分组件、按需加载是主要手段。

---

### Q37. 为什么 `v-for` 要加 key？用 index 有什么问题？

**一句话**：key 帮助 diff 识别节点身份；用 index 在列表插入/删除/排序时会导致节点错位复用，组件内部状态（输入框、勾选）串位。

**项目印证**：`billRule/index.vue:50` 的 `:key="item.value"` 是真实反例（key 恒为 undefined），第 9 章 §2.7 有分析。

### Q38. 「介绍一下你做的这个项目」

**推荐结构**（1~2 分钟）：

1. **项目是什么**：基于开源的肇新合同管理系统，做合同全生命周期管理（起草、审批、签署、归档）；

### Q39. 「你在这个项目里遇到过什么问题，怎么解决的？」

挑**真实、具体、能复现**的例子，比空泛的「性能优化」有说服力：

**例 1：keep-alive 不生效**

- 现象：岗位页切走再回来，`created` 每次都执行；
- 排查：Vue Devtools 看组件树，确认 `<keep-alive include>` 没缓存；
- 根因：`include` 匹配组件 `name`，岗位页导出对象没有 `name`；
- 解决：加 `name: 'Position'`（或明确不需要缓存，就不加）；
- 收获：理解了 keep-alive 的匹配规则。

**例 2：面包屑的 `noRedirect` 大小写不一致**

- 现象：路由注释写 `noRedirect`，面包屑判断 `'noRedirect'`，但 `/user` 路由写的是 `'noredirect'`；
- 影响：该路由本就不进面包屑，所以没暴露；
- 收获：真实项目里「约定」和「实现」可能不一致，读代码要以实际判断逻辑为准。

**例 3：编号规则页的历史代码**

- 现象：页面里有多段注释代码、`v-if="false"` 块、空弹窗、无入口的方法；
- 分析：从标准 CRUD 页改造而来，删表格时没删干净；
- 处理：读懂哪些是死代码，不在上面浪费时间；改造时顺手清理。

**答题模板**：`现象 → 定位过程（用了什么工具）→ 根因 → 修法 → 收获`。重点在「定位过程」，体现排查能力。

---

### Q40. 「如果让你优化这个项目，你会做什么？」

按「影响大、成本可控」排序，挑 3 条讲：

1. **清理死代码和历史遗留**：无入口方法、无消费者校验、空弹窗；降低维护成本；
2. **补齐组件 `name`、规范 keep-alive**：明确哪些页面缓存、哪些不缓存，避免「看起来能用」的隐性 bug；
3. **超大页面拆分**：把合同编辑等上千行组件拆成子组件/组合式函数，提升可读性和渲染性能；
4. **请求层细化**：统一错误码处理、下载错误识别、防抖；
5. **构建优化**：Element UI 按需引入、图片/静态资源 CDN；
6. **工程规范**：ESLint/Prettier、提交规范、单元测试（项目目前基本没有前端测试）。

**注意**：说优化建议时，先承认「现有写法能跑、有历史原因」，再讲改进，不要一上来否定整个项目。

## 九、答题技巧

### 9.1 万能答题结构

```
结论（一句话）
  → 原理/机制（2~3 句）
  → 项目例子（文件/场景）

```

### 9.2 被追问时怎么办

- **不确定**：说「我理解是……，但我没有在生产环境验证过」，别硬编；
- **问到源码细节**：能讲到 `Observer/Dep/Watcher`、`nextTick` 微任务、`sameVnode` 就够，不必背行号；
- **问到项目细节**：说出文件路径和大致行号，比背术语可信；
- **问到不会的**：承认不会，然后说「我会从哪个方向排查」，体现方法。

### 9.3 高频「陷阱题」

| 问题 | 陷阱 | 正确方向 |
|---|---|---|
| Vue 的 DOM 更新是同步还是异步？ | 容易答同步 | 异步批量，`nextTick` 后 |
| 虚拟 DOM 比真实 DOM 快吗？ | 容易绝对化 | 不一定；价值在可维护性和批量 diff |
| `v-if` 和 `v-for` 谁优先级高？ | Vue 2/3 不同 | Vue 2 先 `v-for`，Vue 3 先 `v-if` |
| computed 能异步吗？ | 不能 | 要异步用 watch/方法 |
| watch 能监听数组 push 吗？ | 能，但 deep 才有用 | 取决于监听方式 |
| `$nextTick` 是宏任务吗？ | 2.6 优先微任务 | Promise.then 优先 |
